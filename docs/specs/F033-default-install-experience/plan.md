# F033 · 默认安装体验实施计划

## 现有上下文与复用

外观已有单一默认常量和 `official` 撤销路径；当前默认是 cloud-cat。桌面共用 `PROFILE_TEMPLATES.web` 初始化插件组合；现有本机 desktop profile 已安装 `dsh-context@0.83.1`。直接往 web-app patch 再插入会与已有插件层重复，故使用既有默认组合机制。保持 PSC-027、PSC-031。

## 影响范围

| 路径/模块 | 当前职责 | 计划变化 | 对应 AC |
|---|---|---|---|
| ui-fde-appearance | 皮肤默认与设置 | 默认 official，重置文案与测试同步 | AC-F033-001 |
| apps/cli/package.json、pnpm-lock.yaml | 发行依赖 | 精确锁定 dsh-context 0.83.1 | AC-F033-002 |
| official-bundles 默认模板 | Web 与桌面初始化 | 默认 web 组合包含一次 dsh-context；其他模式不变 | AC-F033-002 |
| 桌面恢复、默认产品检查 | 停用第三方插件、检查发行组合 | 恢复模式仍停用洞察；源码检查接受 CLI 精确版本的外部默认包，真实 patch 由安装后组合测试验证 | AC-F033-002 |
| 定向测试与包说明 | 消费约定与回归 | 新配置、现有配置、禁用与插件解析证据 | 全部 |

## 实现方案

默认皮肤常量改为 official，不新增存储版本或迁移。保持先写成功再应用的控制器路径。设置默认标记复用同一常量，组件与中文/英文提示同步。

CLI 安装依赖固定 dsh-context 0.83.1，并更新锁文件。默认 web 模板追加该插件的既有 bundle，由原插件 patch 注册 Host/Client；桌面沿用同一模板。保留已有 profile 的用户 bundle 列表，不向运行配置插入第二条插件，也不每次启动重置禁用。通过全新临时 profile 读取真实依赖与组合；临时目录仅做测试并在结束清理，不复制运行数据。

现有默认产品检查只解析工作区 bundle，因此外部默认包需验证 CLI 中的精确运行依赖，工作区组合继续完整扫描，外部 patch 使用真实安装后的配置装配验证；不豁免实验性工作区包。桌面故障恢复的“禁用全部插件”不得因新默认而重新启用第三方洞察。

## 实施顺序

1. 更新默认产品约定与本 Feature 文档。
2. 修改外观默认及相关测试。
3. 安装固定依赖并修改共用默认模板，验证新建与既有配置。
4. 必要构建与无密钥装配验证，记录结果并交用户确认。

## 依赖与风险

| 依赖/风险 | 影响 | 应对 | 验证时机 |
|---|---|---|---|
| 插件重复装配 | 激活失败或重复页签 | 仅通过 profile bundle 一处启用，不改 web-app patch | 组合测试 |
| 旧偏好被默认覆盖 | 皮肤或禁用选择丢失 | 不迁移已有合法配置 | 控制器与 profile 测试 |
| 依赖未进入发行 | 学员缺插件 | CLI 运行依赖与锁文件，实际解析校验 | 安装及装配测试 |

## 回退策略

仅恢复本次默认常量、模板和新增依赖并重建，不清理或迁移任何真实项目与配置；既有运行目录保持不动。
