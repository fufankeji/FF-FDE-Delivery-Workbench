# F023 · 部署试运行与进入验收移交实施计划

## 现有上下文与复用

- F006 已把项目推进到 `pilot` 并提供验证基线；F010/F011 已展示统一阶段与项目详情；F005 已建立 expected revision、Host 复核和 FDE 二次确认模式。
- F022 的本地项目运行、持久终端和内嵌预览可作为开发环境证据入口，但不等于目标环境部署或试运行完成。
- FDE Project、Stage 与 UI 插件仍应承载项目级快照、阶段 Skill/人工门和项目进度，不新增平行项目容器或任务数据库。
- 用户已授权本轮开发。V1 冻结为环境中立的事实记录与人工门：真实部署动作仍由 DSH 在 FDE 明确授权后执行，平台不内置通用部署执行器、不读取或保存目标环境凭据。

## 实现方案

本轮实现沿用当前“项目文件＋Host 可信投影＋项目进度只读展示＋FDE CAS 人工门”模式。Agent 只协助读取前阶段基线、执行已授权动作和维护候选文档；Host 负责固定路径、项目归属、状态/理由/证据和 revision 校验。不得把 F022 的本地运行状态、端口或一次健康检查直接转换为部署试运行通过。

结构化事实固定保存在 `.fde/deployment-trial.json`：候选版本、目标环境名称与摘要、授权状态、部署状态、部署/健康/回滚/试运行证据路径，以及问题严重级别、处理状态、理由和责任人。所有本地证据路径必须位于当前项目内。目标环境可以是本地、客户内网、容器或云环境，但具体执行方式由项目自己的 `AGENTS.md`、交付文档和当次 FDE 授权决定；不为尚未出现的环境建立通用部署平台。

## 实施顺序

1. 冻结环境中立状态文件、项目内证据路径和凭据不落盘边界。
2. 落实项目级部署试运行快照和四份固定产物扫描。
3. 增加阶段候选产物指引、问题状态和 FDE 人工接受记录。
4. 在项目进度展示真实输入、证据、产物、缺口和确认入口。
5. 增加绑定当前合同摘要的 FDE 环境/试运行结论确认；只在其余门槛齐备时原子记录授权与 ready，不触发真实外部动作。
6. 增加 `pilot → handoff` Host 复核与 expected revision 冲突处理。
7. 运行最窄 Host/Client 测试并交给用户手动走通，不自动截图或完整 E2E。

## 依赖与风险

| 依赖/风险 | 影响 | 应对 | 验证时机 |
|---|---|---|---|
| 目标环境和执行器尚未确认 | 技术方案可能不适配真实客户环境 | 实施前以一个真实项目固定最小能力，不提前建设通用平台 | 开始开发前 |
| 凭据或客户数据进入文档 | 造成泄露和错误版本化 | 只保存配置项名称、受控引用、摘要和责任，不读取或落盘明文凭据 | Host 解析与人工审阅 |
| 本地运行被误读为生产试运行 | 形成假交付 | 版本、环境和证据显式绑定；F022 状态只作参考 | 门槛测试 |
| 人工接受掩盖原始失败 | 风险不可追溯 | 保留原结果，接受记录独立且只影响单个问题 | Host 原子更新测试 |

## 回退策略

后续若实现失败，移除新增的部署试运行投影、页面和 `pilot → handoff` 路由即可；项目已有四份文档和附件保持原样，不删除用户证据，不自动退回已确认阶段。
