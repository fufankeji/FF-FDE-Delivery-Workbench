# F023 · 部署试运行与进入验收移交规格

## 目标与可观察结果

项目完成验证评估后，FDE 可以把当前候选版本放入明确目标环境，持续记录真实部署、运行、回滚、用户反馈和问题处理结果。项目进度集中展示当前部署事实与四份固定产物；满足门槛只表示可以提交，仍只有 FDE 二次确认才能进入验收移交。

## 来源与范围

- 来源需求：REQ-001, REQ-003, REQ-004, REQ-012, REQ-027, NFR-001, NFR-002, NFR-004, NFR-005, NFR-007, NFR-008
- 来源总规格：PSC-002, PSC-005, PSC-006, PSC-007, PSC-009, PSC-011, PSC-012, PSC-031
- 对应 PRD 验收：AC-001, AC-003, AC-004, AC-010, AC-026
- 本 Feature 包含：部署试运行输入和真实证据；四份固定产物；问题修复、人工接受和延期决定；项目进度审阅；FDE 二次确认 `pilot → handoff`。
- 本 Feature 不包含：通用云部署平台、自动生产发布、凭据托管、通用 APM、企业客户账号、电子签章、项目专有附件规则引擎或无人确认的自动推进。

## 固定输入与产物

### 阶段输入

- 当前有效验证基线、候选版本和验证证据。
- 目标环境资料、必要授权、配置项名称及受控凭据责任说明。
- 项目适用的发布、备份、回滚、健康检查和运行观察方式。
- 试运行期间新增的日志、截图、监控导出、会议纪要、用户反馈和问题证据。

### 固定产物

| 产物 | 固定路径 | 最小职责 |
|---|---|---|
| 部署运行手册 | `fde-deliverables/05-deployment-trial/deployment-runbook.md` | 记录部署、启动、停止、检查、备份和回滚步骤及责任边界 |
| 部署基线 | `fde-deliverables/05-deployment-trial/deployment-baseline.md` | 固定实际版本、目标环境摘要、依赖、配置项名称、地址和产物校验信息 |
| 试运行报告 | `fde-deliverables/05-deployment-trial/trial-operation-report.md` | 汇总真实运行周期、核心链路、稳定性、反馈、结论和关联证据 |
| 问题闭环清单 | `fde-deliverables/05-deployment-trial/issue-closure-list.md` | 逐项记录问题、影响、证据、已修复/人工接受/延期/仍开放状态及责任 |

附件按项目适用关联，不因为缺少通用附件类型而阻塞；四份固定产物本身始终是阶段门前置条件。

## 用户旅程与状态

| 入口/前置 | 用户动作 | 过程与反馈 | 对象状态变化 | 可观察结果 | 下一步 |
|---|---|---|---|---|---|
| 项目已进入部署试运行 | 补充目标环境资料并开展部署 | Agent/工具协助但不获得额外权限；真实动作和失败留证 | 未准备 → 部署中/阻塞/运行中 | 当前版本、环境、运行状态和缺口可见 | 继续修复或开始试运行 |
| 系统在目标环境运行 | 收集运行证据、反馈并处理问题 | 每项问题保留原结果和决定依据 | open → resolved/accepted-with-reason/deferred | 四份产物持续更新，问题状态可追溯 | 审阅阶段输出 |
| 证据、问题决定和四份产物已齐备 | FDE 明确确认当前目标环境授权与试运行结论 | Host 绑定页面当前合同摘要记录 `environment.authorized=true` 与 `status=ready`；不执行部署、停止或回滚 | 待人工确认 → 可提交 | 页面解除授权与试运行结论两项阻塞，仍停留在部署试运行 | 提交阶段完成 |
| 门槛满足 | 在项目进度提交并二次确认 | Host 重新检查当前事实、文件和 revision | pilot → handoff | 项目只推进一步并显示验收移交 | 开始最终验收与移交 |

## 功能行为

### 主流程

1. 阶段从有效验证基线开始，不重新制造一份验证结论。
2. FDE 提供目标环境和授权范围；平台只保存必要摘要、受控引用和责任信息，不保存明文凭据。
3. Agent/工具协助真实部署、检查与问题修复，所有结果绑定当前版本和环境。
4. 四份固定产物在同一路径持续更新；项目进度读取并预览真实文件和问题状态。
5. 严重问题必须真实修复或由 FDE 记录带理由的接受决定；延期问题必须明确责任和后续时间，不等同于已解决。
6. 当五类证据、四份固定产物及问题决定已经齐备时，项目进度提供独立的“确认目标环境与试运行结论”动作；只有 FDE 明确提交页面当前合同摘要，Host 才记录环境授权与试运行 ready。接受某个问题不能隐式完成这一确认。
7. FDE 再提交阶段完成，Host 以当前 revision 复核后只执行一次 `pilot → handoff`。

### 业务规则与边界

- 一次启动、HTTP 200、单条健康检查或 Agent 自评都不能证明试运行完成。
- 人工接受只解除被接受问题自身的阻塞，不改写运行结果、验证结果或其他问题。
- 环境授权与试运行 ready 是一项独立 FDE 决定；该动作只更新当前项目的结构化事实，不执行真实部署、停止、回滚或外部写入，也不能在证据、产物或问题决定仍有缺口时提交。
- 目标环境、当前版本、运行证据和产物必须属于同一项目；不得按最近路径、端口或文件名回退。
- 项目专有部署包、日志、截图和会议资料通过引用扩展，不复制到第二套交付目录。
- 只有 FDE 能提交阶段完成；Agent、Skill、部署动作和文件存在都没有阶段推进权限。

## 异常与恢复

| 情况 | 用户可见状态 | 系统行为 | 恢复/重试 |
|---|---|---|---|
| 目标环境或授权不明确 | 显示具体缺口和“确认目标环境与试运行结论”入口 | 不执行高影响部署、不生成假基线；未满足其余门槛时拒绝记录 ready | FDE 补充资料、核对证据并显式确认后继续 |
| 部署或运行失败 | 保留失败、日志和当前版本 | 不显示试运行通过、不覆盖旧证据 | 修复后产生新证据并更新报告 |
| 回滚条件缺失 | 阶段阻塞 | 不因其余指标正常而放行 | 补齐回滚方案和可复核证据 |
| 严重问题仍开放 | 问题与影响可见 | 阻止提交；不自动接受 | 修复或由 FDE 明确接受并记录理由 |
| revision 冲突 | 提示阶段信息已变化 | 拒绝旧确认覆盖新状态 | 刷新并重新审阅后提交 |

## 验收标准

### AC-F023-001 · 固定输入和四份产物可追溯

- 来源：REQ-003, REQ-027, NFR-001, NFR-002, NFR-005, NFR-007, NFR-008, PSC-005, PSC-007, PSC-031
- 对应 PRD 验收：AC-003, AC-026
- Given 项目处于部署试运行并已有有效验证基线
- When FDE 补充目标环境资料并持续维护部署试运行结果
- Then 当前版本、目标环境、受控输入和四份固定产物均归属当前项目、可读取且能回到真实来源；明文凭据不进入文档或会话

### AC-F023-002 · 真实运行与问题决定不被伪装

- 来源：REQ-003, REQ-004, REQ-027, NFR-001, NFR-002, NFR-004, NFR-007, NFR-008, PSC-005, PSC-006, PSC-009, PSC-011, PSC-031
- 对应 PRD 验收：AC-003, AC-004, AC-026
- Given 当前版本已在目标环境产生运行、失败、反馈或问题证据
- When FDE 修复、接受、延期或继续保留问题
- Then 原始结果与证据保持可见，人工接受记录决定者、理由和范围且只影响该问题；一次启动或 Agent 自评不显示为试运行完成

### AC-F023-003 · 项目进度清晰展示阶段事实

- 来源：REQ-003, REQ-012, REQ-027, NFR-005, NFR-007, NFR-008, PSC-002, PSC-005, PSC-011, PSC-012, PSC-031
- 对应 PRD 验收：AC-003, AC-010, AC-026
- Given 项目处于部署试运行
- When FDE 打开项目进度中的当前项目
- Then 页面展示部署版本、目标环境、运行/回滚证据、问题状态、四份固定产物和真实缺口；缺失或读取失败明确显示，不生成假进度

### AC-F023-004 · 只有 FDE 能进入验收移交

- 来源：REQ-001, REQ-012, REQ-027, NFR-001, NFR-004, NFR-005, NFR-008, PSC-002, PSC-006, PSC-007, PSC-011, PSC-031
- 对应 PRD 验收：AC-001, AC-010, AC-026
- Given 当前版本/环境、必要授权、运行/回滚证据、问题决定和四份固定产物均满足门槛
- When FDE 在项目进度二次确认并提交当前 expected revision
- Then Host 复核后只执行一次 `pilot → handoff`；任何缺口、开放严重问题或 revision 冲突都留在部署试运行并列出原因，Agent 和文件写入不能推进

### AC-F023-005 · 授权与试运行结论存在明确人工入口

- 来源：REQ-004, REQ-027, NFR-001, NFR-004, NFR-005, NFR-008, PSC-006, PSC-009, PSC-011, PSC-031
- 对应 PRD 验收：AC-004, AC-026
- Given 当前合同尚未记录目标环境授权或试运行状态仍不是 ready，但五类证据、问题决定和四份固定产物已经齐备
- When FDE 在项目进度明确确认页面当前合同所代表的目标环境和试运行结论
- Then Host 以精确合同摘要原子记录环境授权与 ready，页面刷新后开放阶段提交；合同已变化或其余事实仍有缺口时拒绝写入并列出原因，问题人工接受不得隐式触发该动作

## 开放问题

- 无；具体目标环境和执行方式继续由当前项目资料与 FDE 当次授权决定。

## 延期边界

- V1 使用环境中立的 `.fde/deployment-trial.json` 记录项目事实，不内置通用部署执行器或凭据托管。具体目标环境、执行方式和项目专有附件继续由项目自身说明与 FDE 当次授权决定，不改变固定产物、证据和人工门语义。
