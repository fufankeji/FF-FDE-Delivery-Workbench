# F015 · 评估优化规格

## 目标与可观察结果

项目由 FDE 完成项目开发并推进到验证评估后，FDE 可以为当前项目维护可版本化评估用例，选择明确候选版本后由用户主动运行隔离的真实 Agent Trial，查看用例级断言、Trace、Token、耗时和总体 PASS/WARN/FAIL，并与人工维护的 Baseline 比较；有效报告可以成为验证评估阶段证据。

## 来源与范围

- 来源需求：REQ-020, NFR-001, NFR-002, NFR-003, NFR-004, NFR-005, NFR-007, NFR-008
- 来源总规格：PSC-004, PSC-007, PSC-008, PSC-009, PSC-011, PSC-012, PSC-014, PSC-022
- 对应 PRD 验收：AC-019
- 当前切片包含：项目交付中的“评估优化”View；项目用例目录；用户二次确认；由当前 Agent 提交的隔离 Headless DSH Trial；确定性 Trace/输出/工具断言；可选多 Trial、重试和标签；JSON/Markdown 报告；PASS/WARN/FAIL；失败样本；Token/耗时；Baseline 对比；错误；报告持久化与恢复。
- 当前切片不包含：打开页面自动评估、自动夜间运行、自动修改 Baseline、默认 LLM Judge、通用 Benchmark 市场、跨客户排行榜、把单一平均分作为上线结论。

## 业务对象

| 对象 | 必需字段 | 权威位置 | 边界 |
|---|---|---|---|
| 评估用例 | CaseId、prompt、断言、标签、可选 Trial/重试 | 当前项目版本化用例目录 | 不包含真实凭据 |
| 评估运行 | EvalRunId、候选版本、用例版本、Profile、模型请求、状态、时间 | 项目评估状态 | 不复用用户当前会话 |
| Trial | CaseId、attempt、隔离目录、Session/Trace、结果、Token、耗时 | 运行报告 | 失败 Trial 不丢弃 |
| 评估报告 | 用例证据、总体 PASS/WARN/FAIL、未覆盖项、指标 | 项目不可变报告文件/记录 | 不能由页面内存编辑结论 |
| Baseline | 版本、来源报告、批准者、时间 | 项目 Baseline 索引 | Candidate 不自动覆盖 |

## 用户旅程与状态

| 前置状态 | 用户动作 | 过程与反馈 | 可观察结果 | 恢复 |
|---|---|---|---|---|
| 项目已进入验证评估但尚无用例 | 打开“评估优化” | 读取项目评估目录 | 显示“尚无评估用例”和需要建立的最小合同 | 在项目中创建用例 |
| 已有用例 | 点击“运行评估”并二次确认 | 使用当前 Agent 模型配置排队，并把 Trial 放入隔离 Session 根 | 当前 Session 运行状态，完成后出现报告 | 当前 runner 不提供可靠独立取消；失败保留诊断 |
| Trial 运行中 | 查看页面 | 独立 DSH_HOME/Session 根执行真实 Agent | 当前 Case/Trial、时间和完成数 | 页面刷新后恢复状态 |
| 运行结束 | 查看报告 | 聚合断言、Trace 与指标 | PASS/WARN/FAIL、失败用例、Token/耗时和未覆盖项 | 修复后新建运行 |
| 已有 Baseline | 比较 Candidate | 按同名用例与兼容合同生成差异 | 回归、改进、不确定和缺失用例 | 不兼容时拒绝比较 |
| 报告满足阶段要求 | 引用为验证证据 | 记录报告和候选版本关系 | 阶段门可以消费明确报告 | F015 自身不推进阶段 |

## 功能行为

1. “评估优化”是项目交付中的独立 View，仅从验证评估阶段开始出现并在后续阶段保留；需求调研、方案设计和项目开发阶段不显示该入口。当前 Session 用于识别 Workspace 并留下用户明确提交的评估指令与工具调用，真实 Trial 使用隔离 Headless Profile、Session 根和工作副本，不修改当前项目源码。
2. 评估只由用户明确动作触发；运行前显示用例数、Trial/重试、模型/Provider 请求和可能费用。没有合法模型或权限时拒绝。
3. 每个用例/Trial 使用独立 Session 根和受控工作副本；并发运行不得共享可变工作区、Session 或输出目录。
4. 第一版优先确定性断言：Turn 完成、工具调用、工具无错误、输出包含/匹配、文件/命令检查和 Token/时间上限；不默认用另一个 LLM Judge。
5. 多 Trial 报告保留 successRate、pass@k/pass^k 等统计时必须显示样本数，不把小样本外推成精确概率。
6. 总体 PASS/WARN/FAIL 必须保留每个失败、错误和未覆盖用例；关键失败不能被平均分抵消。
7. Baseline 由用户从一份有效报告明确批准；比较不修改 Candidate 或 Baseline。用例合同不兼容时显示不可比较。
8. 报告绑定候选版本、用例版本、Profile、模型请求、时间和 Trace；缺失关键身份时不能进入阶段证据。

## 异常与恢复

| 情况 | 用户可见状态 | 系统行为 | 恢复方式 |
|---|---|---|---|
| 无用例/候选版本 | 说明缺失项 | 不启动子进程 | 补齐后重试 |
| 模型/凭据不可用 | 明确拒绝 | 不创建假 Trial | 配置后重试 |
| 单用例超时/Agent 错误 | Case=error/failed | 保留日志和其他用例结果 | 按配置重试或新运行 |
| 运行进行中 | 显示当前会话运行中和“不提供可靠独立取消” | 不显示假取消或假终态 | 等待本轮结束；后续 runner 支持取消后再增加动作 |
| 页面刷新/Host 重启 | 恢复已提交状态；无法恢复的进程标记 interrupted/error | 不显示仍在运行的假状态 | 新建运行或人工处理 |
| 报告损坏/版本未知 | 报告无效 | 不比较、不进入阶段门 | 重新运行 |
| Baseline 不兼容 | “不可比较”及原因 | 不生成误导差异 | 选择兼容 Baseline 或重新批准 |

## 验收标准

### AC-F015-001 · 用户明确触发且运行隔离

- 来源：REQ-020, NFR-002, NFR-004, NFR-005, PSC-004, PSC-008, PSC-012, PSC-014, PSC-022
- 对应 PRD 验收：AC-019
- Given FDE 已将当前项目推进到验证评估，且项目具有用例、候选版本和可用模型配置
- When 用户查看预计用例/Trial/模型信息并明确运行评估
- Then 评估入口可用，每个 Trial 在独立 Session 根和受控工作副本运行，当前会话只增加一条明确评估指令与工具记录，当前项目源码和未保存文件不受影响；打开页面、项目切换或阶段进入不会自动产生调用费用；项目开发及更早阶段不提前显示入口

### AC-F015-002 · 用例级真实断言与报告

- 来源：REQ-020, NFR-001, NFR-003, NFR-007, NFR-008, PSC-009, PSC-011, PSC-022
- 对应 PRD 验收：AC-019
- Given 评估包含通过、断言失败、工具错误和超时用例
- When 真实 Agent Trial 完成
- Then 报告逐项保留 prompt/断言结果、Session/Trace、Token、耗时和错误，总体 PASS/WARN/FAIL 不隐藏任何关键失败或未覆盖项，刷新后仍可读取

### AC-F015-003 · Baseline 比较不自动改写

- 来源：REQ-020, NFR-001, NFR-003, NFR-008, PSC-007, PSC-011, PSC-022
- 对应 PRD 验收：AC-019
- Given 项目已有人工批准的 Baseline 和一个兼容 Candidate 报告
- When 用户执行比较
- Then 页面按同名用例和指标显示回归/改进/不确定，两个报告保持不变；用例合同不兼容时拒绝比较，Candidate 不自动成为新 Baseline

### AC-F015-004 · 有效评估报告才能进入阶段证据

- 来源：REQ-020, NFR-001, NFR-004, NFR-005, NFR-008, PSC-007, PSC-009, PSC-022
- 对应 PRD 验收：AC-019
- Given 项目准备从验证评估进入部署试运行
- When 阶段门引用一份评估报告
- Then 报告必须绑定当前候选版本、用例版本和有效运行，满足项目必需用例且无关键失败；error、损坏或旧版本报告不能通过，F015 页面本身不推进阶段

## 开放问题

- 不同项目类型的必需用例和关键断言由项目合同确定；F015 提供通用执行与证据结构，不预设统一业务阈值。
- 当前固定 `dsh-eval-harness` runner 未暴露 AbortSignal 或进程句柄，因此第一版不提供独立取消；取消能力必须先在 runner 层成立，页面才可增加。
- 报告与项目候选源码版本、阶段证据的正式关联由 F005 交付门实现；在该关联存在前，评估报告只能作为项目内可查看证据，不能单独推进阶段。
- LLM Judge、RAGAS/DeepEval/Promptfoo 等高级指标后续按项目需要接入，不在第一版默认启用。
