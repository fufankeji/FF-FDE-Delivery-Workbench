# F012 · API 文档与受控接口使用规格

## 目标与可观察结果

FDE 在当前项目交付中可以查看项目真实 API 文档，并让项目 Agent 基于同一份受信任 OpenAPI 定义搜索接口、读取参数和响应、按项目授权调用接口。页面可见、接口可描述和接口可调用分别反映真实状态，任何失败都不以空白页面或假成功掩盖。

## 来源与范围

- 来源需求：REQ-017, REQ-025, NFR-001, NFR-002, NFR-005, NFR-007, NFR-008
- 来源总规格：PSC-004, PSC-008, PSC-009, PSC-011, PSC-012, PSC-014, PSC-019, PSC-029
- 对应 PRD 验收：AC-016, AC-024
- 当前切片包含：项目交付中的“API 文档”View；项目级显式配置与当前运行报告来源；仅在项目运行中且 OpenAPI 来源有效时开放；真实文档内嵌与外部打开；OpenAPI 3.0/3.1 接口搜索、描述和受控调用；项目隔离；默认只读；凭据、私网、重定向、参数和响应边界。
- 当前切片不包含：通用网页浏览器、任意 URL 输入、完整 API 管理平台、接口 Mock 服务、自动生成后端、自动放开写方法、把调用成功自动记为项目验证通过。

## 业务对象

| 对象 | 身份与归属 | 用户可见内容 | 不可见/禁止内容 |
|---|---|---|---|
| API 文档配置 | WorkspaceId＋配置版本 | 文档状态、文档地址、OpenAPI 来源状态、API 基地址、允许方法 | 真实凭据值、其他项目地址 |
| OpenAPI 操作 | API 配置＋operationId | 方法、路径、摘要、参数、请求体和响应 | 未声明参数、未授权目标 |
| API 调用记录 | WorkspaceId＋调用身份 | 方法、接口、开始/结束、结果或失败摘要 | 凭据、敏感响应头、超限响应正文 |

## 用户旅程与状态

| 前置状态 | 用户/Agent 动作 | 过程与反馈 | 可观察结果 | 恢复 |
|---|---|---|---|---|
| 项目运行中并报告 OpenAPI | FDE 打开“API 文档” | 检查当前项目显式配置或运行来源和文档可达性 | 内嵌真实文档，并可在新窗口打开 | 刷新或重新启动后探测 |
| 项目停止、阻塞或没有 OpenAPI | FDE 查看项目交付页签 | 不注册“API 文档”，不访问猜测端口 | 继续在对话、终端或项目预览中处理 | 项目运行并报告 OpenAPI 后自动出现 |
| 文档禁止内嵌 | FDE 打开“API 文档” | 保留受信任地址但不伪装加载完成 | 显示“页面禁止内嵌”和外部打开 | 外部打开或修正文档响应头 |
| OpenAPI 已配置 | Agent 搜索或描述接口 | 只读取当前项目受信任定义 | 返回匹配接口及结构化参数/响应 | 修复定义后重试 |
| 项目允许调用 | Agent 请求调用接口 | 校验方法、参数、目标、私网授权和凭据引用 | 返回受限结果或明确拒绝原因 | 调整项目配置或获得审批后重试 |
| 切换到另一项目 | 用户打开另一项目会话 | 重新解析 WorkspaceId 和配置 | 页面与工具只使用新项目 API | 不保留上一项目可操作状态 |

## 功能行为

### API 文档页面

1. “API 文档”作为项目交付中的独立 View，与“对话”“轨迹”“系统架构”并列；只有当前阶段至少为项目开发、项目状态为 `running` 且存在有效 `openapiSource` 时注册，它不是全局页面，也不属于右侧开发 Dock。
2. View 虽由当前 Session 承载，但通过 WorkspaceId 读取项目级配置；同项目多会话看到相同文档状态，跨项目不得复用。
3. 页面优先加载项目明确保存的 `.fde/api-docs.json`；该文件缺失时才读取当前 `running` 记录中由 `project_runtime_report` 提交的受信任来源，不接受模型消息、URL 参数或旧运行记录临时指定任意站点。
4. 文档可内嵌时使用受限 iframe；始终提供受信任地址的“在新窗口打开”。禁止内嵌、混合内容或跨源失败时展示真实原因。
5. 文档页面加载成功不等于 OpenAPI 定义有效、Agent 调用成功或项目验证通过。

### Agent OpenAPI 能力

1. Agent 至少可执行接口列表/搜索、单个接口描述和受控接口调用。
2. 每条项目会话只获得当前项目允许的 API 配置；多项目目录不得形成可被任意会话横向查询的共享工具目录。
3. 默认只允许 `GET`、`HEAD`；`POST`、`PUT`、`PATCH`、`DELETE` 等方法必须由项目配置逐项明确允许，并继续服从 Harness 工具权限和审批。
4. 调用只接受 OpenAPI 声明的路径、查询、Header、Cookie、请求体和响应类型；未声明参数不得透传。
5. 凭据只由 Host 的环境或凭据引用注入，覆盖并拒绝模型传入的同名敏感 Header；工具结果不返回凭据或 `set-cookie` 等敏感响应头。
6. 私网/loopback、重定向、超时、文档大小、操作数量和响应大小均有边界；越界时失败而不是截断成普通成功。

## 异常与恢复

| 情况 | 用户可见状态 | 系统行为 | 恢复方式 |
|---|---|---|---|
| 当前 Session 未归属项目 | 不显示 API 文档能力或提示选择项目 | 不读取最近项目配置 | 进入真实项目会话 |
| 未配置 OpenAPI | 不显示“API 文档”页签 | 不探测默认公共地址 | 配置显式来源或让运行 Agent 报告真实来源 |
| 项目未运行 | 不显示“API 文档”页签 | 不访问猜测端口、不沿用旧运行来源 | 启动项目后重试 |
| iframe 被拒绝 | “页面禁止内嵌”＋外部打开 | 不放宽 sandbox 或顶层导航 | 外部打开或修正服务端策略 |
| OpenAPI 无效/过大 | 显示具体定义错误 | 不注册部分目录为成功 | 修复来源并重新加载 |
| 方法/私网/参数越权 | 调用被拒绝并说明原因 | 不发出网络请求 | 修改项目授权或调用参数 |
| 项目切换 | 新项目重新加载 | 取消旧请求，清除旧项目可操作内容 | 无需手动清理 |

## 验收标准

### AC-F012-001 · 当前项目真实 API 文档

- 来源：REQ-017, REQ-025, NFR-005, NFR-008, PSC-012, PSC-019, PSC-029
- 对应 PRD 验收：AC-016, AC-024
- Given 当前项目已进入项目开发、处于 `running`，并通过显式配置或当前运行报告提供真实 OpenAPI 来源
- When FDE 打开“API 文档”
- Then “API 文档”页签出现并展示当前项目真实文档及外部打开；停止、阻塞或缺少 OpenAPI 时页签收起，禁止内嵌和加载失败显示真实状态，不出现空白成功或其他项目地址

### AC-F012-002 · Agent 搜索和描述当前项目接口

- 来源：REQ-017, NFR-001, NFR-008, PSC-004, PSC-011, PSC-019
- 对应 PRD 验收：AC-016
- Given 当前项目配置了有效 OpenAPI 3.x 文档
- When Agent 搜索接口或描述一个 operationId
- Then 结果只来自当前项目的受信任定义，并包含声明的方法、路径、参数、请求体和响应；项目切换后不能继续查询上一项目目录

### AC-F012-003 · API 调用默认安全且可审计

- 来源：REQ-017, NFR-001, NFR-002, PSC-008, PSC-009, PSC-011, PSC-019
- 对应 PRD 验收：AC-016
- Given 当前项目只允许默认只读方法，并通过 Host 引用调用凭据
- When Agent 请求只读接口、写接口、私网目标或带额外参数的调用
- Then 合法只读调用留下受限结果与执行记录；未授权写方法、私网访问和未声明参数在网络请求前被拒绝，浏览器、对话和工具结果均不出现凭据值

### AC-F012-004 · 失败与项目切换不串 API

- 来源：REQ-017, NFR-005, NFR-007, NFR-008, PSC-004, PSC-012, PSC-014, PSC-019
- 对应 PRD 验收：AC-016
- Given 两个项目使用不同 API 配置，且其中一个文档或调用失败
- When 用户在两个项目会话之间切换并重试
- Then 每个项目只展示和调用自己的 API；单项目失败不被另一项目成功状态覆盖，重试仍使用明确项目身份

## 开放问题

- 写方法的项目级授权界面和审批粒度在实际 API 类型确定后继续细化；第一版默认只读。
