# F007 · 验收移交与项目完成规格

## 目标与可观察结果

项目完成部署试运行后，FDE 可以引用并统一全部前阶段事实，形成可取得、可验收、可使用、可维护的最终交付结果。项目进度展示四份固定产物、验收结论、已知问题和移交状态；满足条件只表示可以提交，仍只有 FDE 二次确认才能完成项目。

## 来源与范围

- 来源需求：REQ-001, REQ-003, REQ-005, REQ-012, REQ-028, NFR-001, NFR-002, NFR-004, NFR-005, NFR-007, NFR-008
- 来源总规格：PSC-002, PSC-005, PSC-006, PSC-007, PSC-010, PSC-011, PSC-012
- 对应 PRD 验收：AC-001, AC-003, AC-005, AC-010, AC-027
- 本 Feature 包含：最终交付物索引、企业验收、运维使用说明、培训/权限/责任/已知问题移交、退回/终止语义，以及 FDE 二次确认 `handoff → completed`。
- 本 Feature 不包含：企业独立门户、客户账号、电子签章、合同/回款、长期售后工单系统、跨项目资产库或把全部交付二进制复制进 Git。

- 全部前阶段正式基线、项目 PRD、验收方案、验证报告和当前最终交付版本。
- 企业验收反馈、未通过项、条件项、培训资料、权限/责任和后续处理决定。

## 用户旅程与状态

| 入口/前置 | 用户动作 | 过程与反馈 | 对象状态变化 | 可观察结果 | 下一步 |
|---|---|---|---|---|---|
| 项目进入验收移交 | 汇总交付物并组织验收 | 系统关联前阶段事实和证据，缺口保持可见 | preparing → ready-for-acceptance | 四份固定产物与可取得状态可审阅 | 继续补齐或记录验收 |

## 功能行为

### 主流程

1. 从部署试运行基线和前阶段正式产物建立最终交付索引，不重新生成互相冲突的第二份事实。
2. FDE 维护四份固定产物；项目进度展示文件、验收结论、交付物可取得状态、已知问题和责任移交。
3. 企业验收可以关联多份项目相对证据；验收逐项引用约定和证据，通过、带条件通过、退回和终止保持不同状态。
4. 条件项和已知问题记录接受人、理由、范围、责任和后续安排；退回项关联需要继续处理的阶段。
5. 项目进度提供独立人工记录入口，FDE 核对验收结论与证据、逐项交付物可取得状态、条件项决定、培训和权限/运维责任移交；Host 以当前合同摘要原子更新这些决定，不执行对应外部业务动作。
6. 只有验收为通过或带明确条件通过、交付物可取得、阻塞/条件项有决定且必要移交完成时，FDE 才能提交项目完成。
7. Host 以 expected revision 复核并只执行一次 `handoff → completed`。

### 业务规则与边界

- 代码完成、仓库存在、Demo 可访问、文件生成或 Agent 自评均不构成项目完成。
- V1 不直接要求客户登录；企业确认由 FDE 通过对话、来源材料或结构化动作记录并保留依据。
- `.fde/deployment-trial.json` 是部署授权和试运行状态的当前事实源；后续 Skill 和页面不能用旧版部署基线或试运行报告覆盖其已确认值。
- 交付物清单只记录位置、版本、校验信息和可取得状态；不得把明文凭据或大型二进制塞入普通文档/Git。
- 人工记录入口只能改变当前合同中已有交付物的 `available`、已有条件项的决定字段、验收结论/证据和三项责任移交/证据；不得从浏览器改写交付物名称、位置、版本、校验值或凭空新增对象。
- `conditionally-accepted` 只有条件、责任和后续处理明确时才能满足完成门；`returned` 和 `terminated` 不得进入 completed。
- Agent 和 Skill 只帮助生成候选材料，不能代替企业/FDE 验收、移交或项目完成决定。

## 异常与恢复

| 情况 | 用户可见状态 | 系统行为 | 恢复/重试 |
|---|---|---|---|
| 交付物路径无效或不可取得 | 清单项标记缺失 | 阻止完成，不用文件名猜测替代物 | 修复位置/权限并重新核验 |
| 验收证据包含多份文件 | 逐份显示可读/缺失 | 有界解析项目相对路径；任一缺失保持阻塞 | 补齐文件或移除错误引用后重新记录 |
| 部署 Markdown 与结构化状态冲突 | 显示结构化状态并提示材料待刷新 | 不把旧 `preparing` 传播到验收合同 | 让 Agent 按当前结构化事实刷新阶段材料 |
| 验收退回 | 显示未通过项和责任阶段 | 保留现有交付包，不显示完成 | 返回对应工作处理后重新验收 |
| 带条件通过但条件不完整 | 显示缺少责任/范围/安排 | 阻止完成 | 补齐条件决定后再提交 |
| 必要权限或责任未移交 | 显示具体缺口 | 不保存明文凭据、不伪造接管完成 | 完成受控移交并记录依据 |
| revision 冲突 | 提示交付事实已更新 | 拒绝旧确认 | 刷新并重新审阅后提交 |

## 验收标准

### AC-F007-001 · 四份最终产物统一引用真实事实

- 来源：REQ-003, REQ-005, REQ-028, NFR-001, NFR-002, NFR-005, NFR-007, NFR-008, PSC-005, PSC-007, PSC-010
- 对应 PRD 验收：AC-003, AC-005, AC-027
- Given 项目处于验收移交且部署试运行基线和前阶段产物可读取
- When FDE 维护四份固定产物
- Then 交付物、验收、运维和移交内容均引用当前项目真实版本与证据，交付物可取得状态明确，明文凭据和大型二进制不进入普通文档

### AC-F007-002 · 验收结论和退回保持真实

- 来源：REQ-003, REQ-005, REQ-028, NFR-001, NFR-004, NFR-008, PSC-005, PSC-006, PSC-010, PSC-011
- 对应 PRD 验收：AC-003, AC-005, AC-027
- Given 企业对当前交付版本提出通过、条件、未通过或终止结论
- When FDE 记录验收和已知问题决定
- Then 每项结论关联约定、证据、责任和后续安排；退回/终止不显示完成，带条件通过不掩盖条件

### AC-F007-003 · 项目进度展示统一交付状态

- 来源：REQ-003, REQ-012, REQ-028, NFR-005, NFR-007, NFR-008, PSC-002, PSC-005, PSC-011, PSC-012
- 对应 PRD 验收：AC-003, AC-010, AC-027
- Given 项目处于验收移交
- When FDE 打开项目进度中的当前项目
- Then 页面展示四份固定产物、交付物可取得状态、验收结论、已知问题、条件项和移交缺口；缺失或失败明确可见，不用假完成度代替

### AC-F007-004 · 只有 FDE 能完成项目

- 来源：REQ-001, REQ-005, REQ-012, REQ-028, NFR-001, NFR-004, NFR-005, NFR-008, PSC-002, PSC-006, PSC-007, PSC-010, PSC-011
- 对应 PRD 验收：AC-001, AC-005, AC-010, AC-027
- Given 验收为通过或带明确条件通过，交付物可取得，阻塞/条件项有决定，必要培训、权限和责任移交完成，四份固定产物齐备
- When FDE 二次确认并提交当前 expected revision
- Then Host 复核后只执行一次 `handoff → completed`；退回、终止、缺口或 revision 冲突保持验收移交并列出原因，Agent、Skill 和文件写入不能完成项目

### AC-F007-005 · FDE 可以如实记录验收和移交事实

- 来源：REQ-003, REQ-005, REQ-028, NFR-001, NFR-004, NFR-005, NFR-008, PSC-006, PSC-010
- 对应 PRD 验收：AC-003, AC-005, AC-027
- Given 项目处于验收移交，当前合同已经登记候选交付物和条件项，FDE 已取得企业验收或责任移交依据
- When FDE 在项目进度提交当前合同摘要、验收结论与多份证据、交付物可取得状态、条件项决定和责任移交状态
- Then Host 只原子更新允许变化的决定字段并返回最新阻塞；合同摘要过期、证据越界或必填决定不完整时拒绝，且操作不执行签章、上传、培训、权限变更或运维接管

## 开放问题

- 无。当前增量沿用已确认的项目内证据、FDE 代录企业结论和外部制品只引用边界。

## 延期边界

- `.fde/acceptance-handover.json` 允许项目专有交付物条目；V1 只保存受控位置、版本、校验值和可取得状态，并由 FDE 记录企业确认依据。具体外部存储由项目决定；企业独立门户、电子签章、制品上传和售后工单不进入当前 Feature。
