# F007 · 验收移交与项目完成实施计划

- F023 将提供部署试运行基线和 `pilot → handoff`；F010/F011 已提供统一阶段和项目详情；F005 已建立 expected revision 与 FDE 二次确认模式。
- F002/F006/F018/F020 已形成来源、验证、方案和研发产物；F007 只引用并统一这些事实，不建立新的交付文件仓库。

## 实现方案

本轮实现沿用“项目文件＋Host 可信投影＋FDE CAS 人工门”。交付物清单承担唯一最终索引，其他三份文件分别承接验收、运维和移交，不复制前阶段全文。Host 校验项目归属、固定路径、交付物可取得状态、验收结论、问题/条件项、必要移交和 revision；Client 只展示投影并收集 FDE 二次确认。

结构化事实固定保存在 `.fde/acceptance-handover.json`：最终版本、验收状态与多份项目相对证据、交付物名称/位置/版本/校验值/可取得状态、条件项及责任安排、培训/权限/运维责任移交状态与证据。`.fde/deployment-trial.json` 是前阶段当前授权与状态事实源，Skill 必须用它识别并刷新冲突的旧 Markdown。V1 由 FDE 记录企业确认，不增加客户账号或电子签章；外部制品只记录受控位置与可取得状态，Host 不主动上传、下载或探测外部地址。

项目进度增加一个绑定当前验收移交合同 SHA-256 摘要的结构化记录动作：Client 分步骤收集验收结论/摘要/证据、既有交付物可取得状态、既有条件项决定，以及培训/权限/运维责任移交和证据；Host 在项目锁内重新读取并核对摘要，只合并这些允许变化的字段，保留交付物身份、位置、版本和校验信息。动作只记录 FDE 已完成的外部事实，不代替执行外部动作；成功后刷新同一项目快照，仍由独立的 `handoff → completed` 二次确认完成项目。

## 实施顺序

1. 冻结项目专有清单扩展、FDE 代录企业确认和外部制品只引用边界。
2. 建立最终交付投影和四份固定产物扫描。
3. 增加验收结论、条件/退回/终止和移交缺口的可信状态。
4. 在项目进度展示四份产物、交付物、验收和移交状态。
5. 增加 `handoff → completed` Host 复核与 expected revision 冲突处理。
6. 增加精确合同摘要保护的 FDE 验收与移交事实记录动作，并让 Skill 以部署试运行结构化合同纠正过期材料。
7. 运行最窄 Host/Client 测试并由用户手动验收，不自动截图或完整 E2E。

## 依赖与风险

| 依赖/风险 | 影响 | 应对 | 验证时机 |
|---|---|---|---|
| 部署试运行基线缺失或不可读取 | 无真实试运行事实可消费 | Host 保持明确阻塞，不用样例或文件名猜测冒充 | 每次最终门复核 |
| 项目专有交付物差异大 | 通用字段可能遗漏关键制品 | 固定四份通用产物；清单允许项目专有条目，不建立通用硬编码模板 | 真实项目审阅 |
| 大型制品或凭据进入 Git | 泄露或膨胀仓库 | 只记录受控位置、版本、校验信息和责任 | Host/文档检查 |
| 条件通过被误读为无条件完成 | 风险和后续责任丢失 | 强制条件、责任、范围和安排；退回/终止不可完成 | 门槛测试 |

## 回退策略

后续若实现失败，移除新增的最终交付投影、页面和完成路由即可；已有四份文档和用户交付物不删除，项目保持 handoff，不自动标记 completed。
