# F031 · 实验室素材交付实施计划

## 现有上下文与复用

根因是 Host 只从包内 `.assets` 加载案例，该目录被 Git 与学员打包白名单排除；本机已有 248 文件、36,654,779 字节，五案例引用 234 份资料。原导入器已逐文件验证运行包摘要，原生训练与权限实现继续复用。保持 PSC-026、PSC-009。

现有 main 比 origin/main 领先一个 F029 检查点，F030 升级尚在工作树。用户要求重新提交，发布范围包含已完成的 F029、F030 和本次修复，不包含根 `.agents/`、`lefthook.yml` 等无关本机文件。根 docs 按用户既有明确要求与仓库合同保留。

|---|---|---|---|

## 实现方案

将本机已验证的 `.assets` 直接迁为同包 `assets/`，不保留两份持久副本。新增固定素材清单和单一校验函数，源码独立命令、Host 初始化与构建复用它；任何必需文件缺失或摘要不匹配均失败。Host 的素材失败仅影响实验室，训练数据库初始化错误不被素材检查吞掉。校验不复制或写运行数据。

原 ZIP 导入器保留为维护工具，目标改为 assets，仍验证固定输入且不覆盖不同字节；不再是新用户部署前提。包 files 显式包含 assets、清单和声明。删除旧“素材不进 Git”规则与过期安装指导，保留其他缓存/凭据排除。

学员构建器复用既有白名单和内部链接物化规则；新增对素材清单每条记录均进入 ZIP 的校验。版本元数据在构建时从实际 HEAD 和基座锁生成，避免手写旧提交。最终只有一个带日期源码 ZIP 放到桌面，不上传 ZIP 到普通 Git。

## 实施顺序

1. PRD/总 Spec、F031 三件套和白名单边界确认。
2. 固定资源迁移、清单、失败处理与针对性测试。
3. 构建与中文部署/分发说明更新。
4. 检查提交范围及秘密边界，建立本地源码提交以冻结打包输入，再执行打包 dry-run。
5. 从该源码版本构建最终 ZIP，在 mktemp 临时目录独立安装/构建和读取五案例。
6. 正常推送并核对远端；记录证据，停止临时 Host，清理本轮可重建验收目录，将唯一 ZIP 放到桌面。后续证据提交只改文档，不改变已验包的产品源码。

## 回退策略

候选 ZIP 失败不覆盖旧包，不删除原运行数据。源码变更作为正常 Git 提交保留，不强推；若需恢复旧行为，使用独立撤销提交并保留本轮诊断。素材迁移本身不改变训练目录。
