# F029 · 中文场景挑战实施计划

## 现有上下文与复用

- 当前实验室通过 `fde.workbench.lab.page` / `summary` 插槽接入统一导航；`ui-fde-discovery-lab` 保活同源业务训练 iframe。
- 新业务由独立 Host 插件 `packages/fde/scenario-challenge` 持有，独立 Client 插件 `packages/client/ui-fde-scenario-challenge` 贡献挑战页面；不增加 Agent Loop、模型或 Workspace 依赖。
- 复用 Connection 的 `createWebRequestTrust`、WebServer 路由、原子文件写入与锁、客户端资源 `useResource`、Slots、locale、Button/Modal 和主题 token。
- 保留 PSC-032 以及 PSC-026/PSC-027 的原训练隔离与导航行为。

## 实现方案

Host 以显式 `DSH_HOME/fde-scenario-challenge/state.json` 保存版本号、一个进行中轮次与最近 20 次完整结果。每次操作在文件锁内重新读取、验证并原子提交，完成后才返回成功；不读取或写入原训练数据库。轮次固定题库快照、开始和截止时间、答案与修订号，服务端校验题目/选项标识及版本，拒绝过期页面覆盖。截止比较在读取、保存和提交时统一执行；客户端计时只是显示与触发重新读取，不能决定延时或补答。

HTTP 使用独立 `/api/fde-scenario-challenge` 路径，复用 owner/同源信任检查。开始与交卷可幂等重试，答案保存用轮次身份与修订号；响应中的进行中题目不含正确选项或解析。错误使用稳定错误码，客户端映射为中文，意外错误不把文件路径或原始堆栈发给用户。无外部题库请求、账号和模型调用。

Client 在新插件内注册资源提供者与挑战插槽，资源状态和失效更新归该提供者所有。组件只消费资源、locale 与动作 callback；题号、历史选择和确认框为本地交互状态。原实验室外层增加两模块入口和返回，不重载已打开 iframe。新页面复用现有语义主题、清晰细边框与共享控件，窄屏自然换行，既有像素训练仍保留原最小宽度。

2026-11-02 人工反馈修复：桌面中将原生 `fetch` 保存在实例字段后直接以方法调用，会把 `ChallengeClient` 当成 Web API 接收者并抛出 `Illegal invocation`。读取与写入统一以普通函数方式调用传入的请求函数；不修改权限、地址、计时或持久化。增加接收者敏感的请求回归，并在实际桌面页面验证介绍与重试读取，不能只以 Host HTTP 200 作为这项缺陷的修复证据。

题库为平台自行编写的简体中文情境、选项和逐项解释，数据与 UI 文案分开维护。只保留必要技术缩写和代码内部标识，不复制参考项目代码/题库，不新增外部许可依赖。包 README 按仓库已有中英成对要求维护，产品规格只有中文。

## 实施顺序

1. 更新 PRD、Product Spec、Feature Map、本目录三件套及架构；运行规格校验后实施。
2. 实现中文题库与可恢复、可结算的轮次，并用确定性时钟测试截止边界。
3. 接入受认证的 HTTP 路由和独立文件持久化，验证失败、重复与并发。
4. 实现中文原生界面、资源读取与双模块导航，保留原训练。
5. 运行直接相关测试和必要构建，重启既有桌面运行区，仅核验在线资源后交用户人工体验。

## 依赖与风险

| 依赖/风险 | 影响 | 应对 | 验证时机 |
|---|---|---|---|
| 两页面同时答题 | 旧页面覆盖已存答案 | 修订号冲突并恢复，不静默合并 | Host 测试 |
| 后台限频或应用关闭 | 计时器不准 | 服务端绝对截止时间，读取时到期结算 | 轮次测试 |
| 存储失败/格式损坏 | 丢历史或假成功 | 原子写入、严格读取、失败不覆盖 | 文件持久化测试 |
| 新入口卸载原 iframe | 输入或训练现场丢失 | 已访问业务训练始终挂载，只隐藏 | 原实验室组件回归 |
| 中文含糊或多解 | 分数缺乏解释意义 | 明确题设约束、逐项解释，用户手动确认题目 | 题库检查与人工验收 |

## 回退策略

只停用两个新插件和撤回对应入口改动，保留独立答题数据与全部既有训练/项目；不执行破坏性 Git 回滚，不自动删历史，不切换全局运行区。
