# F011 · 项目进度实施计划

## 现有上下文与复用

- 官方 Workspace 列表提供全部项目的 WorkspaceId、名称、路径、创建时间和会话归属；F001/F010 分别提供项目基础信息和六阶段状态。
- `ui-fde-project` 已通过 `sidebar.footer.action`＋`shell.overlay` 提供不透出底层会话的完整页面，页面控制器已有 `overview | timeline | project`，项目详情已有资料、阶段产出、人工门和进入项目交付动作。
- `fde-project` 快照已经提供需求、方案和研发读模型；研发数据包括核心文档、Feature、真实任务勾选、可选日期/里程碑/阻塞、读取问题和三份收口产物。本轮不增加 Host 字段或第二套状态。

- 当前 `ProjectProgressOverlay.tsx` 以项目卡、无完整标签的六段条、平级“阶段输入/阶段产出”页签和纵向文档卡为主；本轮只重组该展示层，并复用 `project.module.css` 中现有主题变量。

## 实现方案

继续使用官方 `shell.overlay` 作为技术挂载点，但把产品行为改为完整页面：打开时在应用根设置明确页面状态，隐藏并禁用 Conversation 和 details/Dock 内容；页面自身使用不透明、主题化的完整工作区背景和滚动容器。Overlay 只是框架扩展槽，不再呈现为弹窗或透明遮罩。

页面控制器从布尔 `open` 扩展为 `closed | overview | timeline | project-detail`，项目详情携带明确 WorkspaceId。项目卡默认进入详情；详情保留“进入项目交付”。进入动作从目标 Workspace 的当前 Session 摘要中排除归档与子 Agent，按 `updatedAt` 选择最新普通会话；只有没有候选时才调用官方 `connectWorkspace` 建立或复用首个空白会话。外部项目/会话切换或关闭入口恢复 `closed` 并清理页面标记。

项目详情读取 F002 Source 列表，左侧/上方呈现资料清单和状态，预览区域声明 `fde.project.source.preview` Slot，把受控只读文件描述交给共享预览插件。客户原始资料继续使用 WorkspaceId/SourceId URL；阶段产出由 `fde-project` 只接受需求调研或方案设计合同中的固定 ArtifactId，解析到固定 Markdown 路径后返回同源只读 URL，不接受浏览器传入任意相对路径。每次进入项目详情都强制刷新 Host 产物快照，避免已生成文件或新架构 revision 被 Controller 的首次加载缓存遮蔽。

系统架构完整审阅仍由项目交付中的“系统架构”页承担。候选架构行提供“去确认架构”：复用“进入项目交付”的 Workspace/Session 选择规则，打开目标项目最新可见普通 Session，并通过 Conversation 的 scope-addressed 视图动作选中 `fde-architecture`。项目进度不调用确认接口；架构页“确认当前架构”成功后，用户再次进入项目详情会从 Host 读取并显示不可点击的“已确认 Rn”。

需求调研或方案设计人工门成功后，F011 自己保存 Host 返回的新 revision 并发布只含 WorkspaceId 的浏览器本地阶段变更通知。F010 的项目交付提示收到通知后强制重新读取 Host；通知只用于失效缓存，不携带权威阶段值，也不改变其他 Workspace。

本轮 UI 优化不修改上述控制器与 Host 数据流。组件内从现有 `ProjectRow`、`ProjectStageLoadState` 和 `ProjectSurfaceSnapshot` 生成纯展示视图：概览把项目身份、阶段编号/名称、六阶段位置和真实周期排成统一比较维度；只有真实项目不足以呈现组合效果时，额外拼接带 `demo` 标识的前端常量行，图表和卡片持续说明真实/演示构成，演示行禁用详情与时间轴动作且不进入任何 Store。详情增加本地 `viewedStage`，初始跟随 Host `currentStage`，用户点击阶段地图时只改变展示选择，Workspace 或 Host 当前阶段变化时重新对齐。

概览以标准六阶段流程作为页面主轴，并使用现有主题 Token 绘制阶段分布、交付健康和近六周项目动态。不同信息采用不同图形语法：阶段分布使用带流程关系的大小气泡，交付健康使用环图，协作节奏使用折线面积趋势，待决定/阻塞/节点使用数字信号卡；不得把多个区域都做成相同柱形卡片。图表只表达项目数量、显式演示风险/待确认项和活动次数，不把阶段序号或任务证据解释为项目完成百分比；真实项目缺少某类事实时保持“待确认”，不推断风险或里程碑。

项目组合页的配色以中性画布和明确层级为准：完整页面使用高不透明的主题背景，主卡使用 `bg-overlay`，次级区块使用 `bg-layer-1/2`；大面积区块不重复叠加蓝色渐变。蓝/紫只表达需求、方案、开发和协作趋势，橙色表达待决定/验证，红色表达阻塞，青绿色表达试运行/验收与正常活跃。阶段色和信号色只用于数字、轨迹、窄边和小范围强调，所有颜色继续来自现有语义 Token，不新增固定浅色主题或字面色值。

“全部项目”增加仅属于集合区域的本地 `card | list` 状态，初始固定为 `card`，不写入 Store 或持久化。卡片继续承担六阶段全貌；列表复用相同 `filteredRows`、阶段/健康派生函数和 `showProjectDetail`，以单行展示项目、阶段、周期、会话、状态、近期节点和动作。它与页面控制器已有的 `overview | timeline` 状态相互独立，演示行在两种集合视图中都保持禁用。

详情页把六阶段地图提升为固定方位层，下面只呈现一个阶段工作区。需求阶段复用 Source 与需求产物，方案阶段复用固定文档、架构 CTA 和人工门，研发阶段复用 F020 快照。后续阶段没有专属读模型时只显示阶段说明、真实当前状态和已有入口，不把研发文档重复显示为后续阶段产物。

研发视图先用 Feature 作为主要对象：展示原始 status、任务证据 `completed/total`、已声明日期、里程碑和 blocker；只有 `taskTotal > 0` 才绘制任务证据轨道。固定文档与三份收口产物收敛为证据组，点击后通过项目详情内的预览层打开；预览层继续调用现有 `renderPreview`，不改变文件 URL、下载或错误语义。

## 实施顺序

1. 更新 F011 与 F002/Architecture 合同。
2. 修正页面打开/关闭时的根状态、背景、焦点和底层内容隔离。
3. 把页面状态扩展为概览、时间轴和项目详情，并保持已有项目数据/进入交付逻辑。
4. 声明预览 Slot，接入 Source 列表、选中状态、识别状态和重试。
5. 完成聚焦组件/控制器测试、Client 构建、3080 重启，交由用户人工检查。
6. 在项目详情新增阶段输入/产出分区，读取固定文件快照，并接入只允许 FDE 发起的需求调研二次确认。
7. 为已有固定产物增加受控同源文件地址，复用共享预览 Slot 在阶段产出区域显示 Markdown 原件。
8. 在人工门成功后联动刷新项目交付阶段提示，并把“进入项目交付”收敛为目标项目最新可见普通会话、无候选时才建立空白会话。
9. 在方案设计详情读取项目 PRD 等五份固定文档与架构状态，复用 Markdown 预览并接入 `solution → development` 二次确认。
10. 把候选架构状态改为“去确认架构”，接通目标 Session 的系统架构 View，并在进入项目详情时刷新真实产物快照。
11. 重组项目概览的比较层级与项目卡阶段表达，加入标准六阶段流程、组合图表和显式不可交互演示项目，保留真实项目的概览/时间轴和项目选择行为。
12. 把单项目头部改成带完整名称、可选择且只读的六阶段地图，并建立阶段专属工作区导航。
13. 把项目开发内容改为 Feature/任务证据/真实节奏优先的可视结构，保留文档状态、人工门和全部失败语义。
14. 把产物正文改为不丢失项目与阶段上下文的渐进预览层，并完成现有主题和窄窗口适配。
15. 运行 F011 最窄组件测试与 Client Bundle，恢复隔离预览服务后交由用户人工验收；不运行全量浏览器回放或自动视觉对比。
16. 接入 F005 单步返回：原因和二次确认只在项目详情提交；Host 返回后刷新同项目状态，六阶段地图显示待重新确认范围和最新返回审计。
17. 在“全部项目”区域加入默认卡片、可切换列表的本地展示状态；列表复用同一筛选、数据和项目进入动作，不改页面控制器和 Host。

## 依赖与风险

| 风险 | 应对 | 验证 |
|---|---|---|
| overlay 技术层仍允许底层交互 | 根页面状态同时隐藏/禁用 Conversation 与 details，并在关闭时清理 | 组件状态测试＋人工验证 |
| 背景皮肤使用半透明 token | 页面建立自己的完整表面；允许显示主题背景，但不显示底层组件 | 主题样式检查 |
| 项目详情变成第二套文件管理器 | 只读列表、预览和识别重试；编辑/移动/删除只在项目交付 | 组件动作测试 |
| 资料加载慢或单个损坏 | 列表、预览、识别分别加载和失败，不阻断项目基本信息 | Controller 测试 |
| 产物预览地址被扩展成任意项目文件读取 | Host 只接受固定 ArtifactId，并在已登记 Workspace 的固定目录内解析真实文件 | Host 路由与组件聚焦测试 |
| 项目进度和项目交付持有不同阶段缓存 | 人工门成功后会话头部继续显示旧阶段 | F011 成功后只通知 WorkspaceId；F010 重新读取 Host 已提交状态 | 两个 controller 联合聚焦测试 |
| `connectWorkspace` 被误当作“打开项目” | 已有工作时新建或打开空白会话，用户看不到最近对话 | 先从目标 Workspace 普通可见 Session 中按 `updatedAt` 选择；无候选时才使用 `connectWorkspace` | 导航动作聚焦测试 |
| 项目进度直接确认候选架构 | FDE 未阅读完整架构即改变项目事实 | 项目进度只导航；确认接口继续只由系统架构页调用 | CTA 组件测试＋导航动作测试 |
| 项目详情复用旧产物快照 | Agent 已生成文件或架构已确认，但页面仍显示待生成/待确认 | 每次进入明确项目详情时强制刷新该 Workspace 的 Host 快照 | 页面进入效果测试 |
| 点击六阶段地图被误解为阶段推进 | 查看未来阶段时用户误认为项目已经进入该阶段 | 当前阶段保持独立强标识并显示“正在查看”；点击只更新本地 `viewedStage`，不调用任何阶段接口 | 组件交互测试 |
| 研发任务轨道被误读为 Feature/项目完成率 | 真实勾选数被放大为业务完成结论 | 文案固定使用“任务证据”，零任务不绘制，阶段/项目不显示百分比 | 研发状态组件测试 |
| 阶段专属重组造成已有入口消失 | Source 识别、架构审阅或人工门变得不可达 | 先建立现有动作清单，再在新层级中逐一保留并用原 handler | 入口可达性组件测试 |
| 预览层遮挡或关闭后丢失上下文 | 用户需要重新寻找项目、阶段或 Feature | 预览只持有 selected artifact；关闭不清空 viewed stage，主层保持挂载 | 预览开关组件测试 |
| 主题背景降低信息可读性 | 某套现有皮肤下阶段和状态不清楚 | 只使用现有不透明/半透明表面与语义色 Token，保留边界和文字对比 | CSS Token 静态检查＋人工验收 |
| 演示项目被误认为真实交付数据 | 用户尝试进入演示项目或把样例指标作为经营事实 | 卡片、汇总和图表持续标记“演示”；演示行只存在于 Client 展示常量且全部动作禁用；零真实项目仍显示真实空态 | F011 概览组件测试 |
| 卡片/列表与概览/时间轴混成同一状态 | 用户切换列表后误进入时间轴，或阶段筛选被重置 | 集合视图只使用组件本地状态；页面模式、阶段筛选、数据集合和导航 handler 保持独立 | F011 概览组件测试 |
| 返回按钮被误解为删除或任意跳转 | 用户担心历史丢失或绕过阶段门 | 展开确认明确保留全部产物；Client 不发送目标阶段，Host 固定返回一步 | 状态/路由与组件测试 |

## 回退策略

F011 仍是独立 Client Plugin；移除 Bundle row 即恢复官方会话工作区。Source 原件、阶段和项目数据不受页面回退影响。不得恢复已经被否定的会话页签或透明悬浮形态。
