# F009 · 项目开发工作区规格

## 目标与可观察结果

FDE 在当前项目中无需离开工作台即可浏览项目目录、打开和保存文本、查看 Git 差异与 Agent 文件变化，并同时继续项目 Agent 对话。左侧项目/会话和中央对话保持为稳定主路径；开发能力按需从右侧 Dock 展开。

## 来源与范围

- 来源需求：REQ-015, NFR-003, NFR-005, NFR-008, NFR-010
- 来源总规格：PSC-012, PSC-014, PSC-017
- 对应 PRD 验收：AC-014
- 本 Feature 当前切片包含：可收起的右侧开发 Dock；当前项目文件树；文本和 Markdown 打开、编辑、保存；外部变化刷新与未保存冲突提示；Git 状态与 Diff；按当前会话/轮次组织的 Agent 文件审查、撤销与重新应用；从对话文件结果打开右侧文件；Dock 收起与恢复。
- 本 Feature 当前切片不包含：完整 VS Code、扩展市场、调试器、语言服务诊断、终端/浏览器/侧边对话等非必要工作台页面、项目阶段验证证据、部署或交付状态。

## 用户旅程与状态

| 入口/前置 | 用户动作 | 过程与反馈 | 对象状态变化 | 可观察结果 | 下一步 |
|---|---|---|---|---|---|
| 已进入项目会话 | 点击开发工作台开关或对话中的文件路径 | 右侧 Dock 以当前项目/会话身份打开 | 不改变项目或会话 | 左侧项目树与中央对话不移动，右侧显示当前项目文件或文件树 | 打开文件、Diff、审查或继续对话 |
| 文件树存在文本或 Markdown | 在右侧文件 Tab 点击文件并编辑后保存 | 读取文件版本并在保存时校验外部变化 | 文件成功更新或进入冲突状态 | 右侧显示语法文本/Markdown；成功真实落盘，冲突给出重新加载或保留选择 | 继续编辑、查看 Diff 或让 Agent 工作 |
| Agent/工具产生文件 | 查看对话尾部改动摘要，或打开右侧文件审查/Git | 工作台按当前会话轮次整理 Agent 文件变化，并把文件或 Diff 打开到同一 Dock | 审查状态、打开文件或 Diff 改变，不改变会话归属 | 中央保留生成结果的对话，右侧显示对应文件、Git 差异或 Agent 轮次差异 | 检查、撤销/重新应用、修订或继续提问 |
| 用户切换项目 | 选择另一项目及会话 | 终止旧项目文件的可操作上下文并加载新 Workspace | 当前项目、会话和文件范围一起变化 | 旧项目文件不再可保存；新项目文件树重新加载 | 在新项目继续工作 |
| Git/编辑能力不可用 | 打开相关入口 | 显示真实空态或失败原因 | 项目与会话保持不变 | 文件浏览或对话仍可使用；不显示伪造 Diff/保存成功 | 修复环境或使用明确降级路径 |

## 功能行为

### 主流程

1. 左侧始终保留“项目 → 会话”，开发能力不得作为项目浏览器中的同级业务导航，也不得替换或删除项目入口。
2. 中央始终渲染官方项目 Conversation、Composer、工具调用、审批和队列；右侧 Dock 的展开、Tab 切换和收起不建立第二条对话。
3. 展开右侧文件 Tab 后，只加载当前项目 Workspace 的目录；没有当前项目时不允许浏览最近目录或进程目录。
4. 打开文件后在右侧工作台内形成编辑 Tab；文本与 Markdown 可编辑并保存，二进制或超限文件显示明确不可编辑状态。
5. 当前会话的 Agent 文件写入或编辑成功落盘后，右侧文件树自动重新加载根目录和已展开目录，新建、删除或改名结果无需用户手动刷新；流式文本和只读工具不得造成持续刷新。
6. 已打开文件在页面可见时检查外部版本；干净文件自动刷新，存在未保存草稿时显示“重新加载/保留当前内容”等明确选择。
7. Git 可用时，右侧 Git Tab 展示当前项目仓库状态与真实 Diff；Git 不可用时不影响文件、审查与对话。
8. Agent 直接文件工具的 Diff 继续由官方工具卡提供；对话尾部同时提供本轮文件改动摘要，右侧文件审查 Tab 按当前会话/轮次展示行级差异，并对可安全处理的变化提供撤销/重新应用。Git Diff 仍只表示版本库差异，不能冒充 Agent 轮次审查。
9. 右侧 Dock 可以收起并恢复；收起不结束或改写当前会话，重新打开恢复当前会话的工作台状态。

### 业务规则与边界

- 当前 WorkspaceId 与 SessionId 分别约束项目文件范围和 Agent 审查归属；任何组件不得使用最近项目或其他会话隐式回退。
- 用户保存、Agent 修改和外部编辑都写入同一个项目目录；工作台不维护平行文件副本作为正式版本。
- 未保存草稿只属于页面编辑状态，刷新可能丢失，不能冒充已保存项目文件。
- 文件删除、Git 丢弃、提交和远程操作沿用其真实确认与失败语义，不因工作台安装而自动执行。
- Agent 文件审查覆盖当前会话中能够从官方工具结果和 Code Mode 记录重建的文件变化；Shell、外部编辑器或会话外变化只能进入 Git/磁盘视图，不得被错误归因给某轮 Agent。

## 异常与恢复

| 情况 | 用户可见状态 | 系统行为 | 恢复/重试 |
|---|---|---|---|
| 没有当前项目 | 文件/变更入口不可操作或显示先选择项目 | 不读取进程目录或最近 Workspace | 先创建或选择项目 |
| 文件被外部修改且编辑器无草稿 | 内容刷新并保持当前路径 | 使用磁盘新版本替换干净视图 | 继续查看或编辑 |
| 文件被外部修改且编辑器有草稿 | 明确冲突与重新加载/保留选择 | 不静默覆盖任一方 | 用户选择后继续 |
| 二进制、超限、越界或符号链接 | 显示不可读/不可编辑原因 | 拒绝文本保存与越界访问 | 使用外部工具或选择受支持文件 |
| 项目不是 Git 仓库 | Git 区显示非仓库空态 | 不伪造变化或自动初始化 | 文件工作继续；需要时由用户明确初始化 |
| Agent 文件变化无法形成完整可逆 Diff | 显示不可撤销或不支持状态 | 保留文件与原工具记录，不执行猜测性回滚 | 用户通过 Git、编辑器或继续对话处理 |
| 工作台插件加载失败 | 回到既有项目/会话与官方对话 | 不影响 Workspace、Session 或已有项目文件 | 修复/移除插件后重启 |

## 验收标准

### AC-F009-001 · 右侧开发 Dock 保持项目主路径

- 来源：REQ-015, NFR-005, NFR-010, PSC-014, PSC-017
- 对应 PRD 验收：AC-014
- Given 用户已打开一个项目会话
- When 用户展开右侧开发 Dock 并打开任一文件
- Then 左侧项目/会话和中央同一项目对话保持原位，文件在右侧打开；收起 Dock 不创建、切换或结束会话

### AC-F009-002 · 文本保存与外部变化不造假

- 来源：REQ-015, NFR-003, NFR-008, NFR-010, PSC-012, PSC-017
- 对应 PRD 验收：AC-014
- Given 当前项目中存在可编辑文本文件
- When 用户保存，或 Agent/外部工具在文件打开期间修改该文件
- Then 无冲突保存真实落盘；Agent 成功新建、删除或改名后文件树自动显示结果；干净视图刷新，未保存草稿收到冲突提示且不被静默覆盖；失败不显示成功

### AC-F009-003 · Git Diff 与 Agent 审查语义真实

- 来源：REQ-015, NFR-003, NFR-005, NFR-008, PSC-012, PSC-017
- 对应 PRD 验收：AC-014
- Given 当前项目存在 Git 差异，或当前会话的 Agent 已通过文件工具/Code Mode 修改文件
- When 用户打开右侧 Git Diff 或文件审查
- Then 右侧显示对应真实差异并明确其来源；Agent 审查按当前会话/轮次组织，Git 不可用时显示降级，Shell/外部变化不被错误归因给 Agent

### AC-F009-004 · 项目切换不串文件

- 来源：REQ-015, NFR-008, NFR-010, PSC-014, PSC-017
- 对应 PRD 验收：AC-014
- Given 工作台存在至少两个项目且已打开第一个项目的文件
- When 用户切换到第二个项目会话
- Then 右侧文件树、审查与后续文件操作只作用于第二个项目/会话，第一项目的打开内容不再可保存到第二项目；两个项目的对话和文件均保持原归属

## 开放问题

- 子代理与 Shell/外部编辑共同修改同一文件时的完整归因与冲突处理，等待当前右侧 Dock 人工验收后再决定是否扩展；当前实现必须诚实标记无法归因或不可安全撤销的变化。
