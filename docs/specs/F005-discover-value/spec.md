# F005 · 阶段 1：发现高价值问题规格

## 目标与可观察结果

FDE 从继承简报、客户资料、真实流程知情者和代表案例出发，分开保存“卖出的说法、人员陈述、现场观察、系统行为和政策授权”，判断哪个工作流问题值得继续，并明确安全回退、证据缺口和下一项现场动作。

## 来源与范围

- 来源需求：REQ-003, REQ-006, REQ-007, REQ-018, REQ-019, REQ-025, REQ-026, REQ-028, NFR-002, NFR-004, NFR-011, NFR-013, NFR-014
- 来源总规格：PSC-003, PSC-005, PSC-006, PSC-015, PSC-021, PSC-022, PSC-023
- 本 Feature 包含：阶段 1 工作台、现场资料与观察、方法路由、必要 Artifact、冲突重构和 FDE 决定。
- 本 Feature 不包含：完整价值经济性、技术方案选择、代码实现和生产批准。

|---|---|---|---|

## 用户旅程与状态

| 入口/前置 | 用户动作 | 过程与反馈 | 对象状态变化 | 可观察结果 | 下一步 |
|---|---|---|---|---|---|
| V2 项目阶段 1 | 上传资料并描述现场问题 | 推荐观察、访谈或工作流资格判断 | 输入与工作项新增 | 看见为什么先观察而非设计方案 | 补代表案例或开始资格判断 |

## 功能行为

### 主流程

1. 保存原始资料而不把上传解释为 Agent 已读或事实成立。
2. 引导用户找到真实流程知情者、一个正常案例和一个重要异常案例。
3. 路由 `qualify-ai-workflow`，只加载当前任务所需参考与工具。
4. 当关键说法冲突并改变边界时，条件触发 `reframe-ai-engagement`。
5. 形成 Field Observation Log、Workflow Charter starter，并在需要时形成 Engagement Reframe starter。
6. 工作台展示输入、当前工作、Artifact、证据缺口和可提交的 FDE 决定。

### 业务规则与边界

- 没有流程知情者、代表案例、结果验证者、可访问上下文或风险上限时，不能进入方案设计。
- 基线未知必须写为未测，不能由 Agent 估算成现场事实。
- `discover`、`defer`、`do_not_build` 是方法结论；项目阶段仍由 FDE 记录 Go／Revise／Narrow／Stop。

## 异常与恢复

| 情况 | 用户可见状态 | 系统行为 | 恢复/重试 |
|---|---|---|---|
| 只有演示资料，没有代表案例 | 缺少现场证据 | 保持 Artifact 待验证 | 添加近期案例后重跑 |
| 冲突缺少有权处置人 | 等待责任人 | 保存冲突和安全回退，不默认同意 | 补充权限依据和处置 |
| Skill 或 Artifact 校验失败 | 工作失败或结构无效 | 保留输入和执行轨迹，不发布有效 Artifact | 修复字段或适配器后重试 |

## 验收标准

### AC-F005-001 · 业务化发现工作与按需路由

- 来源：REQ-006, REQ-007, REQ-025, REQ-026, NFR-004, NFR-013, NFR-014, PSC-005, PSC-006, PSC-021, PSC-022
- 对应 PRD 验收：AC-006, AC-022, AC-023
- Given 当前项目只有继承简报、资料和不完整现场信息
- When 用户描述要理解的工作流问题
- Then 工作台用业务语言推荐资格判断或冲突重构，只加载必要方法与工程 Skills，并如实显示输入、过程、缺口和预计 Artifact

### AC-F005-002 · 可组合发现 Artifact 与人工去留决定

- 来源：REQ-003, REQ-018, REQ-019, REQ-028, NFR-002, NFR-011, PSC-003, PSC-015, PSC-023
- 对应 PRD 验收：AC-016, AC-017, AC-025
- Given 已完成代表案例观察并形成候选结论
- When 系统发布 Workflow Charter 或 Engagement Reframe 并由 FDE 评审
- Then Artifact 记录来源版本、结构状态和证据状态，文档存在不代表生产就绪，只有 FDE 决定改变阶段
