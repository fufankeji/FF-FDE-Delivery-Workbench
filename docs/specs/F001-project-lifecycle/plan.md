# F001 · 项目身份与 V2 生命周期实施计划

## 现有上下文与复用

- 当前实现与入口：`packages/fde/project` 管理项目事实，`packages/fde/stage` 管理 V1 六阶段，`ui-fde-project` 与 `ui-fde-stage` 提供现有入口。
- 直接复用点：项目隔离存储、阶段快照、人工阶段确认、项目目录绑定和现有测试夹具。
- 必须保持的现有行为：V1 项目、会话、资源、右侧工作台与当前六阶段入口继续可用。
- 必须保持的 Product Spec 合同：PSC-001, PSC-003, PSC-004, PSC-008, PSC-009, PSC-010。

## 影响范围

| 路径/模块 | 当前职责 | 计划变化 | 对应 AC |
|---|---|---|---|
| `app/deepseek-harness/packages/fde/project` | 项目解析与持久化 | 增加显式生命周期版本和隔离校验 | AC-F001-001 |
| `app/deepseek-harness/packages/fde/stage` | 六阶段状态与门禁 | 增加 V2 八阶段状态、决定记录和返回语义 | AC-F001-002 |
| `app/deepseek-harness/packages/client/ui-fde-project` | 项目入口与切换 | 只投影已解析的当前项目身份 | AC-F001-001 |
| `app/deepseek-harness/packages/client/ui-fde-stage` | 阶段入口 | 消费 V1/V2 对应生命周期而不自行推断 | AC-F001-001, AC-F001-002 |

## 实现方案

在项目元数据中加入显式生命周期版本；Host 先按隔离根目录解析项目，再由阶段域返回对应状态机。V2 状态机只接受带 FDE 身份、理由和影响范围的决定命令。返回阶段时追加历史与重评标记，不覆写 Artifact。Client 只消费 Host 快照，不从文件数量或构建结果推断阶段。

## 实施顺序

1. 固化当前 V1 项目与阶段契约测试。
2. 增加生命周期版本、V2 阶段定义和决定对象。
3. 实现合法迁移、返回、重评和 Stop 规则。
4. 将项目与阶段 UI 改为按生命周期版本投影。
5. 验证隔离、V1 保护和失败恢复。

## 依赖与风险

| 依赖/风险 | 影响 | 应对 | 验证时机 |
|---|---|---|---|
| 现有项目未声明生命周期版本 | 可能被错误解释为 V2 | 缺省严格识别为 V1，不自动迁移 | 项目解析测试 |
| UI 仍按六阶段数组渲染 | V2 阶段显示错误 | 阶段定义由 Host 合同提供 | 客户端契约测试 |
| 返回操作误删候选结果 | 破坏证据链 | 仅追加决定和重评状态 | 返回流程测试 |

## 回退策略

V2 入口使用显式版本分支；若切片失败，停止创建 V2 项目并保留已写入的元数据和诊断，V1 分支与已有项目不回滚、不重写。

## 验收映射

| AC | 实现结果 | 最窄验证方法 | 预期证据 |
|---|---|---|---|
| AC-F001-001 | 项目隔离且 V1/V2 明确分流 | 运行 project 与 stage 定向测试 | 两类夹具保持各自生命周期，跨目录读取被拒绝 |
| AC-F001-002 | 只有 FDE 决定能迁移，返回保留事实 | 运行 V2 状态机迁移测试 | 自动事件不迁移；决定、历史与重评范围可读取 |
