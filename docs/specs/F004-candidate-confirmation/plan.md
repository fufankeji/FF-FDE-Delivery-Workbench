# F004 · 候选产物与人工确认实施计划

## 现有上下文与复用

- 官方 Skill Registry 和 `skill` 工具已经提供“目录中只展示摘要、使用时加载正文”的轻量机制。
- `systemPrompt.section()` 可在每次模型请求根据当前 Agent 的 Workspace 与阶段返回短约束，无需切换 Session Preset 或修改 Agent Loop。
- F002 已保存原始资料，F011 已提供项目详情，F010 已持久化当前阶段。

## 影响范围

| 模块 | 计划变化 | 对应 AC |
|---|---|---|
| `packages/fde/stage` | 注册需求调研 Skill 和阶段感知短提示 | 001, 003 |
| `packages/fde/project` | 固定产物合同并读取真实文件状态 | 002, 003 |
| `packages/client/ui-fde-project` | 项目详情增加阶段输入/产出 | 002, 003 |
| 文档/测试 | 合同、状态读取和组合验证 | 全部 |

## 实现方案

由 `fde-stage` 在 Host 侧注册一个内置 Runtime Skill，并在系统提示中只注入当前阶段、固定路径、按需加载 Skill 和禁止 Agent 推进四类短规则。标准正文继续通过现有 `skill` 工具按需加载，避免把整套模板放进每轮上下文。

`fde-project` 只读检查三个固定项目相对路径，不创建空白文件、不解析内容为确认事实。F011 复用同一快照展示状态；FDE 的显式阶段确认由 F005 当前需求调研门负责。

## 实施顺序

1. 冻结三份产物、路径和候选语义。
2. 注册 Skill 与需求调研阶段提示。
3. 增加 Host 产物快照和项目进度输入/输出展示。
4. 运行 Host/Client 聚焦测试和包级 TypeScript 检查。

## 依赖与风险

| 依赖/风险 | 影响 | 应对 | 验证时机 |
|---|---|---|---|
| 当前阶段与 Workspace 解析错误 | Skill 或产物状态可能串项目 | 只接受已注册 WorkspaceId，并按 Agent cwd 精确匹配项目 | Host 聚焦测试 |
| 文件存在被误认为已经确认 | 需求可能提前进入下一阶段 | 快照只报告文件状态，阶段推进固定交给 F005 人工动作 | Client/Stage 组合测试 |
| Skill 正文每轮注入 | 增加上下文并干扰普通对话 | 系统提示只保留 Skill 名称与短规则，正文按需加载 | Prompt 注册测试 |

## 回退策略

移除 Skill/提示注册即可恢复普通 Agent；移除 F011 的阶段产出区域不删除任何项目文件。回退不得修改 `fde-resources/` 或已生成的交付物。

## 验收映射
