# F004 · 候选产物与人工确认规格

## 目标与可观察结果

需求调研阶段不依赖使用者临时编写 Prompt。工作台向项目 Agent 提供同一套需求调研 Skill 和阶段约束，引导 Agent 基于当前项目资料与多轮对话生成、更新固定目录中的三份 Markdown 产物；项目进度读取这些真实文件并展示“未生成／已有文件／待 FDE 确认”，但文件存在或 Agent 自评都不等于客户确认或阶段完成。

## 来源与范围

- 来源需求：REQ-003, REQ-009, REQ-010, REQ-011, NFR-001, NFR-003, NFR-004, NFR-005, NFR-007, NFR-008
- 来源总规格：PSC-004, PSC-005, PSC-006, PSC-007, PSC-011, PSC-018, PSC-026
- 对应 PRD 验收：AC-003, AC-009, AC-010, AC-015
- 当前切片包含：需求调研内置 Skill；当前阶段提示；三份固定产物与路径；真实文件状态；项目进度中的阶段输入/输出分区；人工确认边界。
- 当前切片不包含：自动生成、自动读取全部资料、Agent 自动推进、客户门户、多人审批、后续五阶段产物模板和通用文档工作流。

## 需求调研产物合同

| 产物 | 固定路径 | 用途 | Agent 边界 |
|---|---|---|---|
| 需求调研报告 | `fde-deliverables/01-requirement-research/requirement-research-report.md` | 汇总业务背景、目标、角色、流程、系统与数据、范围、约束、风险和验收方向 | 必须区分来源事实、推断与未知项 |
| 需求确认清单 | `fde-deliverables/01-requirement-research/confirmation-checklist.md` | 记录需要向客户确认的问题、依据、影响和当前结论 | 不得替客户或 FDE 填写已确认结论 |
| 需求基线 | `fde-deliverables/01-requirement-research/requirement-baseline.md` | 汇总准备进入方案设计的范围、边界、验收方向和仍保留的未决项 | Agent 只能形成候选；只有 FDE 明确确认后才可作为阶段依据 |

## 用户旅程与状态

| 入口/前置 | 用户动作 | 过程与反馈 | 对象状态变化 | 可观察结果 | 下一步 |
|---|---|---|---|---|---|
| 项目处于需求调研 | FDE 让 Agent 分析资料并形成阶段材料 | Agent 按需加载 Skill，并读取本次授权资料与已有产物 | 同一路径中的候选文档被创建或更新 | 项目进度显示三份真实文件状态 | 继续沟通和修订 |
| 客户补充资料或修改结论 | FDE 上传资料并继续对话 | Agent 重新核对来源、推断和未知项 | 既有候选文档原位更新 | 不产生平行 final/v2 文件，也不推进阶段 | FDE 审阅输入和输出 |
| 三份产物已经存在 | FDE 打开项目进度 | Host 只读检查固定路径 | 候选状态不变 | 需求基线仍显示待 FDE 确认 | 使用 F005 人工交付门 |

## 功能行为

1. 当当前项目处于“需求调研”时，模型请求获得一段短阶段约束；只有被要求生成或更新上述产物时，Agent 才加载 `fde-requirement-research` Skill。
2. Skill 要求先读取用户本次授权的项目资料、已有产物和当前对话，再更新同一路径；不得重复创建 `final-v2`、`new` 等平行文件。
3. Skill 只规定文档结构、证据标记和路径，不固定客户结论，也不自动发起模型调用。
4. 项目进度的“阶段输入”展示当前项目原始资料；“阶段产出”按固定合同展示三份真实文件。缺失文件显示“待生成”，不得生成假内容或假完成率。
5. 需求基线文件存在时仍显示“待 FDE 确认”；Agent、Skill 和文件写入均无阶段推进能力。

## 异常与恢复

| 情况 | 用户可见状态 | 恢复 |
|---|---|---|
| Skill 未加载或生成失败 | 对话显示真实失败；产物继续显示原状态 | 用户重试当前请求或人工编辑文件 |
| 产物路径缺失 | 单项“待生成” | 在项目交付中让 Agent 生成或手动创建 |
| 文件读取失败 | 单项“读取失败”，不计为存在 | 修复项目文件后刷新 |
| 资料新增或需求变化 | 既有产物仍可见但不自动视为最新确认 | 重新对话并更新同一文件 |

## 验收标准

### AC-F004-001 · 固定产物规范可被 Agent 按需加载

- 来源：REQ-003, REQ-009, NFR-003, NFR-005, PSC-004, PSC-005
- 对应 PRD 验收：AC-009
- Given 当前项目处于需求调研并拥有项目资料
- When FDE 请求 Agent 生成或更新阶段产物
- Then Agent 被要求先加载 `fde-requirement-research`，并只在固定目录更新三类标准产物，不自动推进阶段

### AC-F004-002 · 项目进度真实展示输入与产出

- 来源：REQ-010, NFR-001, NFR-005, NFR-007, NFR-008, PSC-005, PSC-011, PSC-018, PSC-026
- 对应 PRD 验收：AC-015
- Given 当前项目存在零到多份原始资料和零到三份标准产物
- When FDE 打开项目进度中的项目详情
- Then “阶段输入”显示真实原始资料，“阶段产出”逐项显示固定路径及真实文件状态；缺失不补造，文件存在不显示为阶段已完成

### AC-F004-003 · Agent 输出不替代人工确认

- 来源：REQ-011, NFR-003, NFR-004, PSC-006, PSC-007
- 对应 PRD 验收：AC-003, AC-010
- Given Agent 已生成三份标准产物
- When Agent 完成回复或文件写入
- Then 当前阶段仍保持需求调研，需求基线显示待 FDE 确认，且 Agent 没有确认或推进阶段的工具

## 开放问题

- 后续五个阶段各自需要哪些固定产物，等进入对应阶段设计时再补充；本 Feature 不预设通用模板系统。
