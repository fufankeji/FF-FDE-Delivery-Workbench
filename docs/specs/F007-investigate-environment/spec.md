# F007 · 阶段 3：调查现场环境规格

## 目标与可观察结果

FDE 在承诺方案前，查清真实数据、系统、接口、身份、权限、组织责任和治理边界，形成可引用的现场地图与缺口；连接动作必须同时具备最小权限、动作政策、人工升级路径以及独立的安全、隐私、法务审查状态。

## 来源与范围

- 来源需求：REQ-003, REQ-006, REQ-007, REQ-020, REQ-021, REQ-025, REQ-026, REQ-028, NFR-002, NFR-004, NFR-011, NFR-012, NFR-013, NFR-014
- 来源总规格：PSC-003, PSC-005, PSC-006, PSC-016, PSC-017, PSC-021, PSC-022, PSC-023
- 本 Feature 包含：数据就绪、系统与调用链调查、访问边界、责任归属、动作政策、人工升级和三类治理审查。
- 本 Feature 不包含：最终机制选择、生产凭据授予、详细方案、实现或治理批准代签。

## 功能行为

### 主流程

1. 从阶段 2 固定版本读取结果、范围、责任和停止条件。
2. 按目标选择数据、系统、接口、仓库或组织调查，不默认扫描整个工作区。
3. 在执行前展示请求的读取范围、身份、工具和是否可能产生外部影响。
4. 使用 DeepSeek Harness 工具执行只读检查，并将命令、结果和来源写入 Artifact。
5. 对真实连接建立动作政策、最小权限和人工升级路径；对安全、隐私、法务分别送审。
6. 由 FDE 根据缺口与审查结论决定进入方案、收窄范围、返回补证或停止。

### 业务规则与边界

- Data Context Manifest 的 starter／complete 只表达结构成熟度，不能证明数据准确、授权有效或治理通过。
- 一个治理审查通过不得推断另外两项通过；Agent 不得代填责任人、批准人或凭据。
- 只读调查与未来可写动作必须分开授权，工具可用不等于用户有权执行。

## 异常与恢复

| 情况 | 用户可见状态 | 系统行为 | 恢复/重试 |
|---|---|---|---|
| 缺少账号或审批人 | 等待访问 | 不尝试绕过权限 | 补有权责任人与最小访问 |
| 系统说明与真实行为不一致 | 发现冲突 | 同时保存声明与观察，不覆盖任一方 | 交由责任人确认或重构范围 |
| 某项治理未通过 | 对应治理阻塞 | 仅阻止受影响连接或动作 | 整改、收窄或取得例外批准 |

## 验收标准

### AC-F007-001 · 现场调查按最小范围执行且过程可理解

- 来源：REQ-006, REQ-007, REQ-020, REQ-025, REQ-026, NFR-004, NFR-013, NFR-014, PSC-005, PSC-006, PSC-016, PSC-021, PSC-022
- 对应 PRD 验收：AC-018, AC-022, AC-023
- Given 阶段 2 已确认要解决的结果与范围
- When 用户选择调查真实系统、数据或接口
- Then 平台说明调查目的、最小权限、动作政策、升级路径和所选能力，只在授权范围内执行并展示真实观察与缺口

### AC-F007-002 · 现场事实和三类治理结论可追溯且由人工决定

- 来源：REQ-003, REQ-021, REQ-028, NFR-002, NFR-011, NFR-012, PSC-003, PSC-017, PSC-023
- 对应 PRD 验收：AC-003, AC-018, AC-025
- Given 系统地图、数据清单、权限和治理材料已形成候选版本
- When 安全、隐私和法务责任人分别评审并由 FDE 提交阶段决定
- Then 每项事实回指证据、三类结论互不替代、未知项保持待验证，只有 FDE 决定改变阶段

## 开放问题

- 首轮只对 Data Context Manifest 使用上游渐进校验；Data Readiness Assessment 和治理记录按真实模板能力展示，不伪造机器通过状态。
