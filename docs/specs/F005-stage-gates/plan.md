# F005 · 阶段交付门实施计划

## 现有上下文与复用

- `fde-stage` 已以 WorkspaceId 持久化当前阶段和 revision，并已有六个固定人工推进路由。
- F004 提供三个需求调研固定产物；F018 提供项目 PRD 等五个方案设计固定文档，F013 提供项目级架构与确认状态；F020 提供三份研发收口产物；F006 提供验证合同、证据和三份验证产物；F011 提供项目进度详情。

## 影响范围

| 模块 | 计划变化 | 对应 AC |
|---|---|---|
| `packages/fde/stage` | 保留六个固定门，增加单步人工返回、返回审计和待重新确认上界 | 001～005 |
| `packages/client/ui-fde-project` | 当前阶段产出区域的二次确认、返回原因/二次确认、重新确认状态和即时刷新 | 001～005 |
| 文档/测试 | 当前阶段门合同与并发/重复请求验证 | 全部 |

## 实现方案

扩展现有 `fde_stage` 记录，不新增通用工作流引擎。推进时 Client 只发送 WorkspaceId 和页面看到的 `expectedRevision`；返回时再发送非空原因。Host 自己解析 Workspace，推进按固定路由重新检查当前阶段合同，返回则根据当前状态计算唯一上一阶段并与推进共用 Workspace 串行写入。记录追加有界返回历史和待重新确认上界；入口不暴露给 Agent Tool Registry。

## 实施顺序

1. 增加状态层的单步 CAS 推进与测试。
2. 增加同源人工确认路由和真实文件前置检查。
3. 在项目进度阶段产出区域接入二次确认并刷新状态。
4. 验证缺失、冲突、重复和成功路径。
5. 维护 `solution → development` 固定路由，复核五份文档与已确认架构，并复用 Client 阶段变化通知。
6. 增加 `validation → pilot` 固定路由，复核当前方案定义摘要的 FDE 方案确认、验证合同、必需指标证据、关键失败、WARN 接受理由和三份固定产物。
7. 增加单步返回状态、同源人工路由和审计测试；不接受目标阶段，不触碰项目文件。
8. 在项目进度接入返回原因、二次确认、“重新打开项目”、最新返回记录与待重新确认状态。

## 依赖与风险

| 依赖/风险 | 影响 | 应对 | 验证时机 |
|---|---|---|---|
| 多个页面同时提交旧 revision | 可能重复推进 | 状态层按 Workspace 串行并使用 expectedRevision 比较 | 状态单元测试 |
| Client 传入任意目标阶段 | 可能越过交付门 | 路由不接受目标阶段，只提供固定单步动作 | HTTP 路由测试 |
| 文件或架构在页面加载后发生变化 | 页面状态与提交时不一致 | Host 提交时重新读取固定产物与当前架构状态 | 缺失产物/未确认架构路由测试 |
| 验证结果引用旧候选版本或证据被移除 | 页面看似通过但提交事实已变化 | Host 提交时重新解析合同与证据，不接受 Client 汇总值 | 验证门缺失/失败/成功路由测试 |
| 旧页面或重复返回请求 | 多次返回或覆盖新阶段 | 返回与推进共用 Workspace 串行写入并校验 expected revision | 状态并发/冲突测试 |
| 返回被误解为删除后续工作 | 用户不敢补充早期工作 | 页面明确“保留全部产物”，状态层只更新 `fde_stage` 记录 | 状态和组件测试 |

## 回退策略

移除返回路由和按钮即可恢复仅向前推进；已有返回历史和项目产物不删除。不要通过清空阶段表或删除文件回退本功能。
