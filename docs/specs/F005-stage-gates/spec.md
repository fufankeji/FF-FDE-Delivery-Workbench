# F005 · 阶段交付门规格

## 目标与可观察结果

当前实现六个连续人工交付门，按需求调研、方案设计、项目开发、验证评估、部署试运行和验收移交的固定合同逐步推进至 `completed`。满足固定前置条件只允许 FDE 发起二次确认；Host 仍以当前 revision 原子推进一步。FDE 也可在项目进度填写原因并二次确认后返回唯一上一阶段；返回保留全部产物并使受影响后续阶段待重新确认。Agent、Skill、文件写入、架构生成、评估运行和页面浏览都不能推进或返回阶段。

## 来源与范围

- 来源需求：REQ-001, REQ-011, REQ-012, REQ-018, REQ-023, REQ-026, NFR-001, NFR-003, NFR-004, NFR-005, NFR-008
- 来源总规格：PSC-002, PSC-006, PSC-007, PSC-011, PSC-018, PSC-020, PSC-026, PSC-027, PSC-028, PSC-030
- 对应 PRD 验收：AC-001, AC-010, AC-022, AC-023, AC-025
- 当前切片包含：六个阶段门的固定合同检查；FDE 二次确认；revision 冲突保护；固定单步推进；填写原因后的单步人工返回；`completed → handoff` 重新打开；有界返回历史；受影响后续阶段待重新确认；项目进度即时刷新。
- 当前切片不包含：Agent 自动返回、一次跨越多个阶段、浏览器指定任意目标阶段、自动判断文档正文质量或通用可选附件规则引擎。

## 功能行为

1. Agent 不注册任何阶段推进 Tool；同源 HTTP 入口只由明确的浏览器人工动作调用。
2. 首次点击显示确认说明；只有再次点击“确认并进入方案设计”才提交。
3. Host 按固定路由重新检查当前阶段对应的真实产物；方案设计额外检查项目级架构 `confirmed`，验证评估额外检查当前方案定义摘要的 FDE 方案确认、结构化合同、每个必需指标的合格证据或完整 FDE 人工接受，以及关键问题；所有路由都校验当前阶段和 revision，任一失败不写入部分状态。
4. 成功后 revision 加一并只进入固定下一阶段，项目进度与当前项目页签使用同一新状态。
5. 同一旧 revision 的重复请求返回冲突或当前状态，不得一次跨越多个阶段。
6. 返回入口只接受 WorkspaceId、`expectedRevision` 和非空原因；Host 根据当前状态计算唯一上一阶段。需求调研没有返回动作，`completed` 使用“重新打开项目”并只回到验收移交。
7. 返回只写入阶段记录：保留会话、文档、源码、报告、交付物和旧通过历史，追加有界 from/to/原因/时间审计，并把返回点之后至原阶段标记为待重新确认。重新前进继续执行原阶段门，不因旧产物存在自动恢复通过。

## 异常与恢复

| 情况 | 用户可见状态 | 系统行为 | 恢复/重试 |
|---|---|---|---|
| 提交前文件被移除 | 显示缺失产物 | 不写入阶段记录 | 补齐文件后刷新重试 |
| revision 已变化 | 显示阶段状态已更新 | 拒绝旧请求，不重复推进 | 刷新项目详情 |
| 当前阶段不匹配当前固定路由 | 显示当前真实阶段 | 不接受任意目标阶段 | 按当前阶段继续工作 |
| 需求调研尝试返回或返回原因为空 | 显示不能返回/需要填写原因 | 不写入阶段记录 | 继续需求调研或填写有效原因后重试 |
| 架构不存在或未确认 | 显示真实架构状态 | 不写入阶段记录 | 在系统架构中生成、审阅并确认 |
| Host 写入失败 | 显示真实错误 | 不发布成功状态 | 保留现场后原位重试 |

## 验收标准

### AC-F005-001 · 缺少产物不能进入方案设计

- 来源：REQ-012, NFR-001, PSC-002, PSC-007
- 对应 PRD 验收：AC-010
- Given 当前阶段为需求调研且至少一份标准产物缺失
- When FDE 查看阶段产出或尝试完成阶段
- Then 页面列出缺失项且 Host 拒绝推进，当前阶段和 revision 不变

### AC-F005-002 · 只有 FDE 明确确认才推进一次

- 来源：REQ-001, REQ-011, REQ-012, NFR-003, NFR-004, NFR-005, NFR-008, PSC-002, PSC-006, PSC-011, PSC-018, PSC-026, PSC-028
- 对应 PRD 验收：AC-001, AC-010
- Given 三份标准产物齐备且页面持有当前 revision
- When FDE 完成二次确认
- Then Host 原子推进到方案设计并增加 revision；Agent 完成回复、写文件或重复旧请求都不能再次推进

### AC-F005-003 · 方案设计必须有固定产物和已确认架构

- 来源：REQ-012, REQ-018, REQ-023, NFR-001, NFR-003, NFR-004, NFR-005, NFR-008, PSC-002, PSC-006, PSC-007, PSC-011, PSC-020, PSC-027
- 对应 PRD 验收：AC-010, AC-022
- Given 当前阶段为方案设计，可能存在部分固定文档或候选架构
- When FDE 尝试完成方案设计
- Then 缺少任一固定文档或架构未确认时 Host 拒绝推进并列出真实缺口；只有五份文档存在、架构已确认、当前 revision 一致且 FDE 二次确认时，Host 才原子推进一次到项目开发

### AC-F005-004 · 验证评估必须有当前候选版本的完整证据

- 来源：REQ-003, REQ-004, REQ-012, REQ-020, REQ-026, NFR-001, NFR-003, NFR-004, NFR-005, NFR-008, PSC-002, PSC-007, PSC-009, PSC-011, PSC-022, PSC-030
- 对应 PRD 验收：AC-003, AC-004, AC-010, AC-019, AC-025
- Given 当前阶段为验证评估，可能存在部分验证合同、结果、证据或固定产物
- When FDE 尝试完成验证评估
- Then 评估方案未由 FDE 确认、确认因方案定义或来源文件内容变化失效，或缺少候选版本、环境、任一必需指标的合格证据/完整 FDE 人工接受或固定产物，存在未处理关键问题时 Host 拒绝推进并列出真实缺口；只有全部门槛成立、当前 revision 一致且 FDE 二次确认时，Host 才原子推进一次到部署试运行；人工接受不能把原 NOT_RUN/FAIL 显示为 PASS

### AC-F005-005 · FDE 单步返回且不删除任何交付事实

- 来源：REQ-012, NFR-001, NFR-003, NFR-005, NFR-008, PSC-002, PSC-007, PSC-011, PSC-018
- 对应 PRD 验收：AC-003, AC-010
- Given 项目当前位于方案设计或更晚阶段，页面持有当前 revision
- When FDE 选择返回上一阶段、填写非空原因并完成二次确认
- Then Host 只返回唯一上一阶段并增加 revision，记录 from/to/原因/时间；所有会话、文件、代码、报告和交付物保持原位，受影响后续阶段显示待重新确认；旧 revision、空原因、需求调研返回或任意目标阶段请求均被拒绝，Agent 没有同等动作

## 开放问题

- 无。本切片只增加项目级单步人工返回，不建立任意跳转或自动回滚工作流。
