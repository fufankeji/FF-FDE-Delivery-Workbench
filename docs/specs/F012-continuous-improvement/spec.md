# F012 · 阶段 8：持续改进与能力沉淀规格

## 目标与可观察结果

FDE 将生产结果、事故、用户反馈、成本、漂移和现场差异转成有证据的改进候选，经过影响分析、重新测试、治理审查、人工批准和受控发布后再进入生产；经验证的现场经验可以沉淀为有适用边界、版本和证据的复用能力，而不是把一次客户特例直接产品化。

## 来源与范围

- 来源需求：REQ-003, REQ-006, REQ-007, REQ-024, REQ-025, REQ-026, REQ-028, NFR-002, NFR-004, NFR-011, NFR-012, NFR-013, NFR-014
- 来源总规格：PSC-003, PSC-005, PSC-006, PSC-020, PSC-021, PSC-022, PSC-023, PSC-024
- 本 Feature 包含：生产复盘、问题与机会归因、改进候选、影响分析、回归案例、复测、审批、受控发布、回滚和现场能力沉淀。
- 本 Feature 不包含：自动在生产自我修改、未经客户授权跨项目复用数据、把所有反馈变成需求或未经验证发布。

## 功能行为

### 主流程

1. 从生产服务读取有来源的业务结果、技术指标、事故、成本、用户反馈和变更记录。
2. 建立 Field Learning，区分一次性异常、配置问题、产品缺陷、新需求和可复用模式。
3. 形成改进候选、影响范围、责任人、预期结果、风险、回归案例和回滚方式。
4. 按候选类型返回阶段 1～7 的相应工作，执行必要实现、模拟、Eval、UAT、治理和发布门禁。
5. 只有重新测试、审查和有权批准完成后，才能在限定范围受控发布并观察结果。
6. 对可复用学习记录适用条件、禁止复用内容、证据强度和版本；由 FDE 决定标准化、延期、拒绝或退役。

### 业务规则与边界

- 生产反馈先是候选，不因频率、Agent 判断或客户一句话自动进入已批准需求。
- 改进不得在后台自动修改生产；所有写动作继续受 ToolPolicy、阶段门和人工批准约束。
- 跨项目复用只能复用方法、Schema、匿名模式或明确授权资产，不得带出客户数据、凭据和专有事实。

## 异常与恢复

| 情况 | 用户可见状态 | 系统行为 | 恢复/重试 |
|---|---|---|---|
| 信号与业务影响无法关联 | 学习待验证 | 不创建确定结论 | 补观测或现场调查 |
| 复测失败 | 候选未通过 | 保留失败和原生产版本 | 修订、延期或拒绝 |
| 发布后指标恶化 | 回滚触发 | 执行批准回滚并恢复旧版 | 新建事故与学习项重新分析 |

## 验收标准

### AC-F012-001 · 生产信号转成可理解、可路由的改进工作

- 来源：REQ-006, REQ-007, REQ-024, REQ-025, REQ-026, NFR-004, NFR-013, NFR-014, PSC-005, PSC-006, PSC-020, PSC-021, PSC-022
- 对应 PRD 验收：AC-021, AC-022, AC-023
- Given 项目已有生产结果、事故、反馈或成本信号
- When 用户调查并选择一项改进候选
- Then 平台说明证据、影响和处理选项，按需路由到相应方法、工程能力与阶段，并持续展示复测、审查和发布进度

### AC-F012-002 · 改进和复用必须经复测、批准并保留边界

- 来源：REQ-003, REQ-028, NFR-002, NFR-011, NFR-012, PSC-003, PSC-020, PSC-023, PSC-024
- 对应 PRD 验收：AC-003, AC-021, AC-025
- Given 改进候选已完成实现、影响分析和回归验证
- When 有权人员审批并由 FDE 决定受控发布或沉淀复用
- Then 候选回指生产证据、复测、审查、批准、范围和回滚；未完成任一门禁不得发布，复用资产保留适用与禁止边界
