# FF - FDE 交付工作台 V2 产品总规格

## 1. 文档职责与来源

- 产品需求事实源：`docs/PRD.md`。
- V1 使用与实现事实：`PRODUCT_GUIDE.md`、现有源码、隔离工作区和会话状态。
- 本文职责：定义 V2 所有 Feature 共同遵守的产品对象、生命周期、权限边界、证据语义和兼容规则。
- 本文不负责：一次性定义八个阶段的全部产物、选择技术架构、拆开发任务或改写 V1 实现。

V2 使用滚动确认：本文件冻结全部 Feature 共同遵守的合同；阶段细节进入 Feature 规格后再按计划逐个实现、真实调试并同步文档。未进入当前 Feature 的后续实现不因本文确认而自动获得开发授权。

## 3. 产品对象与职责

| 对象 | 用户可感知含义 | 负责 | 不负责 | 相关 PSC |
|---|---|---|---|---|
| 项目 | 一次独立企业交付的完整空间 | 隔离工作目录、会话、阶段、证据和决定 | 客户关系管理、跨项目资产市场 | PSC-001, PSC-008 |
| 项目阶段 | 当前主要需要回答的一类业务问题 | 组织输入、候选产物、证据、缺口和评审 | 自动证明项目成功 | PSC-003, PSC-004 |
| 项目事实 | 已保存且可回指来源的资料或状态 | 作为两个工作面的共同数据源 | 用自然语言猜测填补未知值 | PSC-002, PSC-009 |
| 输入 | 当前判断所依据的客户或项目材料 | 保存原件、来源、版本和授权范围 | 自动代表 Agent 已读取或客户已确认 | PSC-005 |
| 候选产物 | Agent、Skill 或 FDE 形成的阶段材料 | 支持审阅、修改和关联证据 | 仅凭存在触发推进 | PSC-005, PSC-006 |
| 证据 | 支持或反驳某项判断的可观察事实 | 关联来源、条件、结果和适用边界 | 用总体分数掩盖阻断问题 | PSC-005, PSC-009 |
| 未决项 | 尚缺事实、确认、验证或责任人的事项 | 显示影响与后续动作 | 被 0 值或“完成”隐藏 | PSC-005, PSC-009 |
| 阶段决定 | FDE 对当前证据作出的专业结论 | 记录类型、理由、决定人、时间和影响 | 由 Agent 或文件数量代签 | PSC-004 |
| 方法 Skill | 把现场问题转成业务工作、Artifact 和决策条件的方法入口 | 定义为什么做、需要哪些证据、形成什么决定 | 直接执行代码、授予权限或证明客户事实 | PSC-006, PSC-022 |
| 工程 Skill | 完成代码、数据、测试、发布和运维动作的工程规范 | 在已确认业务边界内完成具体交付工作 | 私自改变业务结果、范围和阶段 | PSC-006, PSC-022 |
| 工程能力 | 文件、代码、终端、运行、架构、观察与评估工具 | 服务当前业务判断和交付动作 | 固定绑定在单一“开发阶段” | PSC-007 |
| 智能执行会话 | FDE 用自然语言驱动当前项目工作的连续交互 | 管理请求、上下文、可用能力、工具动作、结果和解释 | 自动替代阶段评审与客户决定 | PSC-011 |
| 工具能力 | Agent 可调用的一项受控平台操作 | 声明用途、输入、结果、权限、风险、确认和验证方式 | 超越当前用户权限 | PSC-012 |
| 上下文项 | 当前会话允许模型读取的一项信息来源 | 标明来源、所属项目、激活状态和移除方式 | 因项目中存在而自动加载 | PSC-013 |
| 执行步骤 | 闭环中的一次动作及其真实反馈 | 保存动作、观察、验证结果和下一步判断 | 用解释文本代替工具结果 | PSC-014 |
| 生产就绪责任 | Agent 从业务定义到持续改进必须承担的一项生产责任 | 聚合当前状态、证据、批准和缺口 | 取代八阶段或自动推进项目 | PSC-015～PSC-020 |
| 全部项目视图 | FDE 判断今天先介入哪个项目的组合入口 | 展示当前阶段、下一动作、待人工决定、风险、停滞和交付时间 | 用项目总数或完成率代替行动优先级 | PSC-002, PSC-021 |
| 单项目首页 | FDE 重新进入项目时恢复现场认知的项目记录页 | 展示当前状态、业务原因、关键人员、阶段路径、风险、近期证据与下一动作 | 复制一套独立项目状态或替代阶段执行 | PSC-002, PSC-021 |
| 当前阶段工作台 | 用户理解和推进当前工作的主操作面 | 展示阶段问题、上下文、推荐行动、实时过程、Artifact、缺口和决定 | 默认暴露全部技术日志或另建一套进度 | PSC-021 |
| 真实交付环境 | 对当前工作项执行代码、文件、终端、浏览器和工具操作的工程空间 | 执行真实动作并把结果写回项目事实、Artifact 和证据 | 自行维护阶段状态或脱离工作项执行 | PSC-002, PSC-007, PSC-021 |
| Skill 路由结果 | 平台对本次工作适用方法、工程能力和工具的有依据选择 | 记录业务工作、方法 Skill、工程 Skill、工具、加载范围和预计产物 | 把全部 Skill 描述注入每次请求 | PSC-022 |
| Artifact 引用 | 一项持久化结果在后续工作的稳定输入身份 | 保存类型、来源、版本、结构状态、证据状态、所属项目和消费关系 | 把 Schema 通过或一次聊天回答当作真实结论 | PSC-023 |

### 3.1 项目身份

- [PSC-001] 每个项目必须拥有稳定且唯一的项目身份。目录名、展示名称或会话标题变化不得造成项目串线。
- [PSC-001] 所有文件、会话、阶段状态、证据和决定必须能回指所属项目。
- [PSC-001] 未明确属于当前项目的数据不得进入当前项目视图或统计。

### 3.2 四层产品形态

工作台把同一组项目事实投影为四层页面。四层不是四套数据，也不是四个互相割裂的产品：

| 层级 | 用户进入时要回答的问题 | 默认重点 | 进入下一层的方式 |
|---|---|---|---|
| 全部项目 | 今天哪个项目最需要我介入 | 待人工决定、下一动作、当前阶段、风险、停滞与交付时间 | 选择一个真实项目 |
| 单项目首页 | 这个项目现在为什么在这里、接下来做什么 | 当前状态、业务缘由、八阶段路径、关键人员、风险、近期证据／决定／交付和下一动作 | 选择当前工作或阶段 |
| 当前阶段工作台 | 这一阶段正在回答什么问题、还缺什么 | 阶段问题、推荐行动、执行过程、中心业务视图、Artifact、证据、缺口和人工决定 | 打开一项真实工作 |
| 真实交付环境 | 具体动作如何在真实项目中完成 | 对话、文件、代码、Diff、终端、浏览器、工具和轨迹 | 执行结果写回当前工作项 |

- [PSC-002] 全部项目视图优先呈现“需要谁做什么”，阶段分布和项目数量只能作为辅助判断，不能成为首页唯一内容。
- [PSC-002] 单项目首页是可持续恢复现场认知的项目记录，至少呈现当前状态、业务缘由、关键人员、风险、项目记录、成功标准和现场条件；未知字段保持未知，不用演示数据补齐。
- [PSC-002] 四层页面读取同一项目事实、Artifact、证据、决定和执行记录，并由确定性规则生成投影，不通过页面本地状态或模型临时总结维护另一套结论。
- [PSC-002] 报告、时间线、任务、关系图和阶段视图都是同一事实源的不同投影；任何写入必须回到稳定对象和来源记录。
- [PSC-002] 项目中心近期记录的描述、时间与打开目标必须属于同一事实：会话更新打开对应普通会话，阶段或项目登记更新打开所属项目详情，不创建会话或推进阶段。近期记录是现有记录的最近更新摘要，不冒充完整操作日志。
- [PSC-002] 企业名称与预计交付周期随项目持久保存，创建表单、项目中心、时间轴与侧栏读取同一份数据；浏览器旧值只在项目尚未保存时导入，不能覆盖已有项目记录。读取或保存失败可重试，不冒充已登记。
- [PSC-009] 交付周期计数只包含日期有效的已登记项目；预览优先显示未完成项目，已完成项目仍可在完整时间轴查看。查看周期与返回项目集合不改变项目进度。
- [PSC-002] 真实交付环境从当前工作项进入，执行结果必须回写对应 Artifact、证据、风险、未决项或决定引用，不能只留在聊天或终端历史中。

### 3.3 智能执行原理

一次自然语言请求必须形成以下闭环：

```text
理解意图与获准上下文
→ 确定适用的 Skill、工具、数据和平台操作
→ 在当前项目及用户权限范围内执行
→ 持久化文件、代码、运行结果和证据
→ 返回上下文相关的解释与文档说明
```

- [PSC-011] 上下文至少受当前项目、当前阶段、当前会话和用户明确授权约束，不能因为模型“可能有帮助”而自动扩展到其他工作区或资料。
- [PSC-011] 系统可以自动选择完成请求所需的能力，但用户必须能够查看和收窄可用模型、工具和数据。
- [PSC-011] 返回结果必须区分已执行事实、生成内容、失败、建议和仍需人工确认的事项。
- [PSC-011] 智能执行循环负责完成当前任务，不具有改变项目责任阶段或代表客户作出结论的权限。

### 3.4 可自定义工具

- [PSC-012] 当前会话可用工具必须是当前用户有权执行操作的子集；Agent 不得因为工具已经安装就自动获得使用权。
- [PSC-012] 用户必须能够查看工具用途、输入输出、所需权限、是否改变状态、风险级别、确认要求和验证方式。
- [PSC-012] 用户可以在会话内启用、停用或收窄工具；Agent 自动调整能力时不得突破用户设定的上限。
- [PSC-012] 会话轨迹必须记录所有已调用工具及其触发请求、执行身份、输入范围、结果、错误和验证证据。

### 3.5 上下文管理

上下文按以下层次组织：

| 层次 | 默认内容 | 扩展方式 | 是否可移除 |
|---|---|---|---|
| 平台基础上下文 | 工作台规则、工具说明和安全边界 | 平台版本更新 | 否 |
| 项目基础上下文 | 当前项目身份、阶段、项目约束和适用 `AGENTS.md` | 项目或阶段变化 | 否，但必须可见 |
| 任务上下文 | 用户本次选择的文件夹、数据集、文档和资料 | 用户添加或明确授权 Agent 添加 | 是 |
| 运行反馈上下文 | 当前闭环产生的工具结果、错误和验证证据 | 工具执行 | 可由系统压缩，但必须保留证据引用 |

- [PSC-013] 新会话只激活平台与项目的最小基础上下文，不默认读取项目中的全部文件和历史会话。
- [PSC-013] 用户必须能看到当前生效上下文的来源、范围与状态，并能移除任一任务上下文项。
- [PSC-013] “项目资料已保存”和“资料已加入当前会话”是两个独立状态，任何一方变化不得隐式改变另一方。
- [PSC-013] 不属于当前项目或未被当前会话授权的内容不得进入模型上下文。
- [PSC-013, PSC-023] 条件本体路线的 Agent 与工作台共享项目来源绑定、定义草稿、构建和验证记录；Agent 不得直接改写运行状态、候选审核、Schema 发布或 FDE 决定。后续开发按明确的问题或实体只读消费当前有效图谱，保留版本和来源，不使既有切片或决定失效。运行环境不可用、来源过期或验证版本不匹配时明确拒绝，不以历史成功代替本次可用性。

### 3.6 当前阶段工作台

当前阶段工作台是项目交付的默认主操作面，任何活动阶段都必须提供相同的信息层次：

| 区域 | 默认回答的问题 | 技术详情 |
|---|---|---|
| 阶段目标 | 为什么现在做、做到什么程度可以评审 | 引用阶段合同和生产责任 |
| 输入与上下文 | 当前使用了哪些资料、系统和前序 Artifact | 展开来源、版本、权限和激活状态 |
| 当前工作 | Agent 正在做什么、为什么选择这项工作 | 展开 Skill、工具、命令和原始结果 |
| Artifact 与证据 | 已经形成什么、可信度如何、哪些会被后续使用 | 展开文件、版本、引用和验证 |
| 缺口与决定 | 还缺什么、需要谁决定、下一步是什么 | 展开风险、阻塞和决定记录 |

- [PSC-021] 八个阶段共享相同页面骨架，但中心业务视图必须随阶段问题变化，不能把所有阶段统一做成文件清单、通用看板或聊天记录。
- [PSC-021] 阶段中心视图必须从当前项目事实确定性生成，并明确展示其读取的数据范围、未知项和最后更新时间。
- [PSC-021] 用户从中心视图打开工作项后进入真实交付环境；返回阶段工作台时应看到执行结果已关联到相应 Artifact、证据或缺口。
- [PSC-021] API、系统架构、评估、观测、终端和浏览器等能力只在当前阶段与工作需要时出现，不作为全局常驻页签增加理解成本。
- [PSC-021] 空闲、执行、等待、失败和完成状态都必须说明当前业务含义，不能只显示转圈、空白页或原始日志。
- [PSC-021] 默认过程使用“计划—动作—观察—结果”的业务化描述；工具调用、命令、Token、文件差异和日志在用户展开后显示。
- [PSC-021] 每个阶段只突出一个当前主要行动，同时允许用户添加上下文、调整要求、停止执行或进入人工决定。
- [PSC-021] 所有阶段的目标、步骤、状态和按钮必须从真实业务现场出发，直接说明“客户现在怎样工作、哪里出了问题、谁负责、谁判断结果、接下来要做什么决定”。默认界面不得用 Skill、Artifact、工作流资格、可验证、高价值或“系统智能分析”等内部方法词和抽象判断替代具体业务动作；这些术语只可在执行详情或来源说明中按需展示。
- [PSC-021] 阶段目标使用一句普通业务人员可以直接复述的话，先说明本阶段需要弄清的事实，再说明最终要做的决定。阶段路径使用动词开头的短名称，并分别标明当前、已完成和等待前置事实，不能重复目标句或堆叠同义状态。
- [PSC-021] 左侧八阶段路径同时承担阶段导航，但三类阶段必须使用不同产品语义：当前阶段展示可执行工作；已完成阶段复盘当时真实使用的输入依据、形成的记录与产物、人工阶段结论；未开始阶段只明确提示“本阶段尚未开始”、当前项目仍处于哪个阶段、开始本阶段必须先满足什么条件，以及开始后预计形成哪些记录。查看状态必须与项目当前阶段分别标记，并提供“返回当前阶段”。
- [PSC-021] 查看其他阶段只改变当前页面的只读投影，不得推进、退回或确认项目阶段。后续阶段在成为当前阶段前不得执行工作、提交评审或生成正式阶段产物；历史阶段如需重做，必须走带原因的正式返回流程。
- [PSC-021] 历史阶段只能展示当前项目中真实存在的资料、阶段产物、工作记录与可追溯人工结论；缺少独立输入清单、完成时间或决定记录时必须明确标注“未登记”，不得用阶段模板、计划工作或推算文案冒充历史事实。未开始阶段不得展示“会依次做什么”等仿佛已经启动的过程看板。
- [PSC-021] 项目管理与进度负责跨项目判断，当前阶段工作台负责一项真实工作的推进；两者继续读取同一项目事实。

### 3.7 Skill 路由与 Artifact 组合

- [PSC-022] 用户可以只描述目标或选择推荐行动；系统依据项目类型、当前阶段、任务意图、已有 Artifact、权限和工具可用性选择能力。
- [PSC-022] 路由按“方法 Skill → 工程 Skill → DeepSeek Harness 工具”分层：方法 Skill 确定业务工作、Artifact 与决策门，工程 Skill 完成具体交付动作，工具负责真实执行与审计。
- [PSC-022] `davidahmann/fde-guide` 的 11 个 Skills 作为 AI-FDE 方法层候选；`rpraharaj/forward-deployed-engineer` 的 43 个 Skills 作为工程执行层候选。两者都必须逐项审查、固定来源版本并按需接入，不能批量启用。
- [PSC-022] 路由把能力分为核心、推荐和条件性三类。核心能力满足当前业务决策最低工作，推荐能力补强常见场景，条件性能力只在检测到对应系统、风险或交付类型时加载。
- [PSC-022] Skill 名称可以在执行详情中显示，但默认主界面使用用户能够理解的工作名称、选用原因和预计结果。
- [PSC-022] 没有适用能力、前置 Artifact 或所需权限时，系统必须显示缺口并请求 FDE 调整，不得盲目调用相近 Skill。
- [PSC-023] 每个会影响后续判断的 Skill 必须生成命名 Artifact；一次解释性回答不能代替持久化结果。
- [PSC-023] Artifact 同时记录结构状态和证据状态。结构状态说明是否缺失、无效、通过 starter 校验或通过 complete 校验；证据状态说明结论是“已确认”“推断”还是“待验证”。结构通过永远不能推断事实真实、客户接受或生产就绪。
- [PSC-023] 通用性整改：空白或越出当前项目的产物不算有效记录；结果证据必须绑定内容摘要，改变证据后旧结果失效。明确标注为联调、示例或模拟的数据保留可读性与历史，但不得用于证明真实交付通过。文件作者的结果声明、实际执行和 FDE 人工决定仍是三个独立事实，读取器不能证明自然语言结论真实。
- [PSC-023] starter 与 complete 是同一 Artifact 的渐进成熟状态，不允许维护两套并行的“简版／完整版”对象。只有源方法明确支持渐进校验的类型才能显示 starter 校验通过。
- [PSC-023] 首批可采用 `fde-guide` 的 Workflow Charter、Engagement Reframe 和 Data Context Manifest 渐进校验；其他 JSON Schema、Markdown 模板和控制项必须按其真实验证能力呈现，不能伪装为已通过机器校验。
- [PSC-023] Artifact 中的事实必须引用文件、命令、观察、人工决定或外部系统结果，或标为“已确认”“推断”“待验证”之一。
- [PSC-023] 后续 Skill 通过稳定 Artifact 引用读取前序结果，不能在每次会话重新推导同一项目事实。
- [PSC-023] 外部 Schema、模板和 Skill 的路径、正文与名称可以通过 Adapter 适配本产品，但不得丢失上游来源版本、许可证、类型约束、禁止行为、证据状态和组合关系。

### 3.8 八阶段实施完成合同

八个阶段可以使用不同的业务对象与中心视图，但必须用同一套可验证合同判断“本阶段是否已经做到可由 FDE 评审”：

| 合同项 | 必须满足 | 不得替代 |
|---|---|---|
| 当前阶段 | 项目持久化记录明确保存 V2 阶段 ID、修订号和更新时间 | 由页面名称、会话内容或文件数量推测阶段 |
| 阶段步骤 | 当前阶段定义四个可理解的业务步骤，并只突出一个当前动作 | 用 Skill 名称、工具名或抽象方法词作为步骤 |
| 工作状态 | 每个步骤区分等待、进行中、完成和阻塞，并能回指真实文件或执行结果 | Agent 自述“已经完成” |
| 阶段产物 | 必需产物有固定路径、用途、结构状态、证据状态和预览入口 | 文件存在等同于事实已确认 |
| 可评审条件 | 必需产物存在且结构可读，必需工作已完成，关键阻塞已处理 | 页面加载成功、会话结束或构建通过 |
| 人工决定 | 当前项目内先进入评审模式，再由 FDE 二次确认 Go、Revise、Narrow 或 Stop | Agent 或系统自动推进 |
| 状态同步 | Agent 停止、文件上传、产物写入、人工决定后重新读取同一项目事实 | 依赖刷新页面或页面本地计数 |
| 返回影响 | 返回更早阶段时保留历史，并把受影响的后续阶段标为需要重新评审 | 删除文件或继续显示旧结论有效 |
| 失败与恢复 | 缺失、无效、读取失败和未运行各自显示原义及恢复动作 | 折算成 0、空白或已完成 |
| 手动验证 | 每阶段提供一组可直接复制的中文提示词及最窄自动化测试 | 只验证静态 UI 或 TypeScript 构建 |

- [PSC-024] V2 项目使用真正的八阶段状态机；旧六阶段状态只能作为兼容投影，不能继续充当 V2 的唯一状态源。
- [PSC-024] 兼容投影必须确定、可解释且单向：V2 当前阶段是权威事实，旧入口只读取其对应的粗粒度阶段；不存在静默维护两套可独立变化的阶段记录。
- [PSC-024] 打开旧项目不自动迁移生命周期。六阶段写入口只接受旧项目，八阶段写入口只接受 V2 项目；拒绝版本交叉时不得写入阶段或修订号。
- [PSC-024] Agent 完成一次运行后，Host 必须重新扫描当前阶段的状态文件与固定产物路径，再刷新项目工作台、产物栏和项目中心；扫描失败保留上一次已知事实并显示错误。
- [PSC-024] 每阶段的状态文件保存在 `.fde/stages/<stage-id>.json`，只记录工作项、阻塞、建议和证据引用；文件存在性、结构有效性和可预览性由 Host 按项目目录重新核验。
- [PSC-024] 每阶段必须提供与当前项目绑定的评审页，FDE 能逐项查看产物、未确认事实和关键阻塞后再决定；评审成功后才迁移阶段，保存失败时不改变当前阶段。

### 3.9 后三阶段交付证据 [PSC-025]

- 项目只有一条交付生命周期；侧栏、正文、阶段头部均读取同一当前阶段及已完成轮数。回看只改变浏览位置，推进必须调用现有阶段接口。删除此前误加的演示资料开关、独立快照、模拟进度轴和对应提示。
- 既有用户授权的数据联调记录保留阶段文件、来源、操作依据和历史进度，不新增产品模式，不伪装真实部署或客户签收。真实交付评审不使用明确的联调／模拟输入证明通过；补充实际证据后仍沿原阶段门推进。第八阶段完成一轮后显示已完成轮数，仍停留本阶段等待新一轮评审。

- 当前阶段保留人工评审与返回；历史和未来阶段展示当前可读取的记录，明确不是历史冻结快照，只读预览不改变生命周期。前端不再使用窄侧边项目记录轴；记录放在对应页签与文件下钻中。
- 阶段 6 使用“概览／接入与准备／运行与问题／试点评审”；阶段 7 使用“生产与采用／验收条件／交付清单／责任与实操”；阶段 8 使用“信号与发现／改进事项／影响与验证／发布与复用”。所有布局允许短视口滚动，输入框不得遮挡末尾按钮。
- 共享版本由版本名和文件摘要清单构成。记录包含稳定 ID、固定类别、业务标题、状态、环境范围、说明、版本、责任人、下一动作、观察时间和文件证据；状态声明与 Host 验证后的有效状态分别保留。证据文件必须是本项目非空文件，版本或摘要变化标记失效；缺失、非法结构、读取失败分别可见。
- 本地／Sandbox／Pilot／生产／前序材料的范围不得互换。运行、业务结果、授权、客户签收、责任实操独立留证，不能由三份报告存在或本地服务运行推导通过。必备评审类别缺失或未通过时不能开放 Go；同版本证据齐备只开放人工决定，不替代签收人。
- 本体是条件能力。采用时显示 Schema 版本、图谱修订、快照或运行时接入方式及来源；普通软件路线不显示强制本体面板。应用运行时查询与第四阶段编制验证分离，不能复用会使纵向切片失效的上下文构建操作作为生产查询。Schema、映射、推理或权限变化需要影响检查；固定 Schema 下的增量事实按获批的数据更新规则处理。
- 普通图谱消费不修改方案状态、切片或 FDE 决定。编制验证查询必须显式选择，重新形成上下文后切片需要重跑。身份键、字段类型、必填、唯一性、关系端点与基数按项目定义执行；有效时间与来源过滤先于图遍历。自由文本规则和权限说明不冒充可执行政策；当前查询按明确的问题或节点选择，不声称自由文本语义检索。
- 本轮完成专用工作台、只读文件投影、Agent 提示词入口和真实资料接入。部署、监控采集、生产查询、签收、变更执行 Adapter 未接通时不提供虚假执行按钮；由 Agent 对话承接实际授权任务。跨客户资产发布不在本轮范围。

## 4. 全局状态与生命周期

### 4.1 生命周期版本

每个项目必须显式记录生命周期版本：

```text
V1：需求调研 → 方案设计 → 项目开发 → 验证评估 → 部署试运行 → 验收移交 → 项目完成

V2：发现高价值问题
  → 定义结果、范围与责任
  → 调查数据、系统、接口、安全与组织
  → 设计方案并完成端到端纵向切片
  → 运行 PoC 与 Eval
  → 完成企业集成、可靠性改造和受控 Pilot
  → 进入生产、推动采用并验收交接
  → 持续改进并沉淀可复用能力
```

- [PSC-003] V2 八阶段是默认工作路径；阶段 Feature 已分别定义输入、工作、Artifact、证据和人工决定，真实项目允许跳过、循环和重新路由。
- [PSC-008] 没有生命周期版本的既有项目按 V1 读取，不得根据当前日期、文件或推测自动改成 V2。
- [PSC-008] V1 项目只有在 FDE 发起、审阅并确认迁移后才可变更为 V2；迁移规则尚未定义。

### 4.2 阶段工作状态

- [PSC-021] 第五阶段名称仍为“运行 PoC 与 Eval”，内部主线为项目开发 → 测试与阶段验收；开发过程中也允许准备测试与局部验证。具体项目的代码和工作流由 DSH 在当前项目空间执行，工作台不新增开发引擎或 IDE。
- [PSC-005] 第五阶段首页读取受测范围与候选版本、项目运行状态、测试指标、执行证据和待解决问题；不增加开发区域或任务看板，不以开发任务清单作为验收门槛，不把文件齐备或运行成功推断为验收完成。
- [PSC-018] 测试针对候选版本的目标系统，而非只评估工作台 Agent。指标必须注明验收依据、方法／阈值、实际结果及证据，保留未运行、运行中、失败、警告和版本过期；当前候选或验证定义变化后旧结果不得用于推进。
- [PSC-007] 第五阶段复用既有系统架构、启动、停止、项目预览、终端和评估优化入口。工作台中的快捷动作与页头使用同一项目运行状态，不维护第二套启动命令或进程状态。
- [PSC-007] 已登记并运行的本地项目由平台统一接入预览，不要求业务项目增加工作台端口白名单。页头和阶段工作台使用同一入口；变更项目地址、停止项目或工作台退出后，旧预览不得继续访问原目标。预览失败不改变项目运行事实，保留直接打开原地址的备选。
- [PSC-019] 预览项目与工作台、其他项目的来源和存储隔离。平台只适配已登记本地运行目标，不接受用户提交任意代理地址；不关闭工作台安全策略、不改写业务源码，不向目标转发工作台凭证。外部网站仍尊重其嵌入限制。
- [PSC-024] 第五阶段只有本轮受测版本明确、必测项目有当前版本的通过证据、固定评审记录可读取且无关键阻塞时才开放人工阶段验收；人工确认进入企业集成与受控 Pilot 不代表生产或客户最终验收。历史阶段仅供查看，未知记录保持缺失。

V2 每个阶段至少区分：

```text
未开始 → 进行中 → 待 FDE 评审 → 已记录决定
                    ↘ 需要补充或修订
```

- [PSC-005] “候选产物存在”最多支持进入“待 FDE 评审”，不得直接成为“已通过”。
- [PSC-009] 加载失败、数据未知或证据缺失必须保持明确状态，不得折算为 0 或完成。

### 4.3 阶段决定

| 决定 | 产品语义 | 允许的后续动作 |
|---|---|---|
| `Go` | 当前证据足以承担下一阶段责任 | 进入下一阶段，并保留本次依据 |
| `Revise` | 方向成立，但方案、实现或证据需修订 | 留在当前阶段或返回受影响阶段 |
| `Narrow` | 价值成立，但原范围或责任过大 | 更新范围后重评当前或更早阶段 |
| `Stop` | 不值得继续或关键条件长期不成立 | 停止推进；只有 FDE 明确重开后才能继续 |

- [PSC-004] 任何决定都必须由 FDE 的显式动作产生。
- [PSC-004] Agent 可以建议决定，但建议必须标为候选，不能写成项目决定。
- [PSC-003] 返回不局限于“上一阶段”。FDE 可以选择实际受影响的更早阶段。
- [PSC-009] 返回或重开不删除历史；受影响的后续阶段必须标为“需要重评”，而不是伪装为仍然有效。

### 4.4 持续改进

- [PSC-003] 第八阶段是持续运行状态，不等同于一次性项目完成页。
- [PSC-003] 生产反馈可以触发回到问题、范围、现场调查、方案、评估或 Pilot；每次循环都形成新的证据和决定记录。

### 4.5 闭环执行状态

```text
等待请求
→ 分析与选择能力
→ 执行动作
→ 观察真实结果
→ 验证或判断
   ├─ 需要继续：回到“执行动作”
   ├─ 已完成：保存结果与证据
   ├─ 受阻：保存失败位置与原因
   └─ 等待 FDE：请求信息、授权或决定
```

- [PSC-014] 每次后续动作都必须基于上一动作的真实结果，不能仅凭预期结果继续。
- [PSC-014] 对代码、函数、数据转换、构建和运行修改，应优先执行适用的预览、测试、CI、构建或健康检查。
- [PSC-014] 用户停止、失败、超时或权限不足时，闭环必须安全结束并保留已有事实，不得无限重试。
- [PSC-014] “已完成”只代表当前请求拥有相应执行与验证证据，不代表项目阶段、客户验收或风险接受已经通过。

### 4.6 Agent 生产就绪与持续改进基线

六项责任是八阶段之上的横向审查视图，不是第二套阶段状态机：

| 责任 | 对应合同 | 主要映射阶段 | 完成语义 |
|---|---|---|---|
| 业务结果、成功标准和初始工作流 | PSC-015 | 阶段 1～2 | 结果、工作流、责任人与停止条件拥有已确认依据 |
| 系统连接、政策、权限和人工升级 | PSC-016 | 阶段 3～4 | 数据与动作边界能够被真实系统和责任人执行 |
| 安全、隐私和法务审查 | PSC-017 | 阶段 3，并作为后续门禁 | 三类独立审查均有结论、条件和有权批准人 |
| 模拟、Eval 和验收测试 | PSC-018 | 阶段 5 | 代表、边界与高风险条件均有真实结果和门禁结论 |
| 受控生产与结果监控 | PSC-019 | 阶段 6～7 | 限定范围内拥有授权、运行、监控、接管和回滚证据 |
| 基于生产证据的受测改进 | PSC-020 | 阶段 8 | 改进回指生产证据，并经复测、审查、批准和受控发布 |

- [PSC-015] 文档摄取、知识库建立或模型能够回答资料问题，只能证明上下文可用，不能自动改变任何生产就绪责任状态。
- [PSC-015] 业务结果、成功标准和初始工作流必须先于方案承诺，并同时记录责任人与停止条件。
- [PSC-016] 系统连接不能只登记 API；必须明确允许读取和执行的动作、最小权限、政策约束以及人工升级触发条件与接收人。
- [PSC-017] 安全、隐私和法务是三个独立审查对象，某一项通过不得推断其余两项通过。
- [PSC-018] 模拟、Eval、UAT 和发布门禁必须关联同一候选版本与适用范围，保留未运行、失败、例外和批准事实。
- [PSC-019] 受控生产必须限定用户、数据、周期和动作权限，并持续记录监控、异常、人工接管、回滚和业务结果。
- [PSC-020] 生产反馈只能先形成改进候选；重新测试、审查和批准完成后，才能在受控范围发布，并保留回滚方式。

## 5. 跨 Feature 不变量与共享行为

- [PSC-004] 没有 FDE 决定，不改变项目责任阶段。
- [PSC-005] 文件存在、Agent 自评、任务勾选、构建成功、服务启动和报告生成都不是阶段通过的充分条件。
- [PSC-005] 原始资料、候选产物、验证证据、客户确认和 FDE 决定必须分别保存和展示。
- [PSC-006] Skill 不得虚构客户签字、企业授权、生产运行、业务采用、责任移交或验证结果。
- [PSC-007] 工程能力由业务任务和前置条件决定；同一能力可在多个阶段复用。
- [PSC-009] 失败必须显示在用户正在操作的工作面中；不得以白屏、静默失败或虚构默认数据代替。
- [PSC-010] 未经用户确认，不得提前冻结后续阶段的文件清单、交互或实现。
- [PSC-011] 任何工具动作都必须能回指触发它的请求、所用上下文、执行身份和结果；解释文本不得冒充未执行的操作证据。
- [PSC-012] 禁用工具必须立即从后续可用能力中移除，但不得删除已经产生的审计记录。
- [PSC-013] 上下文压缩或会话整理不得把未授权资料重新引入，也不得丢失产物与验证证据的引用。
- [PSC-014] Agent 的自我验证只生成工程证据；任何阶段变化继续由 PSC-004 约束。
- [PSC-015] 生产就绪状态不得由资料数量、已摄取文档数或 Agent 自评计算。
- [PSC-016] 缺少政策、最小权限或人工升级路径时，真实系统连接保持未就绪。
- [PSC-017] 缺少任一治理审查时，系统必须显示具体缺口而不是统一显示“安全已通过”。
- [PSC-018] 未运行的模拟、Eval 或 UAT 不得折算为零失败或通过。
- [PSC-019] 生产页面可访问或服务返回成功不等于受控生产责任已经成立。
- [PSC-020] 未经重新测试和批准的生产改进不得进入已发布状态。
- [PSC-021] 用户在任一活动阶段都必须能够回答系统正在做什么、为什么做、得到了什么和需要自己做什么。
- [PSC-022] 能力总量不得直接决定模型上下文大小；只有当前任务必要的 Skill 与参考进入请求。
- [PSC-023] 未持久化且无稳定来源的会话回答不得成为后续阶段的唯一输入。
- [PSC-024] 任一阶段只有在真实状态、必需产物、关键阻塞和 FDE 决定四类事实一致时才能迁移；任一类未知都保持在当前阶段。

| 打开工程能力 | 为当前判断执行真实工作 | 能力入口及前置条件 | 当前项目、阶段、会话和运行状态 | 前置条件不足时回到原工作面说明 | PSC-007, PSC-009 |

## 7. 安全、权限、失败与恢复

- [PSC-001] 所有项目级操作必须在当前项目范围内解析路径与会话，不得扫描或加载用户电脑上的其他工作区。
- [PSC-004] 阶段决定、风险接受、外部部署、生产写入和责任移交必须要求明确的人类动作。
- [PSC-006] Agent 只能读取用户授权的资料；Skill 不得扩大资料授权或动作权限。
- [PSC-011] 智能执行必须沿用用户现有的应用、项目和数据权限，不得使用独立高权限身份绕过控制。
- [PSC-011] 用户对模型、工具和数据的选择构成本次执行上限；系统自动选用能力时只能在该上限内遵循最小必要原则。
- [PSC-011] 改变项目事实、调用外部系统、执行高风险动作或影响阶段责任时，必须取得对应的人类授权。
- [PSC-012] 工具授权必须同时满足用户权限、当前项目作用域和会话工具范围；三者任一不满足即拒绝调用。
- [PSC-013] 拖放、引用或自动建议上下文不得绕过项目隔离、资料授权和敏感数据限制。
- [PSC-014] 闭环重试必须有明确的错误依据和终止条件；不确定副作用是否已发生时先转为等待 FDE，不得盲目重试。
- [PSC-016] 系统或数据接入必须遵守已记录的动作政策、最小权限与人工升级约束。
- [PSC-017] 安全、隐私和法务批准必须来自对应有权责任人，Agent 不得代填结论或批准身份。
- [PSC-019] 未获生产授权时不得把测试、预览或本地运行解释为真实生产运行。
- [PSC-020] 改进发布必须保留原版本和回滚路径；生产证据不足时只能停留在候选状态。
- [PSC-022] Skill 自动路由不能扩大用户权限、项目范围或当前会话工具上限。
- [PSC-023] Artifact 不得写入凭据、越权客户数据或无法追溯来源的生产事实。
- [PSC-009] 状态写入失败时，界面不得先行显示成功。
- [PSC-009] 重试必须复用同一项目和动作身份，避免重复生成决定或阶段历史。
- [PSC-009] 恢复后应从持久化事实重新计算视图，不依赖上一次页面内存状态。

## 8. 兼容、能力与产品语言

- [PSC-008] V1 六阶段页面、数据和历史在 V2 迁移功能确认前继续可读可用。
- [PSC-008] V2 功能必须通过生命周期版本或明确能力探测启用，不得用文件名猜测项目已迁移。
- [PSC-010] 产品文档只维护中文事实源；代码标识、协议字段和行业通用缩写可保留英文。
- [PSC-010] V2 每个切片替换 V1 行为时，必须说明被替换入口、仍保留入口及既有项目影响。

### 9.2 Feature 提取约束

- Feature 必须按用户可观察结果拆分，并同时引用来源需求与 PSC。
- 任一阶段 Feature 开始前，必须先补齐该阶段的输入、候选产物、证据、决定和返回影响。
- 共享项目身份、决定语义和证据状态不得由单个 Feature 私自复制或改写。
- Feature 文档可以按当前已确认 Map 完整规划，但开发仍按用户授权逐个 Feature 进行，不自动扩展到后续 Feature。
