# F006 · 验证评估与进入部署试运行规格

## 目标与可观察结果

项目进入验证评估后，FDE 能在既有“评估优化”页面按“生成评估方案 → 确认评估方案 → 开始验证”完成一条可理解链路，并逐项看见指标来自哪份前阶段文档及其中的需求/验收编号。固定用例回归保持独立可选动作。项目进度读取同一结构化验证合同、方案确认和三份固定产物；FDE 可以对未解决问题或单个未运行、失败、缺少证据的必需指标记录带理由和时间的人工接受决定，但该决定不篡改指标真实结果。只有当前方案确认仍有效、候选版本的每个必需指标具有可读取合格证据或完整 FDE 人工接受、关键问题已处理且三份产物齐备时，FDE 才能二次确认进入部署试运行。

## 来源与范围

- 来源需求：REQ-001, REQ-002, REQ-003, REQ-004, REQ-012, REQ-016, REQ-020, REQ-026, NFR-001, NFR-002, NFR-003, NFR-004, NFR-005, NFR-007, NFR-008
- 来源总规格：PSC-002, PSC-005, PSC-006, PSC-007, PSC-008, PSC-009, PSC-011, PSC-012, PSC-018, PSC-022, PSC-030
- 对应 PRD 验收：AC-001, AC-003, AC-004, AC-010, AC-019, AC-025
- 当前切片包含：单一验证 Skill、带前阶段来源的结构化验证合同、绑定方案定义摘要的 FDE 方案确认、生成方案/开始验证的当前会话提示、项目相对证据检查、真实数据驱动的评估总览与指标筛选、独立固定用例回归、项目进度中的问题及必需指标人工接受、三份产物与人工门，以及 `validation → pilot` 单步推进。
- 当前切片不包含：通用数据集管理平台、指标配置后台、性能测试平台、自动生成客户数据/标准答案/阈值、自动运行付费 Judge、部署编排、试运行监控或验收移交。

## 输入、证据与产物合同

### 结构化验证合同

固定路径：`.fde/evaluations/validation.json`。

| 对象 | 必需字段 | 规则 |
|---|---|---|
| 候选版本 | `candidate.id` | 必填；所有当前结果必须属于该候选版本 |
| 验证环境 | `environment` | 必填；描述本轮真实运行环境，不接受空白 |
| 数据/用例 | `datasets[]` | 按项目适用，可为空；只登记名称、版本/哈希和受控项目相对引用 |
| 指标 | `metrics[]` | 至少一项；每项有 id、名称、类别、方法、阈值、是否必需、一个或多个前阶段 `sources[]` 和当前结果 |
| 指标来源 | `sources[].path`、`references[]` | 路径必须是当前项目可读取的前阶段文档；references 记录其中的需求、验收或决策编号；没有来源不能形成可确认方案 |
| 结果 | `status`，PASS/WARN/FAIL 时的 `evidence` | `evidence` 是一个当前项目可读取的非空相对路径字符串，不是数组；多份底层证据由该指标的主证据文件索引；WARN 的结果接受理由只使用 camelCase 字段 `waiverReason`；FDE 对未运行、失败或缺证据必需指标的独立决定写入 `manualAcceptance.reason` 与 `manualAcceptance.acceptedAt`，不得修改原 `status` |
| 问题 | `issues[]` | 记录严重度、`open/resolved/waived` 状态和证据；未处理 critical/high 阻塞阶段门；FDE 人工关闭使用 `waived`，必须保留原问题并写入 `waiverReason` 与 `waivedAt` |

指标类别可使用 `business`、`functional`、`data`、`model`、`performance`、`security`、`recovery`、`agent`。平台不要求每个项目覆盖全部类别；是否适用由验收方案和 FDE 确认。

### 固定阶段产物

| 产物 | 固定路径 | 作用 |
|---|---|---|
| 验证计划 | `fde-deliverables/04-validation/validation-plan.md` | 固定候选版本、范围、输入、指标阈值、环境、执行方法和责任边界 |
| 验证报告 | `fde-deliverables/04-validation/validation-report.md` | 汇总真实运行、证据、问题、复测、未覆盖项和当前结论 |
| 验证基线 | `fde-deliverables/04-validation/validation-baseline.md` | 固定可进入试运行的候选版本、已接受风险、回退边界和证据索引 |

三份文档持续更新同一路径，不创建 `final-v2` 等平行最终版。文档存在不等于门槛通过。

### 评估方案确认

Host 在 `.fde/evaluations/validation-plan-approval.json` 保存 FDE 对当前评估方案定义摘要的确认。摘要覆盖候选版本、环境、数据/用例、指标来源文件内容摘要、方法、阈值和必需性，不包含验证执行后才会变化的结果、证据与问题处理状态。确认文件不由 Skill 生成；方案定义或来源文件内容变化后摘要不一致，状态立即变为“待重新确认”，正常写回执行结果不会使确认失效。验证计划存在、合同有效且所有指标来源可读取时才能确认；只有确认状态仍有效时“开始验证”可用。

### 评估页面信息层级

评估页首屏按“当前动作 → 验证总览 → 运行上下文”组织，而不是把长环境文字或完整指标表放大为同权卡片。三步流程保持紧凑并突出当前可执行动作。验证总览只根据当前合同计算必需指标完成率、PASS/WARN/FAIL/NOT_RUN 分布、证据覆盖、阶段产物和阻塞数量；不根据日期、文件存在或 Agent 自述推算趋势。运行上下文以可换行文本展示候选版本、环境与数据/用例。指标区域支持按结果和类别筛选，逐项保留来源、方法、阈值、结果、证据与接受理由；筛选只改变显示，不修改合同。问题、阻塞和固定用例回归作为独立区域呈现。

当单个指标字段无效时，Host 保留已经成功解析的候选版本、环境、数据集、其他指标和独立扫描的阶段产物，同时把合同标为无效并显示具体指标错误。无效合同不生成确认摘要、不能开始验证或推进阶段；页面不得以全零空状态掩盖仍可读取的真实数据。

## 用户旅程与状态

| 前置 | 用户动作 | 系统行为 | 可观察结果 | 下一步 |
|---|---|---|---|---|
| 项目刚进入 validation | FDE 点击“生成评估方案” | 页面回到当前对话；Agent 按需加载 `fde-validation`，只从验收方案、项目 PRD/方案基线与研发基线生成带来源合同和验证计划 | 页面显示候选版本、环境、输入、指标来源和待确认状态 | 审阅评估方案 |
| 合同与计划可审阅 | FDE 点击“确认评估方案” | Host 重新检查合同、来源和验证计划，并保存当前方案定义摘要的 FDE 确认 | 方案状态变为已确认，“开始验证”启用 | 开始验证或更新方案 |
| 方案已确认 | FDE 点击“开始验证” | 页面回到当前对话；Agent 读取已确认合同并执行项目适用验证，不修改指标迎合结果 | PASS/WARN/FAIL、证据、问题与未覆盖项 | 修复并复测或继续覆盖 |
| 已配置固定用例 | FDE 点击“运行固定用例” | 既有 F015 Runner 只运行 `.fde/evaluations/cases` | 隔离 Trial 报告与 Baseline 差异 | 把真实报告按适用指标引用为证据 |
| 发生失败或 WARN | FDE 修复、复测或记录接受决定 | 新结果引用新证据，旧运行保留；WARN 记录理由和范围 | 当前结论与历史运行可区分 | 继续验证或形成报告 |
| 存在未关闭问题 | FDE 在项目进度选择“人工确认关闭”并填写接受理由 | Host 复核当前方案摘要与问题仍为 open，在同一验证合同中原子写入 waived、理由和时间 | 原问题、处理建议与人工接受决定同时可见，该问题不再作为阶段阻塞 | 继续处理其他指标或进入最终二次确认 |
| 存在无法在本轮完成的必需指标 | FDE 在项目进度选择“人工接受指标”并填写原因、适用范围或后续约定 | Host 复核当前方案摘要、目标指标仍为必需且尚未具备正常合格结果，在同一验证合同中原子写入 `manualAcceptance` | 原 NOT_RUN/FAIL、证据缺口和说明继续可见，旁边显示 FDE 接受理由与时间；仅该指标不再阻塞 | 继续处理其他指标或进入最终二次确认 |
| 门槛满足 | FDE 在项目进度二次确认 | Host 重新解析合同、证据、产物、阶段和 revision | 单步进入 pilot；Agent 无推进能力 | 开始部署试运行 |

## 不变量与边界

1. 验证合同、证据、产物和阶段状态都绑定当前 Workspace，不按文件名或最近报告猜测。
2. 每项指标在结果前登记前阶段来源、方法和阈值；修改候选版本、输入、环境、指标来源、方法、阈值或必需性会使方案确认失效，正常更新结果、证据或问题处理状态不会使确认失效；方案定义变化后旧结果也不能满足当前门槛。
3. 数据集按项目适用，不是所有项目的统一硬门槛；平台不生成虚假客户样本、标准答案或阈值。
4. 每个 PASS/WARN/FAIL 都必须有真实证据；关键失败不能被平均分掩盖。未运行、失败或缺少证据的必需指标默认阻塞，FDE 只有记录单项非空接受理由和时间后才能解除该指标自身阻塞，原始结果与证据事实不得变化。
5. WARN 只有记录接受理由后才可正常满足门槛；open 的 critical/high 问题阻塞。FDE 可以把明确问题人工关闭为 waived，也可以人工接受单个未满足的必需指标；两种动作都必须保留原对象、写入非空理由和时间，且不影响其他指标或问题。
6. 生成方案和开始验证都只由用户明确触发并切回当前项目对话；涉及模型/外部服务时继续显示费用和数据边界。没有固定用例不阻止其他验证方法。
7. Agent、Skill、运行成功、报告生成和文件存在都不能推进阶段。

## 功能行为

1. 仅当项目处于验证评估时注入短阶段提示；“生成评估方案”和“开始验证”向当前 Session 排队明确提示并切回对话，Agent 按需加载 `fde-validation`。
2. 生成方案时 Skill 读取验收方案、项目 PRD/方案基线、研发基线和已有验证合同，为每项指标写入来源路径与编号，只维护合同和验证计划；缺少客户数据、阈值或授权时登记缺口，不编造答案。
3. Host 有界解析 `validation.json`，只接受固定枚举、数量上限、项目内来源/证据路径和精确结果字段；单个指标无效时保留顶层信息与其他有效指标但把整份合同标记为无效，以方案定义摘要保存或校验 FDE 方案确认；候选、环境、数据或指标定义变化后旧确认失效，结果与问题状态写回不影响方案确认。
4. 既有评估页以紧凑三步入口、验证总览、状态分布、证据覆盖、运行上下文和可筛选指标列表展示真实合同；确认前不允许开始验证。图表只使用当前合同和产物快照，不生成虚假趋势或完成度。原 Agent Trial 区域改名为“固定用例回归”，不复制执行器或 Baseline。
5. 开始验证时 Skill 读取已确认合同，执行真实验证并更新证据、验证报告和验证基线；如需修改指标定义则停止并要求 FDE 更新、重新确认方案。
6. 项目进度展示验证摘要、方案确认、三份固定产物、真实缺口和二次确认；问题卡片允许 FDE 对仍为 open 的问题展开人工关闭表单，未满足的必需指标允许展开人工接受表单。两类操作都要求填写理由后二次提交；Host 只接受当前 Workspace、当前方案摘要和仍符合操作条件的目标，原子更新合同并返回同一项目的新快照。
7. Host 只在确认仍有效、完整门槛和 expected revision 成立时单步进入部署试运行。人工关闭问题或人工接受指标只消除该对象自身的阻塞，原始指标状态、证据和其他阻塞保持不变。

## 异常与恢复

| 情况 | 用户可见状态 | 恢复 |
|---|---|---|
| 验证合同缺失/无效 | 显示具体字段或格式缺口；单个指标无效时仍展示候选版本、环境、数据、其他有效指标和独立产物，但不显示准备完成 | 让 Agent/人工修订固定合同后刷新 |
| 指标来源缺失/不可读取 | 对应来源显示缺口，方案不可确认 | 修正为当前项目前阶段文档及真实编号后刷新 |
| 方案未确认或合同已变化 | “开始验证”不可用，显示待确认或待重新确认 | FDE 审阅当前合同并再次确认 |
| 证据路径缺失或越界 | 对应指标显示缺少证据并阻塞 | 运行真实验证并写入项目内证据，或修正引用 |
| 关键 FAIL 或未接受 WARN | 列出指标/问题和原因，不允许提交 | 修复复测，或由 FDE 对非关键 WARN 记录接受决定 |
| 必需指标未运行、失败或缺证据但本轮确需继续 | 指标保持真实结果并显示人工接受入口，完成按钮保持不可用 | FDE 填写原因、适用范围或后续约定；Host 保存理由和时间后只解除该项阻塞 |
| 人工关闭时合同或问题已变化 | 保留当前页面并显示冲突，不覆盖 Agent 或其他 FDE 的较新写入 | 刷新后重新审阅当前问题和方案，再决定是否接受 |
| 产物缺失、阶段/revision 变化 | 完成操作不可提交或 Host 返回冲突 | 补齐三份文件、刷新权威状态后重新二次确认 |
| 评估执行器不可用 | 合同与计划仍可审阅，运行显示真实能力缺口 | 配置模型/工具后由用户再次触发，不生成假报告 |

## 验收标准

### AC-F006-001 · 验证合同不编造项目事实

- 来源：REQ-002, REQ-003, REQ-004, REQ-026, NFR-001, NFR-002, NFR-005, PSC-005, PSC-006, PSC-008, PSC-012, PSC-030
- 对应 PRD 验收：AC-003, AC-004, AC-025
- Given 项目处于验证评估，但部分数据、用例、阈值或环境尚未确认
- When FDE 让 Agent 准备验证
- Then Agent 按需加载 `fde-validation`，只登记已有事实和真实缺口；数据集按项目适用，缺失信息不被生成成客户标准答案或通过条件

### AC-F006-002 · 评估页展示当前候选版本的真实验证证据

- 来源：REQ-003, REQ-016, REQ-020, REQ-026, NFR-001, NFR-005, NFR-007, NFR-008, PSC-009, PSC-018, PSC-022, PSC-030
- 对应 PRD 验收：AC-003, AC-019, AC-025
- Given 当前项目存在有效验证合同、部分或全部真实运行证据
- When FDE 打开“评估”
- Then 页面明确展示生成方案、FDE 确认、开始验证三步，并以真实数字和可视化展示必需指标完成率、结果分布、证据覆盖、阶段产物与阻塞；在既有固定用例 Trial 之外展示候选版本、环境、输入以及可按结果/类别筛选的指标来源、编号、阈值、结果、证据、问题和未覆盖项；单个指标格式错误时保留其余可读取数据并明确阻止方案确认，无来源方案不能确认，无证据指标不显示通过，历史候选版本不满足当前门槛，页面不推算虚假趋势

### AC-F006-003 · 只有 FDE 能把验证评估推进到部署试运行

- 来源：REQ-001, REQ-012, REQ-026, NFR-001, NFR-003, NFR-004, NFR-005, NFR-008, PSC-002, PSC-007, PSC-009, PSC-011, PSC-030
- 对应 PRD 验收：AC-010, AC-025
- Given 当前评估方案确认与方案定义摘要一致，结构化合同有效，当前候选版本的必需指标均有合格证据，关键失败已处理，WARN 有接受理由，三份固定产物均存在
- When Agent 完成回复或 FDE 在项目进度二次确认
- Then Agent 行为不改变阶段；只有 FDE 提交且 Host 重新校验全部门槛、当前阶段和 expected revision 成功时，项目才单步进入部署试运行

### AC-F006-004 · 问题可以由 FDE 透明地人工接受

- 来源：REQ-003, REQ-012, REQ-016, REQ-026, NFR-001, NFR-004, NFR-005, NFR-007, NFR-008, PSC-007, PSC-009, PSC-011, PSC-018, PSC-030
- 对应 PRD 验收：AC-010, AC-015, AC-025
- Given 项目进度展示一个仍为 open 的验证问题，并且当前验证合同和评估方案仍是 FDE 正在审阅的版本
- When FDE 选择人工确认关闭、阅读不会改写真实指标的提示、填写非空接受理由并确认
- Then Host 仅把该问题原子更新为 waived，保存接受理由与时间并返回当前项目新快照；原问题、处理建议和指标真实结果继续可见，该问题自身不再阻塞阶段门；合同或问题已经变化、理由为空或跨项目请求均拒绝且不覆盖文件

### AC-F006-005 · 必需指标可以由 FDE 保留真实结果后人工接受

- 来源：REQ-003, REQ-004, REQ-012, REQ-020, REQ-026, NFR-001, NFR-004, NFR-005, NFR-007, NFR-008, PSC-007, PSC-009, PSC-011, PSC-018, PSC-030
- 对应 PRD 验收：AC-003, AC-004, AC-010, AC-019, AC-025
- Given 项目进度展示一个仍为 NOT_RUN、FAIL 或缺少可读取证据的必需指标，并且当前验证合同和评估方案仍是 FDE 正在审阅的版本
- When FDE 选择人工接受该指标、阅读不会改写真实结果的提示、填写非空理由并确认
- Then Host 只为该指标写入人工接受理由和时间，返回当前项目新快照；原始结果、证据缺口、阈值和说明继续可见且不显示为 PASS，该指标自身不再阻塞阶段门；合同或指标已经变化、指标并非必需、已经正常满足、理由为空或跨项目请求均拒绝且不覆盖文件
