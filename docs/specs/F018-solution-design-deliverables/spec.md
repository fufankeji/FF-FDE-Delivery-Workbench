# F018 · 方案设计标准产物规格

## 目标与可观察结果

项目进入方案设计后，工作台提供单一内置 `fde-solution-design` Skill，引导 Agent 基于已确认需求基线持续更新项目 PRD、方案设计、研发计划、验收方案和方案基线五份固定 Markdown 产物，并通过现有项目级架构工具维护系统架构。项目 PRD 负责定义要建设什么，方案设计负责定义如何实现。项目进度展示这些真实产物及架构确认状态；文件存在或 Agent 自评不等于阶段完成，只有 FDE 能通过 F005 推进到项目开发。

## 来源与范围

- 来源需求：REQ-002, REQ-003, REQ-011, REQ-012, REQ-016, REQ-018, REQ-023, NFR-001, NFR-003, NFR-004, NFR-005, NFR-007, NFR-008
- 来源总规格：PSC-002, PSC-004, PSC-005, PSC-006, PSC-007, PSC-011, PSC-018, PSC-020, PSC-027
- 对应 PRD 验收：AC-017, AC-022
- 当前切片包含：方案设计内置 Skill、阶段提示、五份固定文档、项目 PRD 与技术方案的职责边界、既有项目架构工具使用约束、项目进度真实状态与文档预览、人工交付门前置检查。
- 当前切片不包含：自动生成、完整手动画布、通用附件规则引擎、客户门户、多人审批，以及项目开发之后的阶段产物。

## 固定产物合同

| 产物 | 固定路径 | 用途 | Agent 边界 |
|---|---|---|---|
| 项目 PRD | `fde-deliverables/02-solution-design/project-prd.md` | 把已确认需求基线收敛为可开发、可验收的产品定义：用户与角色、业务目标、用户/业务流程、功能需求、业务规则、输入输出与数据、AI 行为与失败回退、约束、验收映射和未知项 | 只定义“做什么”和可观察结果；不得把候选需求写成已确认事实，不展开具体技术实现 |
| 方案设计 | `fde-deliverables/02-solution-design/solution-design.md` | 记录实现项目 PRD 的技术与工程方案：系统边界、组件、集成、数据/AI 策略、关键技术决策、需求映射和非目标 | 只定义“怎么做”；区分需求事实、方案选择、推断和未决项，不重复项目 PRD 的产品范围与角色定义 |
| 研发计划 | `fde-deliverables/02-solution-design/development-plan.md` | 记录工作包、里程碑、顺序、数据/环境/外部依赖和风险 | 不把候选日期或资源写成已承诺事实 |
| 验收方案 | `fde-deliverables/02-solution-design/acceptance-plan.md` | 记录业务、功能、AI、性能、安全、部署与试运行的验收条件 | 验收条件必须可检查，不以“效果良好”等空泛表述代替 |
| 方案基线 | `fde-deliverables/02-solution-design/solution-baseline.md` | 汇总候选方案版本、需求基线引用、关键决策、未决项、已接受风险和补充证据适用性 | Agent 只能形成候选，不能宣称 FDE 或客户已确认 |
| 系统架构 | `.fde/architecture.json` | 保存项目级组件、分组、关系、边界和确认 revision | 只通过 `architecture_get` / `architecture_set` 更新；不得直接写文件；只有 FDE 确认满足阶段门 |

原型、API 契约、数据映射和 POC 报告是按项目适用的补充证据，不是所有项目的固定文件。方案基线必须记录其是否适用、证据位置或不适用理由，最终由 FDE 复核。

## 用户旅程与状态

| 入口/前置 | 用户动作 | 过程与反馈 | 对象状态变化 | 可观察结果 | 下一步 |
|---|---|---|---|---|---|
| 项目处于方案设计 | FDE 让 Agent 收敛方案 | Agent 按需加载 Skill，读取需求基线、现有产物和当前架构 | 五份文档与候选架构原位创建或更新 | 项目进度显示真实文件与架构状态 | 继续审阅和修订 |
| 客户或技术事实变化 | FDE 补充信息并继续对话 | Agent 重新区分已确认需求、方案选择和未决项 | 同一路径产物更新，架构 revision 按工具合同更新 | 不产生平行最终版，不推进阶段 | FDE 确认架构和适用证据 |
| 五份文档存在且架构已确认 | FDE 打开项目进度并二次确认 | Host 在提交时复核固定文件、架构、当前阶段和 expected revision | F005 执行一次 `solution → development` | 项目进度和项目交付同步进入项目开发 | 开始项目开发 |

## 功能行为

1. 仅当项目处于方案设计时，模型请求获得短阶段约束；FDE 要求生成或更新方案时，Agent 才按需加载 `fde-solution-design`。
2. Skill 要求先读取已确认需求基线、用户本次授权来源、已有五份文档和当前架构，再更新同一路径；项目 PRD 与方案设计按“做什么/怎么做”分工，不互相复制。
3. Agent 不能直接写 `.fde/architecture.json`，必须先 `architecture_get`，再以精确 expected revision 调用 `architecture_set`。
4. 项目进度按固定合同展示五份文档并复用只读 Markdown 预览；架构显示标题、revision 和确认状态，完整审阅与确认仍在“系统架构”。
5. 五份文档存在且架构已确认只表示“可提交人工门”。最终推进必须由 FDE 二次确认，Agent 和 Skill 均无推进工具。

## 异常与恢复

| 情况 | 用户可见状态 | 恢复 |
|---|---|---|
| Skill 未加载或生成失败 | 对话显示真实失败，旧产物保持不变 | 重试当前请求或人工编辑文档 |
| 固定文档缺失/读取失败 | 单项显示待生成或读取失败 | 修复或让 Agent 更新固定文件 |
| 架构不存在或仍为候选 | 显示待生成、候选或待确认 | 在系统架构中生成、审阅并确认明确 revision |
| 阶段或 revision 已变化 | 提交失败并刷新权威状态 | 按最新状态重新审阅后提交 |

## 验收标准

### AC-F018-001 · 方案设计规范可被 Agent 按需加载

- 来源：REQ-002, REQ-003, REQ-011, NFR-003, NFR-005, PSC-004, PSC-005, PSC-011, PSC-027
- 对应 PRD 验收：AC-022
- Given 当前项目处于方案设计并已有确认需求基线
- When FDE 请求 Agent 生成或更新方案设计阶段产物
- Then Agent 被要求加载 `fde-solution-design`，只更新项目 PRD 等五份固定文档并通过项目架构工具维护候选架构；项目 PRD 定义建设对象、方案设计定义实现方式，不创建平行最终版或推进阶段

### AC-F018-002 · 项目进度真实展示方案设计产物

- 来源：REQ-003, REQ-016, REQ-018, REQ-023, NFR-001, NFR-005, NFR-007, NFR-008, PSC-018, PSC-020, PSC-027
- 对应 PRD 验收：AC-017, AC-022
- Given 当前项目存在零到五份固定文档以及零到一个当前系统架构
- When FDE 打开项目进度中的项目详情
- Then 五份文档逐项显示真实状态并在存在时支持预览，系统架构显示真实标题、revision 和确认状态；缺失不补造，候选不显示为已确认

### AC-F018-003 · 方案设计只能由 FDE 推进

- 来源：REQ-012, REQ-018, REQ-023, NFR-003, NFR-004, NFR-008, PSC-002, PSC-006, PSC-007, PSC-020, PSC-027
- 对应 PRD 验收：AC-010, AC-022
- Given 五份文档存在且系统架构状态为已确认
- When Agent 完成回复、文件写入或架构更新，或 FDE 在项目进度完成二次确认
- Then Agent 行为不改变阶段；只有 FDE 提交且 Host 校验固定产物、架构、阶段和 revision 成功时，项目才进入项目开发

## 开放问题

- 项目开发阶段的固定输入、产物和交付门在进入下一阶段设计时另行冻结，本 Feature 不预设。
