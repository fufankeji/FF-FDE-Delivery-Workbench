# F008 · 阶段 4：方案与纵向切片规格

## 目标与可观察结果

FDE 基于已确认的业务结果和真实现场边界，分别判断“系统用什么执行”与“系统用什么语义基础理解领域”，比较不构建／人工、规则、传统软件、检索／RAG、ML／LLM、Agent 等执行机制，以及普通数据／接口 Schema 与正式本体／知识图谱两类语义基础，形成可回滚的生产级方案、合同、NFR 和最窄端到端纵向切片；方案必须说明不做什么、由谁审批以及如何验证。本体／知识图谱是可以与规则、软件、RAG 或 Agent 组合的条件语义路线，不是所有项目的默认实现，也不是与 Agent 互斥的单一候选。

## 来源与范围

- 来源需求：REQ-003, REQ-006, REQ-007, REQ-014, REQ-015, REQ-020, REQ-025, REQ-026, REQ-028, NFR-002, NFR-004, NFR-009, NFR-011, NFR-013, NFR-014
- 来源总规格：PSC-003, PSC-005, PSC-006, PSC-013, PSC-016, PSC-021, PSC-022, PSC-023, PSC-024
- 本 Feature 包含：执行机制与语义基础的双轴选择、方案比较、系统设计、合同、NFR、权限边界、验证计划和可运行纵向切片；当证据表明必须使用正式本体／知识图谱时，还包含项目材料绑定、最小语义模型、受控构建、独立验证和 Agent 上下文查询链路。
- 本 Feature 不包含：完整项目开发、最终 Eval 结论、生产授权，或假设所有项目都必须使用 Agent、本体或知识图谱。
- 本 Feature 不负责对全部客户材料进行规模化建图、批量质量评估或生产图谱运营；第四阶段只使用代表样本和有边界的真实数据证明最小链路，规模、稳定性和效果验证进入后续 PoC／Eval 与 Pilot。

## 条件本体／知识图谱路线

第四阶段始终先做双轴机制判断。所有方案都必须形成最小领域语义、数据／接口合同和系统边界，但只有项目确实需要跨来源实体统一、复杂关系、多跳查询、时间有效性、来源追溯、冲突处理、图推理或多个 Agent 共享稳定语义时，才进入正式本体／知识图谱路线；“业务复杂”、已经安装图谱工具或希望展示知识图谱均不能单独成为启用依据。

### 双轴机制判断

- 执行机制回答“系统如何完成工作”，候选至少覆盖不构建／人工、规则、传统软件、检索／RAG、ML／LLM 和 Agent；可以组合，但必须说明主机制、辅助机制、不采用项和人工边界。
- 语义基础回答“系统如何表达和查询领域事实”，候选为普通数据／接口 Schema 或正式本体／知识图谱；正式本体可以与任一执行机制组合，不得被建模为与 Agent、RAG 或传统软件互斥的单选项。
- 工作台分别显示两轴的适配依据、缺失证据、复杂度、风险和当前候选；任一轴证据不足时保持未决，不因工具已部署而预选正式本体。

工作台用以下九项业务结构解释这条路线：

1. 机制必要性判断；
2. 能力问题集（Competency Questions）；
3. Schema 与关系；
4. 来源规则；
5. 时间与置信度规则；
6. 构建与验证；
7. 项目纵向切片；
8. 运行证据；
9. FDE 人工决定。

九项是用户可理解的业务结构，不等于九个同层文件或九份页面本地状态。定义类对象必须可版本化；构建、验证和纵向切片必须保存为可重复运行记录；运行证据从真实步骤聚合，不允许由说明文字或前端状态伪造。所有 Schema、实体、关系和规则都来自当前项目证据，不得把测试案例固化为产品合同。

### 项目材料绑定

- 本体路线只选择前三阶段已登记且当前获准使用的项目资料，不要求用户向另一个系统重复上传。
- 每次绑定必须保存项目身份、材料引用、来源、内容版本、更新时间、授权范围和本次用途；路径变化不得改变材料身份，未锁定版本或未获授权的内容不能进入构建。
- 原始文件继续由项目 Workspace 保存和管理。本体／图谱能力只能读取本次绑定的材料，并把解析、抽取、映射和构建结果回指这些稳定引用，不得接管、覆盖或静默更新原始材料。
- 用户可查看每份材料是否纳入本轮、处理到哪一步、产生多少候选、有哪些警告或失败；技术日志按需展开，不替代业务状态。

### 本体、Schema 与知识图谱边界

- 最小领域语义和普通数据／接口 Schema 是所有方案都需要的合同；正式 Ontology Schema 只有在语义基础判断为需要时形成。
- Ontology Schema 定义类、属性、关系、关系方向、Domain／Range、约束和规则；项目知识图谱记录遵循当前 Schema 的真实实体实例、关系、来源、置信度和时间。
- 工作台必须分别呈现 Schema 视图和实例图谱视图。Schema 尚未发布或图谱尚未真实构建时，只显示相应前置条件和空状态，不用示例节点填充。
- 抽取结果先进入候选集合。第四阶段优先审阅代表样本、低置信度项、冲突项和高风险关系，不要求人工逐条批准全部节点，也不得把未审核候选自动冒充正式事实。

### 两轮最小闭环

本体路线分为两个可以修订和重跑的循环：

1. 最小本体设计循环：定义能力问题 → 选择代表材料 → 解析和抽取候选 → 生成或导入候选 Schema → 人工删减、修订和补充规则 → 发布当前 Ontology 版本。
2. 最小图谱与业务循环：绑定一组有边界的真实材料 → 解析、抽取、身份匹配、去重和冲突处理 → 按当前 Ontology 构建项目图谱 → 补齐来源、时间和置信度 → 执行结构校验和真实能力问题查询 → 生成受控 Agent 上下文 → 跑通最窄业务链路。

第四阶段只证明一组代表材料和一条真实链路能够成立，不以全量建图、批量性能或总体准确率作为完成条件；这些问题由后续 PoC／Eval 和 Pilot 验证。

### 可配置与固定边界

- FDE 可以审阅和修改能力问题、类与属性、关系方向和 Domain／Range、必填／唯一／基数约束、别名、身份匹配键、字段映射、来源权威级别、冲突优先级、时间有效规则、置信度阈值和约束严重级别。
- 解析器、OCR、切分、抽取模型、并发、批量、重试和图渲染等运行参数默认不占据主流程；只有确有诊断或调优需要时才在高级设置中出现，并明确修改对旧证据的影响。
- 项目隔离、材料版本、权限范围、运行证据、FDE 决定权和禁止跨项目查询属于系统固定边界，不能被本体编辑器或运行参数修改。

### Agent 上下文与项目使用

- 验证中的图谱必须通过项目级受控查询提供上下文，而不是把整张图谱或全部文档注入模型。
- 每次上下文结果至少说明本次问题、相关实体、关系、适用约束、推导事实、来源、有效时间、置信度、Schema 版本和图谱版本；没有来源、已过期或超出权限的事实不能静默进入 Agent 上下文。
- 第四阶段必须用这份上下文实际执行一条项目任务，并记录查询条件、返回子图或答案、Agent 使用方式、业务结果和失败点。能够浏览图谱或得到节点数量不能替代这条纵向切片证据。
- 当前 Schema、来源规则、时间规则、权限或图谱版本变化后，引用旧版本的上下文结果、验证和纵向切片必须标记为待重评。

### 过程状态与结论

- 本体必要性过程状态为未判断、需要或不需要；“需要”只表示进入条件路线，不表示路线已经验证通过。
- 定义类对象至少区分草稿、待审阅、当前版本和已过期；构建与纵向切片运行至少区分等待、运行、成功、失败和已取消；验证至少区分未运行、运行中、通过、失败、不可用和已过期。
- 工作台的当前工作、完成数量和下一动作必须由选中路线、对象版本和真实运行记录推导，不能由固定步骤序号、文件数量或前端本地状态代替。

### 机制结论与人工决定

准备提交阶段评审时，本体机制结论只能是以下四种之一：

- `not_required`：不需要图谱，采用更简单机制；
- `validated`：需要图谱，验证通过；
- `validation_failed`：需要图谱，但当前方案未通过验证；
- `insufficient_evidence`：信息不足，暂不决定。

过程中的“需要”、构建成功或单项校验通过不直接映射为上述结论。只有当前版本的必要结构校验、必答能力问题真实查询和图谱上下文纵向切片均形成可引用证据时，才可以形成 `validated` 候选结论。

本体机制结论与 FDE 阶段决定相互独立。FDE 提交后仍然只有 `Go`、`Revise`、`Narrow` 或 `Stop` 四类决定；提交前显示“等待人工决定”，但它不构成第五种决定。例如 `not_required + Go` 表示不使用图谱但项目可以继续，`validation_failed + Revise` 表示保留图谱方向并修订当前方案。任何构建工具、Provider 或 Agent 都不得根据一次调用结果代替 FDE 写入阶段决定。

## 功能行为

### 主流程

1. 固定读取阶段 2 结果合同和阶段 3 现场 Artifact，并展示本轮引用的确定版本和已确认权限。
2. 分别比较执行机制和语义基础，记录可组合的候选、被淘汰方案、非目标、约束与选择依据，并明确是否需要正式本体／知识图谱。
3. 不需要图谱时，直接形成开发 Spec、合同和验证条件；需要图谱时，绑定获准材料并完成最小本体设计循环，再使用有边界的真实数据完成图谱与业务循环。
4. 设计端到端组件、数据流、身份、工具动作、人工审批、降级和回滚；图谱查询只能作为受控上下文来源，不得绕过当前项目权限。
5. 形成 ADR、合同、NFR、验证计划和最窄纵向切片，并分别保存解析／抽取、Schema、构建、校验、能力问题查询、上下文获取与业务运行证据。
6. 仅在机制选择结果需要时生成对应条件 Artifact；未选中的 Agent、本体或知识图谱路线不得创建空占位文件。
7. 由 FDE 确认候选方案是否进入 PoC 与 Eval。

### 业务规则与边界

- 机制选择先于 Agent 实现；能够用规则或传统软件可靠解决时必须保留该选项。
- 正式本体是语义基础选择，不是执行机制的替代名词；同一方案可以组合规则、软件、RAG 或 Agent 与正式本体。
- 纵向切片必须贯穿真实输入、关键判断、受控动作和可验证结果，而不是只完成静态 UI。
- 连接合同必须继承阶段 3 的权限、政策与人工升级边界，方案不得悄然扩大授权。
- 已上传资料必须通过当前项目的稳定材料引用进入本轮工作；不得以重复上传、绝对路径或 Provider 内部 ID 代替项目身份和版本。
- 本体／知识图谱路线中的“构建完成”和“验证通过”是两个不同事实；一次构建命令成功、生成节点／边或页面可查看均不能单独证明路线有效。
- 能力问题的文字覆盖、类名匹配或总体质量分数只构成诊断信号；必答问题必须在当前项目图谱上执行真实查询并保存输入、结果和证据。
- 图谱提供给 Agent 时必须通过受控查询返回必要上下文，并保留权限、来源、时间和适用边界；不得把整个图谱无差别注入模型上下文。
- Schema、来源规则、时间规则或 Provider 配置发生变化后，引用旧版本的验证和纵向切片证据必须标记为待重评，不得继续显示为当前有效结论。

## 异常与恢复

| 情况 | 用户可见状态 | 系统行为 | 恢复/重试 |
|---|---|---|---|
| 候选机制证据不足 | 选择未决 | 不默认选择 Agent | 补调查或设计最小 Probe |
| 外部合同不可验证 | 集成阻塞 | 保存假设与待确认合同 | 取得沙箱、样例或责任人确认 |
| 切片运行失败 | 方案待修订 | 保存构建、日志和失败点 | 修改候选版本后重跑 |
| 材料版本或权限发生变化 | 下游证据待重评 | 保留旧运行并停止把它显示为当前有效 | 重新绑定当前版本并从受影响步骤重跑 |
| 解析、抽取或身份匹配出现低置信度与冲突 | 候选知识待处理 | 正式图谱不吸收未达到当前规则的候选 | 审阅代表样本、冲突和高风险关系后重跑 |
| 图谱构建成功但能力问题未通过 | 本体方案未通过验证 | 保留构建与失败证据，不写成路线完成 | 修订 Schema、映射或规则后建立新版本并重跑 |
| 本体 Provider、结构校验或查询能力不可用 | 当前验证不可执行 | 显示不可用及缺失能力，不降级成通过或伪造结果 | 恢复能力后针对同一版本重新运行 |
| 本体必要性信息不足 | 暂不决定 | 保持 `insufficient_evidence`，不创建演示图谱补空 | 返回阶段 3 补来源、关系、时间或责任证据 |
| 用户要求在第四阶段处理全部语料 | 超出当前阶段范围 | 保留最小代表集和扩展计划，不把规模化处理冒充纵向切片 | 在 PoC／Eval 或 Pilot 中验证规模、质量和稳定性 |

## 验收标准

### AC-F008-001 · 方案选择与纵向切片工作可理解

- 来源：REQ-006, REQ-007, REQ-020, REQ-025, REQ-026, NFR-004, NFR-013, NFR-014, PSC-005, PSC-006, PSC-016, PSC-021, PSC-022
- 对应 PRD 验收：AC-018, AC-022, AC-023
- Given 业务结果和现场边界已有可引用证据
- When 用户要求选择机制并设计最窄可运行链路
- Then 平台分别比较执行机制与语义基础，允许两者形成有依据的组合路线，按需路由方法、工程能力与工具，并在专属阶段工作台展示前序依据、当前路线、权限边界、真实运行和预计 Artifact；未选择路线不出现空占位或演示数据

### AC-F008-002 · 方案、合同、NFR 与切片证据可组合且人工确认

- 来源：REQ-003, REQ-028, NFR-002, NFR-011, PSC-003, PSC-016, PSC-023, PSC-024
- 对应 PRD 验收：AC-003, AC-018, AC-025
- Given 候选方案、合同、NFR、验证计划和纵向切片已形成
- When FDE 阅读完整方案与真实运行证据并提交决定
- Then Artifact 回指输入版本和证据状态，图谱路线还能回指 Schema、图谱和上下文版本；缺失、失败、不可用或已过期不伪装为完成，只有 FDE 决定进入 PoC 与 Eval

### AC-F008-003 · 本体／知识图谱按必要性进入并独立验证

- 来源：REQ-006, REQ-007, REQ-014, REQ-015, REQ-020, REQ-025, REQ-026, REQ-028, NFR-002, NFR-004, NFR-009, NFR-011, NFR-013, NFR-014, PSC-005, PSC-006, PSC-013, PSC-016, PSC-021, PSC-022, PSC-023, PSC-024
- 对应 PRD 验收：AC-006, AC-012, AC-013, AC-018, AC-022, AC-023, AC-025
- Given 阶段 2 的结果范围和阶段 3 的真实环境证据已可引用
- When 平台判断最小纵向切片是否需要正式本体／知识图谱
- Then 不需要时直接走更简单的 Spec 与实现路线且不生成空图谱 Artifact；需要时绑定当前项目中获准且版本固定的代表材料，通过最小本体设计循环和最小图谱与业务循环，分别形成能力问题、Ontology Schema、实例知识图谱、来源／时间／置信度规则、候选知识处理、结构校验、必答问题真实查询、受控 Agent 上下文和纵向切片证据，并将过程状态、四类本体机制结论与 FDE 人工决定分别保存
