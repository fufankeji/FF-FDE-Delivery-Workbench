# F008 · 阶段 4：方案与纵向切片规格

## 目标与可观察结果

FDE 基于已确认的业务结果和真实现场边界，比较规则、传统软件、ML、RAG、LLM、Agent 与人工处理等机制，形成可回滚的生产级方案、合同、NFR 和最窄端到端纵向切片；方案必须说明不做什么、由谁审批以及如何验证。

## 来源与范围

- 来源需求：REQ-003, REQ-006, REQ-007, REQ-020, REQ-025, REQ-026, REQ-028, NFR-002, NFR-004, NFR-011, NFR-013, NFR-014
- 来源总规格：PSC-003, PSC-005, PSC-006, PSC-016, PSC-021, PSC-022, PSC-023
- 本 Feature 包含：机制选择、方案比较、系统设计、合同、NFR、权限边界、验证计划和可运行纵向切片。
- 本 Feature 不包含：完整项目开发、最终 Eval 结论、生产授权或假设所有项目都必须使用 Agent。

## 阶段主视图与数据投影

| 页面问题 | 核心视图 | 读取数据 | 人工介入信号 |
|---|---|---|---|
| 最窄可运行链路怎么走 | 机制对比、系统与数据／动作流、工具合同、NFR、纵向切片执行路径和 ADR 决策记录 | 候选机制、选择理由、组件、合同、动作、人工门禁、NFR 和切片运行回执 | 机制缺少证据、合同未知、范围持续膨胀、切片未贯通真实输入到结果 |

## 功能行为

### 主流程

1. 固定读取阶段 2 结果合同和阶段 3 现场 Artifact。
2. 比较可行机制，记录被淘汰方案、非目标、约束与选择依据。
3. 设计端到端组件、数据流、身份、工具动作、人工审批、降级和回滚。
4. 形成 ADR、合同、NFR、验证计划和最窄纵向切片，并保存真实构建与运行证据。
5. 仅在选择模型或 Agent 时生成相应行为与能力 Artifact；确定性方案不得创建空占位文件。
6. 由 FDE 确认候选方案是否进入 PoC 与 Eval。

### 业务规则与边界

- 机制选择先于 Agent 实现；能够用规则或传统软件可靠解决时必须保留该选项。
- 纵向切片必须贯穿真实输入、关键判断、受控动作和可验证结果，而不是只完成静态 UI。
- 连接合同必须继承阶段 3 的权限、政策与人工升级边界，方案不得悄然扩大授权。

## 异常与恢复

| 情况 | 用户可见状态 | 系统行为 | 恢复/重试 |
|---|---|---|---|
| 候选机制证据不足 | 选择未决 | 不默认选择 Agent | 补调查或设计最小 Probe |
| 外部合同不可验证 | 集成阻塞 | 保存假设与待确认合同 | 取得沙箱、样例或责任人确认 |
| 切片运行失败 | 方案待修订 | 保存构建、日志和失败点 | 修改候选版本后重跑 |

## 验收标准

### AC-F008-001 · 方案选择与纵向切片工作可理解

- 来源：REQ-006, REQ-007, REQ-020, REQ-025, REQ-026, NFR-004, NFR-013, NFR-014, PSC-005, PSC-006, PSC-016, PSC-021, PSC-022
- 对应 PRD 验收：AC-018, AC-022, AC-023
- Given 业务结果和现场边界已有可引用证据
- When 用户要求选择机制并设计最窄可运行链路
- Then 平台比较适用机制，按需路由方法、工程能力与工具，并展示方案依据、权限边界、当前构建和预计 Artifact

### AC-F008-002 · 方案、合同、NFR 与切片证据可组合且人工确认

- 来源：REQ-003, REQ-028, NFR-002, NFR-011, PSC-003, PSC-016, PSC-023
- 对应 PRD 验收：AC-003, AC-018, AC-025
- Given 候选方案、合同、NFR、验证计划和纵向切片已形成
- When FDE 阅读完整方案与真实运行证据并提交决定
- Then Artifact 回指输入版本和证据状态，缺失或失败不伪装为完成，只有 FDE 决定进入 PoC 与 Eval
