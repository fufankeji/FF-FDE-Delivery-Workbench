## 实现方案

把机制选择、系统设计、合同、NFR、验证计划和纵向切片定义为可独立版本化但相互引用的 Artifact。方法层决定需要回答的问题，工程层选择实现规范，DeepSeek Harness 工具完成真实构建、运行和观察。阶段工作台沿用统一骨架，中心区域专门投影机制对比、系统与数据／动作流、工具合同、NFR 和纵向切片路径；架构页只读取已发布方案 Artifact，不承担阶段推进。

第四阶段先建立机制分支：简单业务直接形成开发 Spec、合同和验证条件并实现最窄切片；只有证据表明需要跨来源实体统一、复杂关系、时间有效性、来源追溯、冲突处理或图推理时，才启用本体／知识图谱路线。业务复杂度或已安装 Semantica 均不能单独触发该路线。

### 稳定对象与状态投影

工作台用“机制必要性判断、能力问题、Schema 与关系、来源规则、时间与置信度规则、构建与验证、项目纵向切片、运行证据、FDE 人工决定”九项业务结构展示过程；持久层不按九张卡片建立九套页面状态，而是区分：

- 可版本化定义：机制判断、能力问题集、Schema／关系、来源规则、时间与置信度规则；
- 可重复运行记录：构建运行、验证运行、纵向切片运行；
- 证据聚合：引用输入版本、Provider 版本与配置、定义版本、真实输出、诊断和适用边界；
- 人工决定：独立于本体机制结论保存，不由 Provider、Agent 或 UI 推导写入。

本体机制结论固定为 `not_required`、`validated`、`validation_failed` 或 `insufficient_evidence`；FDE 提交后继续只使用 `Go`、`Revise`、`Narrow` 或 `Stop`，未提交时保持无决定并显示等待人工评审。Schema、规则或 Provider 配置变化时，引用旧版本的验证与切片证据进入待重评，而不是被覆盖或继续显示为当前通过。

### Semantica Provider 边界

FDE 工作台继续以 Workspace、阶段状态、Artifact、证据和人工决定为权威事实源。Semantica 是条件启用、可替换的本地能力 Provider，只负责被显式编排的摄取、抽取、建图、本体应用、来源／时间处理、验证、查询和导出；一次“构建图谱”返回成功不能自动完成第四阶段。

每个项目使用隔离的图、工作目录和运行身份，不共享全局演示图谱；Provider 版本、配置、输入引用和输出摘要进入运行记录，源码路径和启动方式通过产品配置解析，不硬编码开发机绝对路径。Explorer 仅作为可选深入查看入口，不拥有阶段状态。

Provider 载体在实现前通过最小 Spike 比较 Semantica Python API、本地服务 API 与现有 MCP 能力，以“覆盖本体构建和独立验证、能返回结构化运行证据、可保持项目隔离”为选择条件；不得因 MCP 已存在就牺牲本体或验证能力。

### Agent 上下文边界

验证通过的图谱只通过项目级受控查询进入 Agent 上下文。查询必须携带当前项目身份和权限范围，返回必要子图或答案及其来源、时间、置信度和适用边界；不把整个图谱无差别注入 Prompt，也不允许图谱查询扩大阶段 3 已确认的读取或动作权限。

## 实施顺序

1. 固定阶段 4 方法、模板、Schema、工程 Skills，以及本体路线的九项业务结构与双状态合同。
2. 适配方案类 Artifact、简单实现路线和条件本体／知识图谱路线。
3. 通过最小 Spike 固定 Semantica Provider 载体、版本、项目隔离和结构化运行回执。
4. 实现方案路由、权限继承、受控图谱查询和纵向切片 operation。
5. 构建机制比较、设计、条件本体、切片与证据工作面；未选中路线不显示空占位对象。
6. 接入方案评审、FDE 决定和定义／输入版本变化后的证据失效影响。
7. 用简单确定性路线与需要图谱的路线分别验证；模型型和 Agent 型能力继续按机制选择加载。

## 依赖与风险

| 依赖/风险 | 影响 | 应对 | 验证时机 |
|---|---|---|---|
| 把所有问题默认设计为 Agent | 方案复杂且不可控 | 强制候选机制比较 | 路由／Artifact 测试 |
| 把复杂业务默认设计为知识图谱 | 引入无必要的语义建模和运行成本 | 以能力问题和可验证的跨源／关系／时间需求作为启用依据 | 双路线测试 |
| 工作台直接依赖 Semantica 项目目录或演示图 | 项目串线、状态漂移且难以替换 Provider | Workspace 作为权威身份，Provider 数据逐项目隔离并由配置解析 | 项目隔离测试 |
| 图谱构建成功被当成路线验证通过 | 虚假完成并污染后续 Agent 上下文 | 构建运行、验证运行、切片运行和 FDE 决定分别记录 | 状态与负向测试 |
| 将整个图谱注入 Agent Prompt | 权限、Token、时效和来源边界失控 | 只开放带项目权限、来源和时间过滤的受控查询 | 上下文权限测试 |
| 切片仅有 UI 无真实链路 | 虚假可运行 | 要求输入到结果的运行证据 | 端到端测试 |
| 方案扩大访问权限 | 越权 | 继承 ToolPolicy，扩大必须重审 | 权限回归测试 |

## 回退策略

候选方案失败时保留阶段 3 已确认边界和全部失败证据；可建立新方案版本或返回调查，不覆盖旧 ADR，不把失败切片发布为有效候选。

Semantica 不可用、构建失败或验证未通过时，保留同一次运行的输入、配置、诊断和部分输出；工作台可返回更简单机制、修订本体路线或补调查，但不得自动降级后继续宣称原方案已通过。
