# F008 · 阶段 4：方案与纵向切片实施计划

## 现有上下文与复用

- 当前实现与入口：系统架构页、代码树、终端、浏览器、Diff 和对话可承载方案与切片工作。
- 直接复用点：F007 现场地图、政策边界和治理状态；F003 执行；F004 Artifact 组合。
- 必须保持的现有行为：现有系统架构预览、代码开发和普通会话继续可用。
- 必须保持的 Product Spec 合同：PSC-003, PSC-005, PSC-006, PSC-016, PSC-021, PSC-022, PSC-023。

## 实现方案

把机制选择、系统设计、合同、NFR、验证计划和纵向切片定义为可独立版本化但相互引用的 Artifact。方法层决定需要回答的问题，工程层选择实现规范，DeepSeek Harness 工具完成真实构建、运行和观察。阶段工作台沿用统一骨架，中心区域专门投影机制对比、系统与数据／动作流、工具合同、NFR 和纵向切片路径；架构页只读取已发布方案 Artifact，不承担阶段推进。

## 实施顺序

1. 固定阶段 4 方法、模板、Schema 与工程 Skills。
2. 适配方案类 Artifact 和机制条件映射。
3. 实现方案路由、权限继承和纵向切片 operation。
4. 构建机制比较、设计、切片与证据工作面。
5. 接入方案评审、FDE 决定和上游失效影响。
6. 用确定性、模型型和 Agent 型三类候选验证。

## 依赖与风险

| 依赖/风险 | 影响 | 应对 | 验证时机 |
|---|---|---|---|
| 把所有问题默认设计为 Agent | 方案复杂且不可控 | 强制候选机制比较 | 路由／Artifact 测试 |
| 切片仅有 UI 无真实链路 | 虚假可运行 | 要求输入到结果的运行证据 | 端到端测试 |
| 方案扩大访问权限 | 越权 | 继承 ToolPolicy，扩大必须重审 | 权限回归测试 |

## 回退策略

候选方案失败时保留阶段 3 已确认边界和全部失败证据；可建立新方案版本或返回调查，不覆盖旧 ADR，不把失败切片发布为有效候选。
