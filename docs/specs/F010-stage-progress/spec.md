# F010 · 六阶段项目进度规格

## 目标与可观察结果

FDE 在项目交付的任一会话中都能看见当前项目所处阶段；六阶段顺序、revision 和项目级状态保持统一，完整的多项目阶段、返回历史与待重新确认范围由 F011 独立“项目进度”页面负责。当前阶段提示不提供绕过阶段交付门的推进或返回动作。

## 来源与范围

- 来源需求：REQ-001, REQ-002, REQ-012, NFR-005, NFR-007, NFR-008
- 来源总规格：PSC-001, PSC-002, PSC-004, PSC-011, PSC-012, PSC-014
- 对应 PRD 验收：AC-001, AC-002
- 当前切片包含：六阶段固定顺序和高层目标；项目级当前阶段、revision、返回历史和待重新确认上界的只读合同；空白会话的品牌引导、轻量当前阶段入口与已开始会话的当前阶段标识；从轻量入口打开当前项目的“项目进度”详情；已授权阶段推进/返回后的当前 Workspace 状态刷新；项目切换、刷新、Host 重启后的恢复；加载、失败和重试。
- 当前切片不包含：会话内“交付流程”页面；跨项目汇总页面；空白引导中的文件数量、完成率或产物存在状态；改变阶段的写入口；完成百分比推算；自动启动 Agent、Skill、测试或部署。

## 六阶段定义

| 顺序 | 阶段 | 高层目标 | 阶段回答的问题 |
|---:|---|---|---|
| 1 | 需求调研 | 筛选正确场景，理解真实业务、岗位、SOP、问题边界和验收方向 | 到底要解决什么，为什么值得做？ |
| 2 | 方案设计 | 设计目标工作流、产品形态、技术路线、可行性验证、计划和验收方案 | 应该怎么做，而且确实能做吗？ |
| 3 | 项目开发 | 完成环境准备、工程开发、数据与系统集成，形成可运行候选版本 | 能否把确认方案做成真实系统？ |
| 4 | 验证评估 | 完成功能、端到端、质量、AI 效果和流程验证并闭环问题 | 当前候选版本是否达到约定标准？ |
| 5 | 部署试运行 | 进入真实环境，建立权限、监控、回退和人工兜底并收集反馈 | 它能否在客户真实环境中持续运行？ |
| 6 | 验收移交 | 完成正式验收、运行说明、培训、责任边界和能力沉淀 | FDE 离开后，客户能否继续使用和维护？ |

## 用户旅程与状态

| 入口/前置 | 用户动作 | 过程与反馈 | 对象状态变化 | 可观察结果 | 下一步 |
|---|---|---|---|---|---|
| 新项目首个空白会话 | 进入项目 | 工作台解析会话所属项目并读取或初始化项目阶段 | 项目当前阶段为需求调研；会话内容仍可为空 | 输入框上方以一条轻量阶段栏显示“阶段 1/6 · 需求调研”和一句当前行动提示 | 直接输入需求，或点击“查看项目进度”进入当前项目详情 |
| 已开始的项目会话 | 查看会话头部 | 工作台读取同一项目阶段 | 不改变项目状态 | 头部显示当前阶段 | 继续对话、打开项目资料或开发工作区 |
| 同项目另一会话 | 切换会话 | 按 Workspace 项目身份读取阶段 | 阶段不随 Session 改变 | 两条会话显示同一当前阶段 | 继续项目工作 |
| 另一项目 | 切换项目会话 | 重新解析 Workspace 并读取该项目状态 | 当前查看项目变化 | 不显示前一项目阶段状态 | 在新项目继续工作 |
| 状态读取失败 | 打开阶段提示 | 显示失败原因和重试动作 | 已有项目与会话保持不变 | 不用默认成功或其他项目缓存代替失败 | 重试或继续使用对话 |

## 功能行为

### 主流程

1. 项目创建成功后即处于需求调研阶段；空白只描述项目尚无需求内容，不是第七个业务阶段。
2. 六阶段顺序固定为需求调研、方案设计、项目开发、验证评估、部署试运行、验收移交。
3. 当前阶段属于 Workspace 项目；同项目所有普通 Session 显示同一值，项目切换后不得继续展示旧项目状态。阶段门成功提交后，阶段提示必须使当前 Workspace 的旧缓存失效并重新读取 Host 已提交值。
4. 空白会话沿用官方 Hero 和输入框：品牌标题使用清晰的主副标题层级；输入框上方只显示一条轻量阶段栏，包含当前阶段序号、名称、一句当前行动提示和“查看项目进度”动作。阶段栏与输入卡使用同一水平宽度和左右边界，不能因 Slot 位于输入卡外层而错位；不得在工作入口重复六阶段全景、阶段输入/输出或项目管理数据。
5. “查看项目进度”必须打开当前 Workspace 的项目详情，而不是只打开多项目概览或无响应；六阶段全景、真实资料、阶段产物和人工确认全部由项目进度页面读取并呈现。
6. 当前切片不显示“下一阶段”“完成阶段”“返回上一阶段”或可编辑百分比；阶段写操作只属于 F005/F011 的受控人工入口。
7. 阶段读取发生加载、网络或持久化失败时显示真实失败和重试，不能回退到最近项目或伪造需求调研成功。
8. F011 可以读取本 Feature 的固定阶段顺序、项目级当前阶段、返回历史和待重新确认上界；它只能调用 F005 的受控推进/返回动作，并在成功后通知本 Feature 重新读取该 Workspace。

### 业务规则与边界

- 阶段状态使用 `requirements`、`solution`、`development`、`validation`、`pilot`、`handoff` 六个稳定项目级值；用户界面只显示对应中文产品名称。
- 当前阶段之前的阶段显示“已通过”，当前阶段显示“进行中”；人工返回后，当前阶段之后到待重新确认上界显示“待重新确认”，更晚阶段显示“未开始”。
- F010 自身不暴露改变当前阶段的 Client 或模型入口；所有阶段推进和返回均由 F005/F011 的人工动作提交。
- “可复制”是贯穿六阶段的最终完成原则，不作为额外阶段或进度值。
- POC、环境配置和持续运营分别属于方案设计、项目开发和部署试运行的内部工作，不新增顶层阶段。

## 异常与恢复

| 情况 | 用户可见状态 | 系统行为 | 恢复/重试 |
|---|---|---|---|
| Session 未归属项目 | 不显示项目阶段或提示先选择项目 | 不使用 cwd 或最近项目猜测归属 | 选择或创建真实项目会话 |
| 项目记录尚不存在 | 显示需求调研加载状态 | 为该 Workspace 初始化唯一项目阶段记录 | 初始化成功后显示第 1/6 阶段 |
| Host 或网络失败 | 显示“阶段状态加载失败” | 保持当前会话和页面可用，不缓存假成功 | 用户点击重试 |
| 阶段门已成功但页面缓存仍是旧 revision | 当前阶段短暂显示重新读取 | 只刷新发生变化的 Workspace，不改写 Host 状态，也不影响其他项目 | 读取成功后所有同项目会话显示已提交阶段；失败时提供重试 |
| 页面刷新或 Host 重启 | 短暂加载后恢复 | 从项目持久状态读取，不依赖页面内存 | 无需用户重新选择阶段 |

## 验收标准

### AC-F010-001 · 六阶段名称和顺序稳定

- 来源：REQ-001, NFR-005, PSC-002
- 对应 PRD 验收：AC-001
- Given FDE 已进入一个真实项目会话
- When F010 初始化或读取项目阶段，并由受支持页面呈现阶段定义
- Then 产品按需求调研、方案设计、项目开发、验证评估、部署试运行、验收移交保持固定六阶段顺序，并明确当前处于第几阶段

### AC-F010-002 · 空白和已开始会话都能识别当前阶段

- 来源：REQ-001, REQ-002, NFR-005, PSC-001, PSC-002
- 对应 PRD 验收：AC-001, AC-002
- Given 项目可能仍为空白，或已经产生对话内容
- When 用户进入该项目会话
- Then 空白状态显示与输入卡左右对齐的轻量阶段栏，清楚呈现当前阶段与一句行动提示；“查看项目进度”可打开当前项目详情；已开始状态在会话头部显示当前阶段，且不会出现会话内“交付流程”页签

### AC-F010-003 · 阶段按项目共享且可恢复

- 来源：REQ-001, NFR-007, NFR-008, PSC-002, PSC-004, PSC-011, PSC-014
- 对应 PRD 验收：AC-001
- Given 一个项目拥有两条会话，并存在另一个独立项目
- When 用户在会话、项目之间切换，或刷新页面、重启 Host
- Then 同项目会话显示同一当前阶段；阶段门成功后已打开的会话提示重新读取并显示新 revision；另一项目读取自己的状态，恢复过程不串项目且不要求重新设置

### AC-F010-004 · 查看阶段不能伪造推进

- 来源：REQ-001, NFR-005, NFR-008, PSC-002, PSC-012
- 对应 PRD 验收：AC-001, AC-002
- Given 当前阶段是需求调研且详细交付门尚未定义
- When 阶段状态被页面读取，或阶段状态读取失败
- Then 项目当前阶段保持需求调研；页面不显示可推进成功，不提供绕过交付门的动作，并对失败给出真实重试

### AC-F010-005 · 人工返回后的读模型一致

- 来源：REQ-012, NFR-005, NFR-007, NFR-008, PSC-002, PSC-011
- 对应 PRD 验收：AC-003, AC-010
- Given FDE 已在项目进度中把项目从某一阶段返回上一阶段
- When 同项目任一会话或项目进度重新读取阶段
- Then 它们显示同一新 revision 和当前阶段；项目进度还能区分待重新确认范围并读取最新返回记录，另一项目不受影响

## 开放问题

- 各阶段详细输入、候选产物、确认事项和交付门由对应 Feature 负责；多项目阶段、返回入口、预计周期和时间轴由 F011 负责。
