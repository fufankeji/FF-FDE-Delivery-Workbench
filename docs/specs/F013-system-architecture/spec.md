# F013 · 系统架构规格

## 目标与可观察结果

FDE 在第 2 阶段完成结果与范围定义、第 3 阶段完成真实环境调查并进入第 4 阶段方案设计后，可以让项目 Agent 根据已确认需求、现场约束和候选技术方案形成清晰的项目级系统架构，在“系统架构”中跨会话持续查看和修改，经人工确认后作为方案设计阶段产物，并按明确版本导出 SVG 或 PNG。

## 来源与范围

- 来源需求：REQ-018, REQ-023, NFR-001, NFR-003, NFR-005, NFR-007, NFR-008
- 来源总规格：PSC-002, PSC-005, PSC-006, PSC-007, PSC-011, PSC-014, PSC-020, PSC-027
- 对应 PRD 验收：AC-017, AC-022
- 当前切片包含：项目交付中的“系统架构”View；项目级结构化架构；节点、分组和关系；Agent 生成、读取和完整替换；自然语言修改；候选、待确认、已确认、受影响和已替代状态；版本与来源；同项目跨会话共享；缩放；SVG/PNG 导出；加载、空、校验、布局、保存和导出失败。
- 当前切片不包含：右侧项目步骤面板、完整项目任务计划、自由拖拽的 Excalidraw 编辑器、多人实时协作、自动扫描代码反推正式架构、把运行轨迹或 Trace 当作系统架构、自动推进方案设计阶段。

## 架构内容模型

| 内容 | 作用 | 示例 | 边界 |
|---|---|---|---|
| 分组 | 表达系统层次或责任边界 | 用户端、服务端、数据与外部系统 | 分组不是项目阶段 |
| 节点 | 表达可识别的系统组件 | Web 应用、API 服务、数据库、模型服务 | 不展示隐藏推理或临时工具调用 |
| 关系 | 表达组件之间的业务/技术连接 | HTTPS、事件、读取、写入、异步任务 | 每条边必须引用存在节点 |
| 摘要 | 说明当前架构解决的目标和主要约束 | 单体/服务边界、数据流、外部依赖 | 不替代详细技术方案文档 |
| 版本与状态 | 记录候选、确认和受影响关系 | v3、待确认、由需求变更影响 | 查看和导出不改变状态 |

## 用户旅程与状态

| 前置状态 | 用户动作 | 过程与反馈 | 可观察结果 | 下一步 |
|---|---|---|---|---|
| 方案信息尚不足 | 打开“系统架构” | 显示真实空状态 | 说明需要先完善需求和技术方案 | 返回对话补充信息 |
| 已有需求基线和候选方案 | 请求 Agent 生成系统架构 | Agent 提交完整结构化图，Host 校验后持久化 | 页面显示候选版本、摘要、分组、节点和关系 | 审阅或继续修改 |
| 架构需要调整 | 用自然语言说明变化 | Agent 读取当前版本并提交完整新候选 | 新版本显示变化，旧版本保留 | 提交确认 |
| 候选可作为研发依据 | FDE 记录确认 | 状态进入已确认，并关联确认依据 | 同项目所有会话看到确认版本 | 作为后续阶段门输入 |
| 上游需求或方案变化 | 项目产生影响事件 | 已确认架构标记受影响，不静默改写 | 页面提示需要重新评审 | 形成新候选并确认 |
| 需要分享或归档 | 导出 SVG/PNG | 对当前明确版本执行安全导出 | 下载文件与页面版本一致 | 继续项目工作 |

## 功能行为

### 页面和项目归属

1. “系统架构”作为项目交付中的独立 View，与“对话”“轨迹”“API 文档”并列；不占用右侧开发 Dock。
2. View 由当前 Session 打开，但架构按 WorkspaceId 保存；同项目任意普通会话显示同一当前版本，跨项目严格隔离。
3. 页面顶部显示架构标题、当前版本、状态、更新时间、缩放和导出；主体只呈现架构图，不混入任务步骤、Agent Trace 或评估图。

### 生成、修改与确认

1. Agent 生成架构时提交完整标题、可选摘要、分组、节点和关系；缺失 id 可以由稳定标签推导，但最终保存必须具有稳定身份。
2. Host 在发布前校验节点、分组、边引用、数量和文本上限；任何错误都拒绝整次候选，不保存半张图。
3. 自然语言修改由 Agent 先读取当前版本，再提交完整替代候选；“修改一条边”不能只向页面内存打补丁。
4. 新候选默认不进入已确认项目基线；FDE 明确确认后才变为 `confirmed`。
5. 查看、缩放、导出和切换会话不改变架构状态；确认架构也不自动通过方案设计阶段门。

### 呈现与导出

1. 架构图采用确定性自动布局，使同一结构在刷新和跨会话时保持稳定，不因随机布局改变用户理解。
2. 分组、核心组件、存储和外部系统使用一致而克制的视觉语义；明暗主题都保持可读。
3. 页面支持缩放、适合宽度和恢复 100%；大图允许平移/滚动，不裁掉节点或边。
4. SVG/PNG 导出使用当前明确版本，文件可独立打开；导出不包含脚本、凭据或未经授权外部资源。

## 异常与恢复

| 情况 | 用户可见状态 | 系统行为 | 恢复方式 |
|---|---|---|---|
| 当前项目无架构 | 显示空状态和生成建议 | 不用其他项目或运行 Trace 填充 | 返回对话请求生成 |
| Agent 输入无效 | 显示具体校验错误 | 拒绝整个新候选，保留旧版本 | 修正后重新提交 |
| 布局失败 | 显示无法生成图形 | 不发布半张图或覆盖旧版本 | 简化架构或修正关系后重试 |
| 持久化失败 | 显示保存失败 | 页面继续显示上一有效版本 | 重试保存 |
| 项目切换 | 新项目重新读取 | 取消旧请求，不保留旧项目可操作图 | 无需手动清理 |
| 导出失败 | 显示导出失败 | 不改变当前版本或确认状态 | 原位重试 |
| 已确认架构受影响 | 显示“需要重新确认” | 保留确认历史并建立影响状态 | 生成新候选后再次确认 |

## 验收标准

### AC-F013-001 · 系统架构是项目级产物

- 来源：REQ-018, NFR-007, NFR-008, PSC-005, PSC-011, PSC-014, PSC-020
- 对应 PRD 验收：AC-017
- Given 一个项目拥有两条会话，并存在另一个独立项目
- When Agent 在第一条会话生成架构，用户从第二条会话和另一个项目查看
- Then 同项目两条会话显示同一架构版本，另一项目保持自己的空状态或架构，任何页面都不按最近会话或路径串用

### AC-F013-002 · 架构生成与修改保留真实版本

- 来源：REQ-018, NFR-001, NFR-003, NFR-008, PSC-005, PSC-006, PSC-007, PSC-020
- 对应 PRD 验收：AC-017
- Given 当前项目已有一个候选或已确认架构
- When FDE 通过自然语言要求增加、删除或调整组件关系
- Then Agent 基于明确旧版本提交完整新候选，来源和变化可追踪；校验、布局或保存失败时旧版本不被覆盖，已确认状态不被静默继承

### AC-F013-003 · 架构与运行轨迹明确分离

- 来源：REQ-018, NFR-005, NFR-008, PSC-002, PSC-020
- 对应 PRD 验收：AC-017
- Given 当前项目同时存在 Agent Trajectory、工具调用或 Langfuse Trace
- When 用户打开“系统架构”
- Then 页面只展示经过结构化提交的设计架构，并明确其版本和状态；运行事件、Trace 和隐藏推理不会成为架构节点或已确认产物

### AC-F013-004 · 确认状态参与方案门但不单独推进阶段

- 来源：REQ-018, REQ-023, NFR-001, NFR-005, PSC-002, PSC-006, PSC-007, PSC-020, PSC-027
- 对应 PRD 验收：AC-017, AC-022
- Given 当前架构候选已经过 FDE 审阅
- When FDE 确认当前 revision、导出 SVG/PNG，或随后在项目进度检查方案设计门
- Then 确认记录引用明确版本，导出内容与该版本一致且可独立打开；只有当前 revision 为 `confirmed` 时才满足方案门的架构前置条件，但确认或导出本身都不推进阶段，导出失败也不改变架构状态

## 开放问题

- 方案设计阶段的其他必需产物已由 F018 冻结为项目 PRD 等五份固定 Markdown；F013 继续只拥有系统架构产物和确认状态，F005 读取 `confirmed` revision 作为阶段门前置条件，F013 自身不推进阶段。
- 第一版不提供手工拖拽画布；若后续确有直接编辑需要，再评估 `dsh-diagram`/Excalidraw，并作为独立范围变更处理。
