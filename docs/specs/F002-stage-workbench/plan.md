# F002 · 透明的当前阶段工作台实施计划

## 现有上下文与复用

- 当前实现与入口：`ui-fde-stage` 已有阶段条与项目进度，`ui-fde-project` 已有项目管理，`ui-conversation`、`ui-trajectory`、`ui-tool` 已能呈现会话和工具轨迹。
- 直接复用点：现有 FDE 快照、导航、会话状态、轨迹详情和主题能力。
- 必须保持的现有行为：对话、文件树、会话切换与 V1 阶段页面继续可达。
- 必须保持的 Product Spec 合同：PSC-002, PSC-005, PSC-007, PSC-009, PSC-021。

## 影响范围

| 路径/模块 | 当前职责 | 计划变化 | 对应 AC |
|---|---|---|---|
| `packages/client/ui-fde-stage` | 阶段导航与页面 | 建立统一阶段骨架和阶段专属中心视图承载区 | AC-F002-001, AC-F002-002 |
| `packages/client/ui-fde-project` | 项目管理 | 建立全部项目与单项目首页的同源投影 | AC-F002-001 |
| `packages/client/ui-conversation` | 对话交互 | 从工作项进入真实交付环境并回写结果 | AC-F002-001, AC-F002-002 |
| `packages/client/ui-trajectory`、`ui-tool` | 技术执行详情 | 作为可展开的第二层信息 | AC-F002-002 |
| `packages/fde/stage` | 阶段快照 | 提供工作台所需事实和分区状态 | AC-F002-001 |

## 实现方案

由 Host 从同一项目事实生成版本化快照，确定性投影为全部项目、单项目首页、当前阶段工作台和真实交付环境四层。全部项目负责行动优先级，单项目首页负责恢复现场认知，阶段工作台采用统一骨架与阶段专属中心视图，真实交付环境负责具体执行并回写稳定对象。执行轨迹建立业务步骤摘要与技术详情两层，不复制日志数据。

## 实施顺序

1. 定义四层产品形态共享的项目事实快照与错误语义。
2. 建立全部项目与单项目首页的同源投影。
3. 构建统一阶段骨架、阶段专属中心视图承载区、工作、产物、缺口和决定区。
4. 接入工作项到真实交付环境及执行结果回写。
5. 接入业务进度与可展开技术轨迹。
6. 验证能力显隐、加载失败和窄屏布局。

## 依赖与风险

| 依赖/风险 | 影响 | 应对 | 验证时机 |
|---|---|---|---|
| F001 项目身份未稳定 | 可能投影错误项目 | 所有查询强制携带项目身份 | 合同测试 |
| V1 页面信息结构不同 | 回归风险 | V2 使用版本化 slot，不移除 V1 入口 | UI 回归测试 |
| 技术轨迹淹没业务状态 | 用户仍不理解 | 默认折叠原始日志，固定业务摘要 | 组件测试 |

## 回退策略

新工作台通过 V2 生命周期启用；若呈现层失败，保留现有对话和 V1 页面入口，并显示明确加载错误，不回退到模拟或全局数据。

## 验收映射

| AC | 实现结果 | 最窄验证方法 | 预期证据 |
|---|---|---|---|
| AC-F002-001 | 两个工作面共享同一真实快照 | 运行 Host 快照与两个 UI 包定向测试 | 同一夹具状态一致，失败区域保持错误语义 |
| AC-F002-002 | 业务进度默认可懂、技术详情可展开 | 运行阶段工作台组件交互测试 | 推荐工作、执行步骤和详情层状态可验证 |
