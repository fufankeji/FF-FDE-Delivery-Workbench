# F002 · 透明的当前阶段工作台规格

## 目标与可观察结果

FDE 进入项目后无需理解底层 Skill 或插件，即可在一个当前阶段工作面中看懂阶段目的、已投入资料、当前与推荐工作、实时进展、产物、证据缺口和下一项人工动作；项目管理与交付工作台读取同一事实。

## 来源与范围

- 来源需求：REQ-002, REQ-006, REQ-008, REQ-010, REQ-025, REQ-027, NFR-004, NFR-013
- 来源总规格：PSC-002, PSC-005, PSC-007, PSC-009, PSC-021
- 本 Feature 包含：四层产品形态、统一阶段信息架构、同源一致投影、业务过程进度、技术详情展开、错误和未知状态。
- 本 Feature 不包含：具体阶段 Artifact 规则、工具执行器、最终视觉风格和装饰性经营图表。

## 四层产品形态

| 层级 | 核心任务 | 必须展示 | 不应成为默认内容 |
|---|---|---|---|
| 全部项目 | 判断今天先介入哪里 | 项目当前阶段、下一动作、待人工决定、风险、停滞、交付时间 | 只有项目数量、平均完成率或无行动含义的图表 |
| 单项目首页 | 快速恢复项目现场认知 | 当前状态、业务缘由、关键人员、风险、项目记录、成功标准、现场条件、八阶段路径和下一动作 | 当前阶段的全部执行细节 |
| 当前阶段工作台 | 理解并推进当前阶段 | 阶段主问题、推荐行动、执行过程、阶段专属中心视图、Artifact、证据、缺口和 FDE 决定 | 所有阶段共用一张通用文件清单或看板 |
| 真实交付环境 | 完成一项真实交付动作 | 对话、文件、代码、Diff、终端、浏览器、工具和轨迹 | 独立维护项目进度或阶段结论 |

四层页面必须由同一项目事实确定性投影。工作项从阶段工作台进入真实交付环境，执行结果再回写对应 Artifact、证据、风险、未决项或决定引用；报告、时间线和关系图不得成为独立事实源。

## 统一阶段页面合同

| 固定区域 | 回答的问题 | 阶段差异 |
|---|---|---|
| 阶段问题与状态 | 当前为什么做、处于什么状态 | 使用该阶段的真实业务问题与状态枚举 |
| 推荐与进行中工作 | 现在最应该做什么、系统正在做什么 | 按现有证据与能力路由得到一项主要行动 |
| 中心业务视图 | 这一阶段最重要的关系或变化是什么 | 八个阶段分别使用观察、合同、关系、架构、评估、Pilot、交接或改进视图 |
| Artifact 与证据 | 已形成什么、可信度如何 | 使用该阶段对象与证据类型 |
| 缺口与人工决定 | 还缺什么、由谁决定 | 显示阶段专属介入信号与 FDE 决定入口 |

## 用户旅程与状态

| 入口/前置 | 用户动作 | 过程与反馈 | 对象状态变化 | 可观察结果 | 下一步 |
|---|---|---|---|---|---|
| 打开全部项目 | 选择需介入项目 | 加载同一事实源的组合投影 | 无 | 看见下一动作、待决定、风险和交付时间 | 进入单项目首页 |
| 打开当前项目 | 恢复项目认知并选择工作 | 加载项目记录与当前阶段投影 | 无 | 看见当前状态、业务缘由、关键人员、风险、项目记录和下一动作 | 进入阶段工作台 |
| 打开当前阶段 | 查看并推进阶段工作 | 加载阶段专属中心视图 | 无 | 看见“为什么、正在做什么、得到什么、需要做什么” | 发起推荐工作或补输入 |
| 打开工作项 | 进入真实交付环境执行 | 绑定当前工作与项目范围 | 执行结果写回 | 文件、代码、运行和工具结果可回到阶段证据 | 返回阶段工作台评审 |
| Agent 执行中 | 查看业务进度 | 按计划、动作、观察、结果更新 | 执行轨迹追加 | 默认看业务步骤，可展开工具和日志 | 停止、继续或处理异常 |
| 快照读取失败 | 查看页面 | 保留已知事实并标记失败 | 无伪造状态 | 可见错误、范围和重试入口 | 重试读取 |

## 功能行为

### 主流程

1. Host 从同一项目事实生成全部项目、单项目首页、当前阶段和真实交付环境所需的版本化快照。
2. 全部项目先呈现待介入项目与下一动作；单项目首页再恢复项目背景、阶段路径、关键人员、风险和近期记录。
3. 当前阶段固定展示阶段问题、推荐工作、进行中工作、阶段专属中心视图、Artifact、证据、缺口和人工决定区。
4. 执行过程默认按业务步骤呈现；工作项可进入真实交付环境，工具名、命令、原始日志通过详情展开。
5. 真实执行结果写回项目事实后，四层页面重新读取并一致更新，不在页面间复制状态。

### 业务规则与边界

- 不适用的 API、架构、评估或观测入口不得常驻显示。
- 未知、未读取、未执行和失败不得转换成 0、空白或演示数据。
- 推荐工作说明目的、所需输入与预计产物，不要求用户选择 Skill 名称。

## 异常与恢复

| 情况 | 用户可见状态 | 系统行为 | 恢复/重试 |
|---|---|---|---|
| 部分区域读取失败 | 区域内错误与最后成功时间 | 其他已知区域继续展示 | 单独重试失败区域 |
| 当前阶段没有可执行能力 | 显示缺失前置条件 | 不展示虚假按钮 | 补资料、权限或返回阶段 |
| 工具日志过长 | 业务步骤保持简洁 | 原始日志折叠保存 | 用户按需展开或下载 |

## 验收标准

### AC-F002-001 · 四层页面共享真实项目事实

- 来源：REQ-002, REQ-006, REQ-010, NFR-004, PSC-002, PSC-005, PSC-009
- 对应 PRD 验收：AC-002, AC-006, AC-008
- Given 当前项目存在输入、候选产物、证据、缺口和读取失败状态
- When 用户在全部项目、单项目首页、当前阶段工作台和真实交付环境之间切换并完成一次真实动作
- Then 四层显示同一项目事实的不同业务投影，执行结果可回指工作项，失败不会变成零值、空白或其他项目数据

### AC-F002-002 · 可理解且分层的阶段执行过程

- 来源：REQ-008, REQ-025, REQ-027, NFR-013, PSC-007, PSC-021
- 对应 PRD 验收：AC-022, AC-024
- Given 当前阶段有推荐工作或正在执行的任务
- When 用户查看阶段工作台
- Then 默认界面说明业务目的、过程、结果和下一动作，只有适用能力出现，技术工具与原始日志可按需展开

## 开放问题

- 最终视觉样式在本 Feature 开发前用真实项目状态确认；本规格先冻结信息与状态合同。
