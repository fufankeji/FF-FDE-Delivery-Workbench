# F002 · 透明的当前阶段工作台规格

## 目标与可观察结果

FDE 进入项目后无需理解底层 Skill 或插件，即可在一个当前阶段工作面中看懂阶段目的、已投入资料、当前与推荐工作、实时进展、产物、证据缺口和下一项人工动作；项目管理与交付工作台读取同一事实。

## 来源与范围

- 来源需求：REQ-002, REQ-006, REQ-008, REQ-010, REQ-025, REQ-027, NFR-004, NFR-013
- 来源总规格：PSC-002, PSC-005, PSC-007, PSC-009, PSC-021, PSC-024
- 本 Feature 包含：四层产品形态、统一阶段信息架构、同源一致投影、业务过程进度、技术详情展开、错误和未知状态。
- 本 Feature 不包含：具体阶段 Artifact 规则、工具执行器、最终视觉风格和装饰性经营图表。

## 四层产品形态

| 层级 | 核心任务 | 必须展示 | 不应成为默认内容 |
|---|---|---|---|
| 全部项目 | 判断今天先介入哪里 | 项目当前阶段、下一动作、待人工决定、风险、停滞、交付时间 | 只有项目数量、平均完成率或无行动含义的图表 |
| 单项目首页 | 快速恢复项目现场认知 | 当前状态、业务缘由、关键人员、风险、项目记录、成功标准、现场条件、八阶段路径和下一动作 | 当前阶段的全部执行细节 |
| 当前阶段工作台 | 理解并推进当前阶段 | 阶段主问题、推荐行动、执行过程、阶段专属中心视图、Artifact、证据、缺口和 FDE 决定 | 所有阶段共用一张通用文件清单或看板 |
| 真实交付环境 | 完成一项真实交付动作 | 对话、文件、代码、Diff、终端、浏览器、工具和轨迹 | 独立维护项目进度或阶段结论 |

四层页面必须由同一项目事实确定性投影。工作项从阶段工作台进入真实交付环境，执行结果再回写对应 Artifact、证据、风险、未决项或决定引用；报告、时间线和关系图不得成为独立事实源。

### 全部项目的 V2 默认入口

全部项目页使用“项目中心”而不是经营统计看板作为默认入口。页面提供“新建项目”操作；项目中心与常驻左侧栏复用同一个结构化创建表单和创建状态，不维护第二套表单。“待我处理”与“全部项目”由项目集合中的筛选操作切换，不在首屏重复设置范围页签。

- “待我处理”默认打开，并按真实项目事实说明 AI FDE 当前进度、已形成的产物或证据、等待 FDE 决定的原因和建议下一步。
- 页面顶部使用“项目交付 / 项目中心”位置说明、项目中心标题和一句业务说明建立页面身份，右上角账号、通知和帮助区域在当前版本仅作静态界面展示，不接入登录、消息或权限逻辑。
- 首屏以四项紧凑指标和一张深色优先事项卡展示真实项目数、待人工决定数、运行中会话数、已登记周期与最优先的人工动作。八阶段位置由下方项目卡片逐项呈现，顶部不再重复阶段计数。
- 待处理项目同时提供“进入项目”和“查看阶段与产物”操作，不能只用说明文字代替可执行入口。
- “待我处理”和“全部项目”共用一套查看方式：默认使用双列紧凑卡片，并允许切换为列表；筛选与排序和视图切换固定在项目集合标题右侧。交付时间线由下方日期区域进入，避免把四种同级控制挤在一个按钮组内。
- 待处理卡片以“项目身份与阶段、最近进展、需要谁决定、下一动作”为主信息；八阶段位置、近期会话、运行状态和交付周期保持可见，但不得把单个项目扩展成整页看板。桌面端一行两张，窄屏自动单列，每张卡只保留一个主要动作“进入项目”和一个次要动作“查看产物”。
- 列表视图用于快速比较多个项目，时间线用于查看已登记的交付周期；三种视图读取同一批真实项目和同一份项目事实，点击真实项目进入现有单项目首页。
- 新项目创建成功后先打开该项目的单项目管理首页，不创建或打开 Session；只有用户显式点击“进入项目”或“进入项目交付”，系统才恢复现有普通 Session，或在没有可恢复会话时创建首个空白 Session，并进入 DeepSeek Harness 真实交付环境。
- 阶段分布、健康圆环、趋势图等汇总图表不占用默认首屏；在缺乏足够真实数据时不得用演示数据补齐视觉效果。
- 项目阶段推进继续由 FDE 人工确认；AI FDE 的运行、读取或产物数量只能作为决定依据，不能自动替代人工阶段门。

## 统一阶段页面合同

| 固定区域 | 回答的问题 | 阶段差异 |
|---|---|---|
| 阶段问题与状态 | 当前为什么做、处于什么状态 | 使用该阶段的真实业务问题与状态枚举 |
| 推荐与进行中工作 | 现在最应该做什么、系统正在做什么 | 按现有证据与能力路由得到一项主要行动 |
| 中心业务视图 | 这一阶段最重要的关系或变化是什么 | 八个阶段分别使用观察、合同、关系、架构、评估、Pilot、交接或改进视图 |
| Artifact 与证据 | 已形成什么、可信度如何 | 使用该阶段对象与证据类型 |
| 缺口与人工决定 | 还缺什么、由谁决定 | 显示阶段专属介入信号与 FDE 决定入口 |

### 阶段工作台与真实交付环境的主次

工作台必须保持一条清晰的产品叙事：**阶段工作台是主叙事，AI FDE 是常驻执行器，技术工作区按需打开，Artifact 是进度锚点，FDE 决定是阶段门**。

真实交付环境顶部页签固定按“项目工作台、Agent对话、运行轨迹”排列，“项目工作台”始终位于第一项；后续按阶段出现的系统架构、API 文档、用量分析和评估优化等页签只能追加在这三项之后，不得改变前三项名称和顺序。其中“系统架构”从第 4 阶段“设计方案并完成端到端纵向切片”开始出现，第 2 阶段定义业务结果与范围、第 3 阶段调查真实环境时均不提前展示。

1. 左侧阶段导航只回答“当前在哪里”，主页不再重复项目名、阶段编号或整条八阶段路径。当前或正在查看的阶段项本身是工作方法目录开关，默认收起；进入项目后后台预取一次固定的完整方法目录，用户点击或切换阶段时直接从当前页面缓存展开该阶段的全部真实方法，不再经过“本阶段工作方法”二级入口，也不得为每次切换重复请求；首次预取失败时保留显式重试。展开内容超过可用高度时，项目身份区保持可见，交付路径区域提供独立纵向滚动。导航支持一键收起当前阶段的展开内容，以及一键缩放整个项目侧栏；这些动作只改变界面布局，不得改变项目当前阶段、正在查看阶段或任何交付记录。
   会话顶部的紧凑阶段标识与左侧导航使用同一套八阶段名称和序号；不得继续显示旧版六阶段文案。
2. 主页围绕当前阶段依次展示业务主问题、工作路径、当前工作、Artifact、证据缺口和人工决定；不使用同权重的数据卡片堆叠。
3. DeepSeek Harness 原生输入框始终是唯一自然语言执行入口。阶段页可提供明确的推荐动作，但推荐动作只能切换到 Agent 对话并预填一段可编辑的业务问题，必须等待用户补充或确认后手动发送；不得把 Skill 名称、证据字段、上下文限制或阶段控制规则伪装成用户消息自动发送，也不得创建第二个文本框、发送按钮或独立对话系统。
4. 对话和工具轨迹承担真实执行过程；阶段页仅投影业务进度、结果、证据和缺口，不伪造“正在运行”状态。
5. 文件树、代码、Diff、终端和浏览器属于技术工作区。进入项目工作台时不默认展开；用户从阶段推荐动作进入 Agent 对话时，左侧阶段导航自动收起，右侧当前项目文件树自动展开，让对话与项目文件成为主要操作区。用户仍可手动恢复两侧面板。
6. Artifact 是业务对象，文件只是其中一种载体。Artifact 可引用客户原始资料、访谈记录、工具输出、工程结果和人工确认；存在文件不等于 Artifact 已被客户或 FDE 确认。
7. 桌面端阶段页采用“左侧执行、右侧项目记录、按需提交评审”的空间结构：阶段目标、当前工作、阶段中心视图和原生输入框属于左侧执行列；右侧“项目记录轴”只收纳当前阶段和已经由 FDE 推进的历史阶段，不混入未开始阶段。记录轴默认折叠并按已有阶段数量自适应高度，不得用贯穿整页的空轨道占位；已有阶段超过可见高度时，阶段节点列表必须独立纵向滚动，不能裁掉后续节点或锁死页面。每个节点显示阶段序号、当前或已完成状态和必需记录完成数，悬浮说明阶段名称与状态。点击节点展开该阶段的输入、产物和人工结论；查看历史记录不得改变项目当前阶段。
8. 展开的项目记录面板支持切换当前阶段、已完成阶段与全部已有记录。当前阶段允许预览材料，并在达到评审条件后显示紧凑的提交动作；已完成阶段只读展示当时的输入依据、阶段产物和“已由 FDE 推进”结论；全部记录只做阶段级汇总。关闭面板后恢复紧凑记录轴，左侧执行列获得剩余宽度。原生输入框不得横跨记录列，页面不得用整页底部占位制造无业务含义的空白。
9. “现在先做”区域只设置一个高优先级主动作来启动当前步骤；资料分析与事实冲突处理作为辅助动作。原生输入框与左侧执行列对齐，记录轴折叠后随执行列扩展。桌面端内容不足一屏时，由当前阶段中心视图和记录复核面承接剩余工作空间，不在内容与输入框之间裸露大块背景。产物计数必须明确标注必需项，避免可选产物造成列表数与完成分母不一致。
10. 八个阶段共用同一状态与评审壳：Host 读取 `.fde/stages/<stage-id>.json` 和该阶段固定产物路径，计算当前工作、完成度、阻塞与可评审状态；页面不得以会话消息或文件树视觉状态代替扫描结果。
11. Agent 运行结束、上传资料、写入产物、返回工作台和保存人工决定后，当前阶段、项目记录轴、中心业务视图及项目中心必须从同一快照刷新。读取失败显示明确错误和重试入口，不保留错误的成功计数。
12. 左侧八阶段名称均可用于浏览，但当前、已完成和未开始阶段不得共用同一种内容模板。已完成阶段只读复盘当前项目真实存在的输入依据、工作记录、阶段产物和人工阶段结论；未登记事实明确显示“未登记”，不得用模板内容补齐。
13. 未开始阶段只显示“本阶段尚未开始”、项目当前阶段、阶段目标、开始条件和预计产物，不显示已开展的工作步骤、真实输入、执行、生成、评审或确认动作。侧栏与右侧工作台都必须分别标明“项目当前阶段”和“正在查看阶段”，并提供返回当前阶段入口。
14. 浏览其他阶段是只读行为，不调用阶段迁移接口。已完成阶段如需补做，用户必须返回当前阶段并通过正式阶段返回流程处理。
15. 达到可评审状态后，项目记录面板出现“提交 FDE 评审”；点击后在当前项目内打开评审模式，逐项展示必需产物、未确认事实和关键阻塞。只有二次确认的 Go 改变阶段，Revise、Narrow 与 Stop 只记录相应决定并保持或返回到明确阶段。
16. 每阶段交付一套可直接复制的中文手动测试提示词；提示词按四个业务步骤组织，要求产物写入固定目录，并明确“生成候选材料不代表客户确认或阶段完成”。
17. 第三阶段进行中使用环境调查驾驶舱，不沿用第一、二阶段的线性证据链：以四项调查总览、系统与数据关系、AI 动作边界矩阵、数据适用性、独立治理审查、阻塞与固定产物为中心；所有节点、连接、权限和结论只从结构化阶段状态投影。驾驶舱已经承接固定产物和阶段门时，不再额外显示右侧项目记录轴。第三阶段已完成后，历史查看必须保留同一套环境调查驾驶舱、信息架构和真实阶段投影，只增加已完成与返回当前阶段提示，并移除启动、刷新、提交评审和返回上一阶段等写操作；不得降级成通用三栏历史摘要。
18. 第二阶段以及复用共享阶段工作台的第四至第八阶段，在形成完整阶段快照后，历史查看必须继续使用各自原有工作台和真实记录，只切换成只读状态并提供返回当前阶段入口；不得因为项目已经推进就替换成另一套通用摘要。旧项目若只有精简历史快照、缺少工作路径或产物结构，则继续使用兼容的只读归档视图，不能因字段缺失导致页面报错。

| 入口/前置 | 用户动作 | 过程与反馈 | 对象状态变化 | 可观察结果 | 下一步 |

| Agent 执行中 | 查看业务进度 | 按计划、动作、观察、结果更新 | 执行轨迹追加 | 默认看业务步骤，可展开工具和日志 | 停止、继续或处理异常 |

## 功能行为

### 主流程

1. Host 从同一项目事实生成全部项目、单项目首页、当前阶段和真实交付环境所需的版本化快照。
2. 全部项目先呈现待介入项目与下一动作，同时允许复用统一表单创建项目；创建成功后打开单项目首页，不隐式启动 Session。
3. 单项目首页恢复项目背景、阶段路径、关键人员、风险和近期记录；只有显式“进入项目”动作才打开真实交付环境。
4. 当前阶段固定展示阶段问题、推荐工作、进行中工作、阶段专属中心视图、Artifact、证据、缺口和人工决定区。
5. 执行过程默认按业务步骤呈现；工作项可进入真实交付环境，工具名、命令、原始日志通过详情展开。
6. 真实执行结果写回项目事实后，四层页面重新读取并一致更新，不在页面间复制状态。

### 业务规则与边界

- 不适用的 API、架构、评估或观测入口不得常驻显示。
- 未知、未读取、未执行和失败不得转换成 0、空白或演示数据。
- 推荐工作说明目的、所需输入与预计产物，不要求用户选择 Skill 名称。
- 项目集合的卡片、列表和时间线只是同一事实的不同排布，切换视图不能改变项目范围、阶段状态或人工决定。

## 异常与恢复

| 情况 | 用户可见状态 | 系统行为 | 恢复/重试 |
|---|---|---|---|
| 部分区域读取失败 | 区域内错误与最后成功时间 | 其他已知区域继续展示 | 单独重试失败区域 |
| 当前阶段没有可执行能力 | 显示缺失前置条件 | 不展示虚假按钮 | 补资料、权限或返回阶段 |
| 工具日志过长 | 业务步骤保持简洁 | 原始日志折叠保存 | 用户按需展开或下载 |

## 验收标准

### AC-F002-001 · 四层页面共享真实项目事实

- 来源：REQ-002, REQ-006, REQ-010, NFR-004, PSC-002, PSC-005, PSC-009
- 对应 PRD 验收：AC-002, AC-006, AC-008
- Given 当前项目存在输入、候选产物、证据、缺口和读取失败状态
- When 用户在全部项目、单项目首页、当前阶段工作台和真实交付环境之间切换并完成一次真实动作
- Then 四层显示同一项目事实的不同业务投影，执行结果可回指工作项，失败不会变成零值、空白或其他项目数据

### AC-F002-002 · 可理解且分层的阶段执行过程

- 来源：REQ-008, REQ-025, REQ-027, NFR-013, PSC-007, PSC-021
- 对应 PRD 验收：AC-022, AC-024
- Given 当前阶段有推荐工作或正在执行的任务
- When 用户查看阶段工作台
- Then 默认界面说明业务目的、过程、结果和下一动作，只有适用能力出现，技术工具与原始日志可按需展开

### AC-F002-003 · 项目中心优先呈现人工行动

- 来源：REQ-002, REQ-010, NFR-004, PSC-002, PSC-005
- 对应 PRD 验收：AC-002, AC-008
- Given 当前隔离工作区存在一个或多个真实项目
- When 用户进入工作台默认页
- Then 页面默认打开“待我处理”和双列紧凑卡片；首屏以真实项目数据展示当前优先事项、项目数、待人工决定、运行中会话和已登记周期，优先事项可直接进入对应项目处理；页面身份区具有位置说明、标题、新建项目入口和静态账号展示，但静态账号不产生登录、消息或权限行为；顶部不重复下方卡片已经呈现的八阶段位置或阶段计数；逐项目展示阶段位置、最近进展、真实产物或证据、最近活动、运行状态、待决定原因和下一动作，并提供进入项目及查看阶段产物的操作；项目集合可切换卡片与列表，可筛选待处理或全部项目并按优先事项或最近更新排序，下方分别展示最近活动和交付日期入口；切换后项目事实与范围不变；项目集合具有独立视觉边界并承接首屏剩余空间，所有集合视图与页头使用同一最大内容宽度，桌面端不得产生页面级横向溢出；新建成功先进入单项目管理首页且不创建 Session，只有显式进入项目后才打开真实交付环境；切换“全部项目”后可进入现有单项目首页，且默认首屏不显示演示数据或无行动含义的组合图表

### AC-F002-004 · 阶段状态、产物和人工评审同源同步

- 来源：REQ-003, REQ-006, REQ-008, REQ-025, NFR-002, NFR-004, PSC-004, PSC-005, PSC-009, PSC-024
- 对应 PRD 验收：AC-003, AC-004, AC-006, AC-022
- Given 当前项目处于任意 V2 阶段，Agent 可能生成、修改或删除阶段状态及产物
- When Agent 运行结束或用户返回工作台并提交人工评审
- Then 页面重新扫描真实项目文件，准确更新四步状态、中心业务视图和产物栏；缺失、无效和失败保持原义；只有当前项目内 FDE 二次确认才迁移阶段

### AC-F002-005 · 八阶段可查看但不越权推进

- 来源：REQ-008, REQ-025, NFR-004, PSC-021
- 对应 PRD 验收：AC-022, AC-024
- Given 当前项目处于八阶段中的任一阶段
- When 用户从左侧交付路径点击已完成阶段或后续阶段
- Then 当前阶段保持独立标记且不发生迁移；已完成阶段只读展示当前项目真实输入依据、工作记录、已有产物和 FDE 人工阶段结论，缺少的事实标记未登记；未开始阶段只显示尚未开始、当前项目阶段、阶段目标、开始条件和预计产物，不展示已执行过程或任何执行、生成、评审及确认推进入口；用户可一键返回当前阶段
