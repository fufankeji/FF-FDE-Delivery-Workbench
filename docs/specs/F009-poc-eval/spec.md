# F009 · 阶段 5：PoC 与 Eval 规格

## 目标与可观察结果

FDE 对同一候选版本运行代表案例、边界案例、对抗案例、模拟、确定性测试、NFR 检查和 UAT，用真实执行结果判断最高风险假设；未运行、失败、例外和人工接受必须分别保存，不能用文件数量或 Agent 自评替代验证。

第五阶段保留“运行 PoC 与 Eval”名称，核心是依据第四阶段确认的方案在 DSH 中开发实际项目，再以测试和阶段验收判断是否进入下一阶段。本工作台只展示受测范围与版本、运行情况、指标与证据、待解决问题及阶段验收，不另建 IDE、代码生成引擎或工作流执行器。本轮适配不包含开发当前测试案例的业务系统。

## 来源与范围

- 来源需求：REQ-003, REQ-006, REQ-007, REQ-022, REQ-025, REQ-026, REQ-028, NFR-002, NFR-004, NFR-011, NFR-013, NFR-014
- 来源总规格：PSC-003, PSC-005, PSC-006, PSC-018, PSC-021, PSC-022, PSC-023, PSC-024
- 本 Feature 包含：候选版本固定、评估案例与数据、执行清单、模拟／Eval／测试／UAT、失败归因、验收门禁和 FDE 决定。
- 本 Feature 不包含：用一套 LLM 指标强行评估所有软件、生产授权、Pilot 运行或自动判定项目成功。

## 功能行为

### 第五阶段有效信息工作台

1. 首页只组织阶段有效信息：本轮受测范围与候选版本、运行情况、指标结果、待解决问题和阶段验收。开发仍在已有 Agent 对话中进行，不再增加开发区、任务看板或开发进度百分比。第四阶段方案和切片记录作为按需展开的依据。
2. 准备／更新指标和重新验证按钮只预填当前项目的 DSH 对话指令，用户确认发送后才执行；沿用现有 Agent 对话入口，不增设开始开发流程。刷新和进入页面不发起开发、测试或模型调用。
3. 项目运行区域复用既有启动、停止、预览、终端操作和同一运行快照。明确区分未启动、启动中、运行中、停止中和受阻；启动成功不等于开发完成。系统架构和评估优化保留原入口。预览使用 F002 的平台隔离入口，不为本阶段或业务项目单独修改嵌入白名单。
4. 测试区域可随时查看和准备；正式测试需要可识别的候选版本及其文件指纹。指标来源、方法与阈值、实际结果、执行版本和证据分别显示。修改源码、环境、指标定义或候选版本后，旧结果显示过期。
5. 本阶段测试面只汇总项目记录及链接真实证据，不冒充通用测试执行器；现有 Agent Trial 是可用验证手段之一，不替代接口、页面与业务流程测试。必要的专项验证由 DSH 执行项目自身测试命令。
6. 缺失、结构错误、重复 ID、缺少证据、必测项未运行／失败／警告、过期版本均阻止阶段验收；非必测项仍保留结果和风险。FDE 在查看缺口和证据后明确确认推进，不因查看页面或刷新而改变阶段。
7. 项目记录按需展开，不再用右侧常驻窄栏挤压主体；主页面使用自然纵向滚动并为输入框保留空间。历史第五阶段使用同样视图只读查看，保留返回当前阶段入口。

### 主流程

1. 固定候选版本、配置、模型／规则版本、环境、数据集和评估范围。
2. 从 Workflow Charter、验收条件、NFR、风险和客户案例生成验证方案；由 FDE 补充或修改。
3. 对当前机制选择相应方法：模型／Agent 使用 AI Eval，确定性软件使用等价业务测试与技术验证。
4. 通过 DeepSeek Harness 工具逐项执行，保存输入、输出、日志、指标、评分、失败和证据链接。
5. 关联 UAT 参与者、实际任务与人工结论，未执行项目保持未运行而非零失败。
6. 方法层给出 Accept／Inconclusive／Reject 建议，FDE 决定进入 Pilot、返回方案／开发、收窄或停止。

### 业务规则与边界

- 模拟、Eval、UAT 和门禁必须关联同一候选版本与适用范围；任何输入变化都触发相应结果过期。
- 评估案例必须同时包含正常、边界、失败／对抗和人工接管条件。
- 评分器、人工评审和确定性断言分别记录；总分不能掩盖安全、权限或关键业务失败。

## 异常与恢复

| 情况 | 用户可见状态 | 系统行为 | 恢复/重试 |
|---|---|---|---|
| 缺少客户样例或正式阈值 | 评估方案未就绪 | 不运行伪造数据替代正式验收 | 补样例、阈值或标记为探索性运行 |
| 执行中断 | 部分完成 | 保存已完成证据与未运行项 | 从未完成项继续或新建一轮 |
| 评分器不可用 | 该项失败 | 不将无结果记为通过 | 修复评分器或转人工评审并记录 |

## 验收标准

### AC-F009-001 · 验证工作按候选版本执行且过程透明

- 来源：REQ-006, REQ-007, REQ-022, REQ-025, REQ-026, NFR-004, NFR-013, NFR-014, PSC-005, PSC-006, PSC-018, PSC-021, PSC-022
- 对应 PRD 验收：AC-019, AC-022, AC-023
- Given 阶段 4 已确认候选方案与最窄纵向切片
- When 用户生成、确认并运行验证方案
- Then 平台固定版本与范围，按机制选择必要方法、工程能力和工具，持续展示计划、动作、结果、失败与下一项人工动作

### AC-F009-002 · 验证证据不被美化且阶段由 FDE 决定

- 来源：REQ-003, REQ-028, NFR-002, NFR-011, PSC-003, PSC-018, PSC-023, PSC-024
- 对应 PRD 验收：AC-003, AC-019, AC-025
- Given 一轮模拟、Eval、测试或 UAT 已结束
- When 系统形成验证报告并由 FDE 评审
- Then 未运行、失败、例外和通过分别保留并回指同一候选版本，方法结论不自动推进，只有 FDE 决定进入受控 Pilot

## 本轮适配验收

### AC-F009-003 · 工作台展示有效信息并复用既有操作

- 来源：REQ-025, REQ-026, NFR-004, NFR-013, PSC-021, PSC-022
- 对应 PRD 验收：AC-022, AC-023
- Given 第五阶段尚无验证记录，或已存在真实版本、指标和项目运行记录
- When 用户进入、刷新、准备验证或使用运行入口
- Then 显示真实版本与验证状态、不出现开发任务面板；测试指令只预填 DSH 对话；运行操作复用已有能力，不执行当前客户项目、不另起开发引擎；无窄记录栏，保留历史只读与旧阶段入口
- 信息页按受测对象、项目运行、验证结果、阶段验收分组；页面独立滚动并保留原生输入框的高度预留，补充记录和验证操作进入现有 Agent 对话输入。所有阻塞原因可展开查看，长记录和返回原因表单不能被底部固定区域遮挡。

### AC-F009-004 · 受测版本与测试证据共同约束人工阶段验收

- 来源：REQ-003, REQ-006, REQ-022, NFR-002, NFR-004, PSC-005, PSC-018, PSC-024
- 对应 PRD 验收：AC-003, AC-006, AC-019
- Given 同一项目有候选文件和测试指标
- When 结果缺失、失败、指纹变化、证据不可读，或本轮证据已具备后由 FDE 确认
- Then Host 与页面一致拒绝无证据／旧版本推进，合法状态才开放人工确认；文件存在与服务启动不单独代表验收通过
