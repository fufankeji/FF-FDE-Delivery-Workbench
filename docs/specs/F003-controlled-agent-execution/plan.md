# F003 · 受控 Agent 执行实施计划

## 现有上下文与复用

- 当前实现与入口：DeepSeek Harness Session、Interaction、Tool、Workflow Run 和 Conversation 已保存模型与工具事件。
- 直接复用点：现有 Agent Loop、会话日志、工具注册、权限检查、用户问题、任务和轨迹 UI。
- 必须保持的现有行为：普通对话、现有工具调用和 Session 日志格式保持可用；不改 Agent Loop。
- 必须保持的 Product Spec 合同：PSC-011, PSC-012, PSC-013, PSC-014。

## 影响范围

| 路径/模块 | 当前职责 | 计划变化 | 对应 AC |
|---|---|---|---|
| Session/Interaction Host 包 | 会话与事件持久化 | 增加 operation 边界、终态和执行上限 | AC-F003-001, AC-F003-003 |
| Tool 与权限相关包 | 工具发现和调用 | 记录最小授权、输入范围和验证证据 | AC-F003-001 |
| Context/Source 与 `fde/source` | 资料引用 | 区分项目归档和会话激活 | AC-F003-002 |
| `ui-conversation`、`ui-workflow-run` | 请求与运行反馈 | 显示边界、等待、停止和终态 | AC-F003-001, AC-F003-003 |
| `ui-tool`、`ui-trajectory`、`ui-user-questions` | 详情与人工输入 | 提供审计、展开和授权交互 | AC-F003-001, AC-F003-002, AC-F003-003 |

## 实现方案

保持现有 Agent Loop，由外围 operation 合同将一次用户目标与多个 Session 事件关联。执行前计算项目、上下文和工具上限；执行中把动作、观察和验证写入 Session；等待授权或停止时进入明确终态。上下文激活通过项目内引用记录，不复制跨项目数据。

## 实施顺序

1. 定义 operation、执行上限和终态合同。
2. 补齐工具审计与权限拒绝事件。
3. 分离项目归档和会话激活上下文。
4. 接入闭环观察、验证、停止和等待状态。
5. 在现有对话与轨迹 UI 中呈现并验证。

## 依赖与风险

| 依赖/风险 | 影响 | 应对 | 验证时机 |
|---|---|---|---|
| 改动 Agent Loop 造成上游冲突 | 升级困难 | 只扩展插件、Session 事件和 UI slot | 代码评审 |
| 工具返回缺少结构化验证 | 无法区分完成与声称完成 | operation 保存观察和验证结果 | 工具集成测试 |
| 停止后仍有后台动作 | 产生非预期副作用 | 调度检查取消信号并记录晚到事件 | 取消测试 |

## 回退策略

operation 元数据采用附加事件；若新编排不可用，普通 Harness 对话与既有工具路径继续运行，新 UI 显示降级说明并保留 Session 日志。

## 验收映射

| AC | 实现结果 | 最窄验证方法 | 预期证据 |
|---|---|---|---|
| AC-F003-001 | 权限内执行且工具全程可审计 | 运行 operation 与工具权限定向测试 | 允许、拒绝和确认三类调用均有完整事件 |
| AC-F003-002 | 归档与激活上下文独立 | 运行 source/context 项目隔离测试 | 状态分别变化，跨项目引用被拒绝 |
| AC-F003-003 | 闭环可停止并明确终态 | 运行成功、失败、等待、停止夹具 | 每条执行只有合法终态且无无限重试 |
