# 第二步：还原实际流程

只复制下面提示词到同一个 Agent 会话：

```text
我补充一组客户现场信息：

- 售后人员通过企业微信收到客户问题，常见内容是设备型号、故障码和使用异常；
- 售后人员先到共享文件夹里查产品手册、维修 SOP 和历史答复，找不到时再问资深工程师；
- 共享文件夹里有多个版本的 PDF 和 Word，文件名不统一，有时会找到过期内容；
- 最近一个案例是客户询问“X200 设备出现 E27 故障码怎么办”。新人查了约 15 分钟，随后询问资深工程师，总共约 25 分钟才回复；
- 正常情况下由售后专员回复，无法判断时由资深工程师接手；回复完成后没有统一记录这次答案是否有效；
- 售后主管负责这项工作的业务结果，产品经理确认资料是否有效，IT 只负责本地部署环境；
- 客户资料不能上传到公网。

请基于这些信息，还原一个“售后问题查询与回复”的候选工作流，写清触发条件、参与人、正常步骤、异常步骤、人工接手方式和当前最明显的问题。无法从现有信息确认的内容请明确标为待确认，不要开始设计解决方案。
```

## 本步观察点

- “待确认业务流程”应开始出现真实工作流，而不是技术实施步骤；
- 正常路径、异常路径和人工接手应被区分；
- 公网限制应作为现场约束保留；
- 不应把尚未验证的客户说法自动标记为事实。
