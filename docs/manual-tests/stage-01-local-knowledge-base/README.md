# 第一阶段手动测试：本地知识库项目

## 测试目标

用一个简单但接近真实客户现场的“售后本地知识库”需求，验证第一阶段能否完成以下链路：

1. 接收客户的模糊诉求；
2. 通过对话还原真实工作流程；
3. 判断问题是否值得继续投入；
4. 形成三项第一阶段必备记录，等待 FDE 人工确认。

本轮只测试第一阶段，不测试方案设计、技术选型、项目开发或后续阶段。

## 建议测试项目

- 项目名称：`售后知识库试点`
- 所属企业：`星海设备有限公司`
- 项目目录：选择一个新的空目录
- 当前阶段：`阶段 1/8 · 发现高价值问题`

## 使用顺序

在同一个项目、同一个 Agent 会话中，依次打开并复制下面四份文件里的提示词：

1. [01-听客户怎么说.md](./01-听客户怎么说.md)
2. [02-还原实际流程.md](./02-还原实际流程.md)
3. [03-确认是否值得做.md](./03-确认是否值得做.md)
4. [04-形成阶段记录.md](./04-形成阶段记录.md)

每次等待 Agent 完成当前回答后，再复制下一步。测试过程中不需要另外编写长提示词；如果 Agent 追问，下一份提示词已经提供了主要补充信息。

## 第一阶段通过时应看到

- “待确认业务流程”中出现至少一个候选工作流；
- 右侧三项必备记录均已形成并可打开查看：
  - 客户现状记录；
  - 待确认事项；
  - 业务流程说明；
- 记录中能够区分已确认、推断和仍待确认的事实；
- 系统没有因为文件生成而自动进入第二阶段；
- 由 FDE 阅读记录后，手动决定继续调查、缩小范围、停止，或确认进入下一阶段。

如果任一页面状态、文件预览、候选工作流或人工确认入口与上述结果不一致，就暂停后续操作并记录实际现象，用于继续修复。
