适用于任意当前项目。具体开发在已有 Agent 对话中进行，项目工作台只展示受测范围与版本、运行情况、指标证据、问题与阶段验收。不要为查看页面而启动项目或伪造测试数据。

## 1. 生成验证方案

```text
请加载 verification-plan，基于当前项目的业务验收条件、第四阶段已确认方案和实际实现，整理本轮受测范围、版本、代码/配置/测试数据文件清单、环境和必要指标。写入 fde-deliverables/05-poc-eval/evaluation-plan.md，并按 Skill 的准确结构同步 .fde/stages/evaluation.json 的 evaluation.candidate 和 evaluation.testing。指标记录来源、方法、阈值及是否必测，缺少客户样例或阈值时明确标记；不要创建开发任务清单。这次只准备记录，不开发项目、不运行测试、不启动服务。
```

## 2. 确认评估边界

```text
请核对评估计划中的候选版本、数据范围、阈值、评分方式、验证人和权限，把尚未确认的项列清楚。使用 project_evaluation_get 读取本轮指纹和缺口；该指纹只覆盖显式受测文件清单，未覆盖的范围不能宣称已验证。没有正式阈值的结果只能作为探索性结果，不代替人工批准。
```

## 3. 运行并记录真实结果

```text
请按已确认的 evaluation-plan.md 运行当前项目本轮有权执行的验证。开始前通过 project_evaluation_get 取得 testing.fingerprint，实际运行后保存原始日志和结果，把对应指纹及各项 metricId/status/value/evidenceRefs 写入 evaluation.testing.run，并形成 evaluation-report.md 和 evaluation-baseline.md。测试方法按目标系统选择，Agent Trial 不能替代全部项目验证。未运行、失败、警告分别记录；不要把无证据的项目记为通过。需要外部授权、生产操作或付费调用时先询问。
```

## 4. 整理给 FDE 评审

```text
请核对三份固定记录和 project_evaluation_get 返回的当前版本证据，保留失败、陈旧结果和未运行项。只有本轮必测结果有实际值与有效证据、固定产物齐全且无关键阻塞时，才更新阶段记录为 review-ready，保留 plan/cases/run/conclusion 固定工作项。不要代替 FDE 确认或改变生命周期。
```

工作台刷新后应能逐项查看来源和结果文件；只有证据已具备时才开放“提交 FDE 阶段验收”，二次确认后进入第六阶段。后续修改受测文件、版本、环境或指标定义时，旧结果须显示“结果已过期”，不能继续用于推进。首次准备指标与真实测试分开执行，不自动发送对话。

## 5. 已有项目数据如何加载

第五阶段不是上传一个 JSON 就自动启动业务系统。工作台读取已登记 Workspace 对应项目目录中的文件；项目服务、阶段记录和人工决定分别管理。

| 展示内容 | 相对当前项目根目录的文件 | 加载边界 |
| --- | --- | --- |
| 受测版本、范围、指标与结果 | `.fde/stages/evaluation.json` | 使用 `evaluation.candidate` 和 `evaluation.testing`，不是前端内置示例 |
| 验证计划、报告、基线 | `fde-deliverables/05-poc-eval/evaluation-plan.md`、`evaluation-report.md`、`evaluation-baseline.md` | 文件形成不等于测试通过或人工验收 |
| 当前版本与指标依据 | `candidate.sourceFiles`、指标 `sourceRefs` 所引用的项目文件 | 必须保留相对路径和实际内容，缺失会显示缺口 |
| 运行结果的证据 | `testing.run.results[].evidenceRefs` 引用的文件 | 保存真实结果；阶段 JSON 不能作为自身证据 |
| 系统架构 | `.fde/architecture.json` | 通过现有架构能力发布，候选与人工确认分开 |
| 本机项目运行入口 | `.fde/project-runtime.json` | 必须核对本机真实服务后登记，不能复制另一台机器的 running 状态冒充已启动 |

加载过程为：Workspace 定位项目目录 → 后端读取阶段文件和引用文件 → 校验版本指纹与证据 → 返回项目快照 → 前端展示。点击“刷新阶段记录”重新读取，不运行测试、不调用模型、不自动推进阶段。

源码入口位于 `upstream/deepseek-harness/packages/fde/project/src/`：`snapshot.ts` 加载项目快照，`v2-stage-surface.ts` 校验固定阶段合同，`evaluation-workbench.ts` 读取版本与指标、计算指纹。前端使用快照中的 `value.v2Stages.evaluation`，不要与其他评估读模型混淆。

1. 在正确的本地目录准备项目文件，保留内部相对路径。缺少原始材料或证据时先补齐，不通过改状态隐藏缺失。

3. 如需保留既有 Source 身份，按项目同步规则保留文件字节与高精度修改时间。Git checkout 通常不恢复原文件修改时间；出现 Source 过期时走正常资料核对/更新流程，不假设复制了 Git 文件就已完成资料同步。

6. 核对版本、文件依据、结果证据和架构；若代码、材料、环境或指标依据变化，旧结果应保留为过期。取得新的测试指纹、实际运行后保存新证据，不把旧结果重新签成当前通过。
