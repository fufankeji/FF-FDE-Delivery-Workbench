# 第二步：明确成功标准

只复制下面提示词到同一个 Agent 会话：

```text
客户补充并确认了本次试点的成功判断：

- 只选择 X200 产品系列和 5 名售后人员试用；
- 用 20 个有标准答案的代表问题验收，其中至少 16 个能够找到可追溯到有效版本资料的答案；
- 代表问题的平均查询和整理时间从当前抽查的 14 分钟降到 8 分钟以内；
- 找不到可靠依据时必须转给资深工程师，不能编造答案；
- 售后主管确认处理效率，产品经理确认引用资料是否有效；
- 客户资料仍然不能上传公网。

请把这些业务结果、验证方式、验证人和仍待确认的口径写入 fde-deliverables/02-outcome-scope/outcome-contract.md。同步更新 .fde/stages/definition.json，保持根对象 stage 为 definition：outcome 标为 complete，scope 标为 current。不要把目标值写成已经实现的结果，也不要设计实现方案。
```

## 本步观察点

- 页面当前工作应切换到“划定交付边界”；
- “业务结果与范围约定”应出现候选文件并可预览；
- 14 分钟是当前样本基线，8 分钟是待验证目标，两者不能混写；
- 成功标准必须包含验证人和验证证据；
- 本步完成不代表客户已经验收项目。
