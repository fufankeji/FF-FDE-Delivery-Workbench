# 第二阶段手动测试：本地知识库项目

## 测试目标

沿用第一阶段已经由 FDE 确认的“售后问题查询与回复”工作流，验证第二阶段能否完成以下链路：

1. 建立当前业务基线，并区分实测、估算和未知信息；
2. 把成功标准写成可由客户核验的结果；
3. 划清本次交付范围、非目标和停止条件；
4. 明确责任与交付计划，形成三份必备记录，等待 FDE 人工评审。

本轮只测试第二阶段，不调查客户系统、不设计技术方案，也不开始项目开发。

## 前置条件

- 当前项目已经完成第一阶段 FDE 人工确认；
- 页面显示 `阶段 2/8 · 定义结果、范围与责任`；
- 第一阶段三项固定记录仍可预览；
- 继续使用第一阶段的同一个项目，建议新建一个 Agent 会话进行第二阶段测试。
- 第二阶段状态文件固定为 `.fde/stages/definition.json`，其根对象 `stage` 必须始终为 `definition`，不能写成产物目录名 `outcome-scope`。
- `workItems` 必须是数组，每项写为 `{ "id": "固定工作项 ID", "status": "真实状态" }`；四个固定 ID 必须各出现一次，不能写成对象映射。

## 使用顺序

在同一个 Agent 会话中，依次复制下面四份文件里的提示词：

1. [01-建立当前基线.md](./01-建立当前基线.md)
2. [02-明确成功标准.md](./02-明确成功标准.md)
3. [03-划定交付边界.md](./03-划定交付边界.md)
4. [04-确认责任与计划.md](./04-确认责任与计划.md)

每次等待 Agent 完成文件更新并停止运行后，再回到“项目工作台”刷新阶段记录，然后发送下一条提示词。

## 第二阶段通过时应看到

- 四个工作步骤均显示完成；
- 三份必备记录均已形成并可预览：
  - 业务结果与范围约定；
  - 价值测算记录；
  - 交付计划；
- 实测数据、客户估算、项目目标和未知项没有混写；
- 页面不再显示阶段进度或必备记录缺口；
- 文件齐备后只能提交 FDE 评审，系统不会自动进入第三阶段；
- FDE 能在评审页面阅读本阶段记录，再人工确认进入第三阶段或返回补充。

如果 Agent 提前设计 RAG、选择模型、调查未授权系统，或者文件生成后自动推进阶段，应暂停测试并记录实际现象。
