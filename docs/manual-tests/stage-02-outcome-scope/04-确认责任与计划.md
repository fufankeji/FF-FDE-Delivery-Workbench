# 第四步：确认责任与计划

只复制下面提示词到同一个 Agent 会话：

```text
客户确认本次试点按下面的责任和节奏推进：

- 售后主管负责业务结果并作最终试点决定；
- 产品经理提供并确认 X200 有效资料清单，核对引用是否正确；
- 客户 IT 提供本地运行环境和必要访问条件，不负责业务验收；
- FDE 负责项目实施、问题记录和阶段材料维护；
- 5 名售后人员参加试用并反馈真实案例；
- 第一周确认资料和验收问题，第二周完成可用版本并内部验证，第三周由 5 名售后人员试用并复盘；任何前置资料或环境未具备时，对应节点顺延，不虚构已经完成。

请生成或更新 fde-deliverables/02-outcome-scope/delivery-plan.md，并复核 outcome-contract.md、value-case.md 和 delivery-plan.md 是否一致。随后重新读取三份固定产物，最后更新 .fde/stages/definition.json，保持根对象 stage 为 definition，不能写成 outcome-scope；workItems 保持为完整数组，四个固定工作项各出现一次并如实标记，记录仍存在的阻塞和 recommendation。只有三份记录齐备且没有未解决的 high 或 critical 阻塞时，才能把 status 写为 review-ready；否则保持 blocked 或 working。

最后告诉我三份记录分别写了什么、还有哪些待确认事项，以及是否已经具备提交 FDE 评审的条件。不要自动进入第三阶段，是否推进由我在工作台人工确认。
```

## 本步观察点

- “交付计划”应出现并可预览；
- 四个工作步骤应按照真实状态更新，不能仅因文件存在就全部完成；
- 三份记录中的范围、指标、责任人和停止条件应保持一致；
- 无未解决的高风险阻塞时，页面才能出现“提交 FDE 评审”；
- 点击提交后应进入当前项目的评审界面，而不是自动跳转第三阶段。
