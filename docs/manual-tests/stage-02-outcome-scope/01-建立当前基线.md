# 第一步：建立当前基线

只复制下面提示词到一个新的 Agent 会话：

```text
我们已经由 FDE 确认了第一阶段的“售后问题查询与回复”工作流。现在进入第二阶段，请先读取第一阶段三项固定记录，不要读取整个项目目录，也不要设计技术方案。

请整理这个工作流目前的业务基线：每天问题量、平均处理时间、需要资深工程师介入的比例、因旧资料造成的返工，以及当前无法核实的数据。必须区分人工抽查结果、客户估算和未知信息。

把结果写入 fde-deliverables/02-outcome-scope/value-case.md，并创建或更新 .fde/stages/definition.json。该 JSON 根对象的 stage 必须固定写为 definition，不能写成 outcome-scope；workItems 必须是数组，依次包含 {"id":"baseline","status":"complete"}、{"id":"outcome","status":"current"}、{"id":"scope","status":"waiting"}、{"id":"ownership","status":"waiting"}，不能写成对象映射。阶段状态保持 working。先重读本步产物，最后写状态文件，不要推进项目阶段。
```

## 本步观察点

- 页面第一步应完成，当前工作切换到“明确成功标准”；
- “价值测算记录”应出现候选文件并可预览；
- 每天约 60 个问题必须保留为客户估算；
- 20 个问题的人工抽查结果可以作为样本证据，但不能冒充全量统计；
- Agent 不应开始技术选型或项目开发。
