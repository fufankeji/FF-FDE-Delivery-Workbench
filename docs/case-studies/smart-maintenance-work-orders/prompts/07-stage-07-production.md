# 阶段 7 提示词：生产、采用与验收交接

## 前置条件

- 阶段 6 已由 FDE 人工决定进入阶段 7。
- 导入 `materials/07-production/01-production-adoption-handoff-evidence.md`。

## Prompt A：审查发布和观察证据

```text
请针对精确候选版本和获准范围，整理生产发布前的证据、残余未知、变更窗口、停止条件、回滚和上线观察计划。发布流水线成功只能证明发布动作，不代表业务结果或服务稳定；上线后要按预先约定的指标和时间窗口观察。若缺少生产授权、owner、回滚或关键硬门证据，请保持阻塞。
```

预期内部路由仅供学习对照：发布就绪＋上线观察；存在新旧系统切换时才使用切换能力。

## Prompt B：分析采用链和业务结果

```text
请把合格工作、系统曝光、建议完成、独立接受、草稿读回、正式派单和最终业务效果分开分析，找到第一个明显断点。不要把未曝光、系统失败、数据冲突、人工容量和用户选择都统一写成“用户抵触”。结合当前基线说明哪些结果已有证据、哪些仍需独立核对，并建立持续运营的 owner、SLO、告警、成本和服务复盘候选。
```

预期内部路由仅供学习对照：生产服务运营。

## Prompt C：准备验收和责任移交

```text
请整理客户可以取得的交付包、已知限制、开放风险、运行手册、支持路径和责任清单，并为接收团队安排实际操作、变更、权限调整、回滚、事故恢复、评估更新和停用演练。培训材料存在、参加会议或指定负责人都不能证明交接完成；请记录每项能力的实际演练证据和阻塞。客户验收、交付物可取得和责任转移必须等待 FDE 人工记录。
```

预期内部路由仅供学习对照：服务转移＋交付包＋接收团队实操；旧系统确认无消费者后才使用退役能力。

## 人工检查

- 是否把发布、采用、验收和交接当作四个不同状态。
- 是否找到“电话事件未曝光”和“人工不接受建议”两个不同断点。
- 是否要求接收团队真实演练，而不以文档交付替代能力。
- 是否保留采购和生产写入尚未批准的边界。
