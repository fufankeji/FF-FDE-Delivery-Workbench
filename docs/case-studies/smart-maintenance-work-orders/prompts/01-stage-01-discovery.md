# 阶段 1 提示词：发现高价值问题

## 本阶段操作入口

严格按照 [`STAGE-01-RUNBOOK.md`](../STAGE-01-RUNBOOK.md) 分三批上传。不要一次导入全部资料，也不要上传阶段 2～8 的未来素材。

## Prompt A：从最近案例还原真实工作

```text
我刚导入了客户原始简报。请先保留客户的原始说法，不要马上设计 AI 方案，也不要因为客户数据很多就预设需要知识图谱或本体。请告诉我：为了判断这个问题是否真实、是否值得继续，最少还需要哪一个近期正常案例、哪一个重要异常案例，以及需要找到哪些真正了解流程或拥有决定权的人。未知内容请明确标为待核对。
```

预期内部路由仅供学习对照：工作流资格判断；根据缺口可能追加项目定向、访谈或责任映射。

## Prompt B：比较异构来源并提出最小调查动作

```text
我又导入了聊天记录、工单抽样、设备台账、值班表、政策 PDF、设备图片、位置草图和一个当前无法识别的邮件原件。请逐项区分项目发起人说法、现场消息、系统记录、人工维护表、图片观察和政策授权，并为每个关键主张保留来源与时间。重点追踪南京收银中断和杭州空调两个案例，识别重复事件、故障域、设备身份、合同状态和费用权限之间的冲突。图片和无法识别的文件只能按真实能力处理；不要猜内容或把格式失败写成事实失败。最后列出还必须向哪些流程知情者或决策人确认的最少问题，不要设计方案或执行外部动作。
```

预期内部路由仅供学习对照：资格判断；根据证据缺口可能使用责任映射和系统勘察。此时还没有导入访谈结果，不应伪造访谈结论。

## Prompt C：加入访谈并形成重新界定与阶段候选

```text
我现在补充了首轮访谈纪要。请把亲眼观察、近期记忆、设计假设和未知分开，并重新核对“自动派单、80% 自动处理、三个月上线”与实际权限、应急和费用责任的冲突。保留原始简报；如果冲突改变项目边界，请形成带触发事实、安全回退、受影响范围和有权决策人的重新界定候选。然后形成本阶段可供 FDE 审阅的真实工作流、角色、正常与异常路径、当前基线或未测状态、候选业务结果、范围与非目标、人工回退、风险、停止条件和仍缺证据。每条关键主张都要回到具体来源。只维护固定路径，不创建平行最终稿，不要把结构有效写成事实已确认，也不要自行推进阶段。
```

## 人工检查

- 是否真的识别出发起人目标与区域经理、采购、财务和信息安全权限之间的冲突。
- 是否把案例 B 的“收银机故障”还原成可能的网络故障链。
- 是否把聊天、工单、设备台账、值班表、政策、图片和访谈作为不同证据，而不是互相覆盖。
- 是否保留尚未测量的总体基线，而不是用 12 条抽样编造比例。
- 是否如实保留 PNG/SVG `needs-ocr` 和 EML `unsupported` 的能力边界。
- 是否生成逐条 evidenceRefs 和固定 Artifact Catalog。
- FDE 审阅后再决定 Go、Revise、Narrow 或 Stop，并记录 revision。
