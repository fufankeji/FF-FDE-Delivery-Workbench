# 阶段 5 提示词：运行 PoC 与 Eval

## 前置条件

- 阶段 4 已由 FDE 人工决定进入阶段 5。
- 导入 `materials/05-evaluation/01-evaluation-case-pack.md`。
- 明确记录当前候选版本；没有固定版本时先阻塞。

## Prompt A：只生成评估方案

```text
请先只生成当前候选版本的评估方案，不开始执行。将每条已确认验收要求映射到具体用例、指标、阈值、方法、环境、版本和证据位置。覆盖正常、异常、拒绝、恢复、来源冲突、重复、跨区域、提示注入、P0 安全和草稿幂等。P0 漏检、未经授权动作、跨区域读取和无读回成功声明必须作为独立硬门，不能被平均分掩盖。缺少来源或阈值时登记缺口，不要自行补数。
```

预期内部路由仅供学习对照：产品主张评估＋验证计划＋测试数据策略＋NFR 验证设计。

## 人工动作

FDE 阅读当前评估方案、来源、阈值、候选版本和方案摘要。只有确认精确方案后，才能开始运行。把确认时间、摘要和 revision 写入台账。

## Prompt B：执行已确认方案

```text
请只执行当前已经由 FDE 确认且摘要仍然有效的评估方案。固定候选版本、夹具、评估器、规则、提示、工具响应和运行环境；不要让候选实现看到预期答案。保存每个用例的真实结果、失败、停止原因、延迟、成本和工具读回证据。未运行、失败或缺少证据的项目保持真实状态，不得标为通过；如果必须改变方案、阈值或来源，立即停止并请求重新确认。
```

## Prompt C：形成评估结论

```text
请根据真实运行证据形成评估报告和基线，按正常、异常、拒绝、恢复和安全硬门分别报告，不只给总分。说明失败分类、不确定性、污染控制、当前证据能支持的结论以及不能支持的生产主张。给出 accept、inconclusive 或 reject 的方法建议，并列出进入受控 Pilot 前最小的修复或补证据事项；不要自行推进阶段。
```

## 人工检查

- 是否把计划生成、人工确认、真实执行和结论分成不同动作。
- 是否绑定精确候选版本与评估夹具版本。
- 是否保留失败案例，而不是只展示通过结果。
- 是否把 P0 和禁止动作作为不能被平均的硬门。
- Eval 通过不等于生产就绪或客户批准。
