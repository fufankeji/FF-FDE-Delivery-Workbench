# 阶段 8 提示词：持续改进与能力沉淀

## 前置条件

- 阶段 7 已由 FDE 人工决定进入阶段 8。
- 导入 `materials/08-improvement/01-operation-signals-and-improvement-candidates.md`。

## Prompt A：从生产信号选择问题

```text
请按业务结果、采用、事故、可靠性、成本和证据强度整理最近生产信号，区分症状、已确认原因、推断和未知。找出最值得先处理的一项问题，说明影响、适用范围、当前安全处置和需要补什么证据。不要把所有信号都归因于模型，也不要因为某项容易实现就优先选择。
```

预期内部路由仅供学习对照：生产证据复盘；有事故或看不见的失败时使用事故定位和可观测性缺口能力。

## Prompt B：形成改进、复测和受控发布方案

```text
请为选中的改进建立与原生产信号相连的假设、最小变更、回归案例、指标、硬门、失败恢复、发布范围、观察窗口和回滚条件。先证明改进解决原问题且没有破坏 P0、权限、幂等和读回，再安排小范围发布。缺少根因或验证证据时保持调查状态，不要把候选直接写成已修复。
```

预期内部路由仅供学习对照：改进优先级＋改进验证＋受控发布。

## Prompt C：判断是否能沉淀为复用能力

```text
请评估“受控草稿写入”是否值得沉淀为可复用能力。先分离本案例特有的门店、设备、区域、500 元额度、维修合同和故障等级，再识别可能可移植的草稿/提交分离、幂等键、独立读回、unknown 状态、kill switch、审计字段和负向测试。当前只有一个案例时不得称为平台标准；请写出跨独立现场验证、维护成本、兼容、迁移、Canary、回滚和退役条件。
```

预期内部路由仅供学习对照：现场经验产品化。

## 人工检查

- 是否把合同元数据陈旧识别为数据流程问题，而不是用模型掩盖。
- 是否把事故根因保持未确认，并优先修补 operationId 可观测性。
- 是否由生产证据触发复测和发布边界。
- 是否明确一个客户案例不足以证明通用能力。
- 最终复盘应回到运行台账，比较两个开源来源、产品 Adapter 和真实执行之间的差异。
