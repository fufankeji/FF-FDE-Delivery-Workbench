# 阶段 2 提示词：定义结果、范围与责任

## 前置条件

- 阶段 1 已由 FDE 人工决定进入阶段 2。
- 导入 `materials/02-definition/01-baseline-and-target-discussion.md`。
- 导入 `materials/02-definition/02-scope-constraints-and-dependencies.md`。

## Prompt A：建立价值和结果合同

```text
请从阶段 1 已确认的工作流和我刚导入的基线材料出发，建立当前业务基线、候选目标、指标 owner、独立验证者、测量窗口、归因方式、风险上限和停止条件。请把已测数据、手工估算、客户目标和未知项分开，不要用模型活动、建议数量或 Token 量代替被接受的业务结果，也不要把口头成本范围写成正式财务标准。
```

预期内部路由仅供学习对照：价值工程。

## Prompt B：把结果转成可验收范围

```text
请把候选业务结果拆成可验证的要求，逐项说明适用角色、触发条件、预期结果、失败回退、边界、非目标和证明方式。用现有资料检查哪些要求已有系统或数据落点、哪些只是看起来可行、哪些必须等待访问或负责人确认。不要在本阶段选择技术框架或承诺自动派单。
```

预期内部路由仅供学习对照：需求转规格＋可行性探针。

## Prompt C：估算并按风险排计划

```text
请基于已经有证据的范围和可行性结果，给出带区间、假设、客户等待时间、外部依赖和风险缓冲的估算，并按最可能推翻项目的风险安排交付顺序。三个月只能作为发起人期望，不能自动变成承诺日期。若范围、时间、资源和治理条件不能同时成立，请提供少量可比较的重谈选项，并指出谁必须决定。
```

## 人工检查

- 是否把“工单草稿”作为可独立验证的首期结果，而不是偷偷恢复自动派单。
- 是否把基线的匹配率和统计限制保留在指标解释中。
- 是否先安排 Sandbox、设备匹配、合同权威性和复核容量等高风险假设。
- FDE 只在 owner、verifier、范围、停止条件和计划足以承担下一阶段调查时推进。
