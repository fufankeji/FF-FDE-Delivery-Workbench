# 阶段 2 提示词：定义结果、范围与责任

## 前置条件

- 阶段 1 已由 FDE 人工决定进入阶段 2。
- 继续使用阶段 1 的同一个项目，保留既有 SourceId 和三个阶段 1 必需 Artifact。
- 严格按照 [`STAGE-02-RUNBOOK.md`](../STAGE-02-RUNBOOK.md) 分批上传，不要一次导入全部阶段 2 资料。
- 不要上传阶段 3～8 的未来素材，也不要把 Runbook 或文件清单上传给 Agent。

## Prompt A：建立价值和结果合同

```text
请从阶段 1 已确认的工作流和我刚导入的基线材料出发，建立当前业务基线、候选目标、指标 owner、独立验证者、测量窗口、归因方式、风险上限和停止条件。请把已测数据、手工估算、客户目标和未知项分开，不要用模型活动、建议数量或 Token 量代替被接受的业务结果，也不要把口头成本范围写成正式财务标准。
```

预期内部路由仅供学习对照：价值工程。

## Prompt B：把结果转成可验收范围

```text
请把候选业务结果拆成可验证的要求，逐项说明适用角色、触发条件、预期结果、失败回退、边界、非目标和证明方式。用现有资料检查哪些要求已有系统或数据落点、哪些只是看起来可行、哪些必须等待访问或负责人确认。不要在本阶段选择技术框架或承诺自动派单。
```

预期内部路由仅供学习对照：需求转规格＋可行性探针。

## Prompt C：估算并按风险排计划

```text
请基于已经有证据的范围和可行性结果，给出带区间、假设、客户等待时间、外部依赖和风险缓冲的估算，并按最可能推翻项目的风险安排交付顺序。三个月只能作为发起人期望，不能自动变成承诺日期。若范围、时间、资源和治理条件不能同时成立，请提供少量可比较的重谈选项，并指出谁必须决定。
```

预期内部路由仅供学习对照：估算＋风险优先交付计划；出现范围、周期和资源冲突时才重谈。

## Prompt D：吸收责任确认并准备人工阶段门

```text
请读取我刚上传的阶段二责任与边界确认纪要，把正式确认与仍未确认的事项分别更新到业务结果与范围约定、价值测算记录和交付计划中。请保留每项结论的来源、口径限制和责任人，不要把 Pilot 候选目标、口头成本、未开通的 Sandbox 或三个月期望改写成生产承诺。最后列出三个固定产物的状态、仍需在下一阶段调查的事项和当前是否具备人工评审条件；不要替我推进项目阶段。
```

预期内部路由仅供学习对照：价值工程＋需求与计划更新，不需要重新加载全部方法。

## 人工检查

- 是否把“工单草稿”作为可独立验证的首期结果，而不是偷偷恢复自动派单。
- 是否把基线的匹配率和统计限制保留在指标解释中。
- 是否先安排 Sandbox、设备匹配、合同权威性和复核容量等高风险假设。
- 是否将正式责任确认与仍未确认的系统、数据、成本和日期严格分开。
- FDE 只在 owner、verifier、范围、停止条件和计划足以承担下一阶段调查时推进。
