# 阶段 4 提示词：设计方案并完成端到端纵向切片

## 前置条件

- 阶段 3 已由 FDE 人工决定进入阶段 4。
- 导入 `materials/04-design/01-solution-constraints.md`。

## Prompt A：先比较机制

```text
请把已确认的工作流拆成若干关键决策点，分别比较不建设、人工流程改进、确定性规则、传统软件、检索、单次模型调用、有界 Agent 和多 Agent。请以业务结果、数据、权限、可靠性、延迟、成本、可维护性和可验证性选择每一步的最小充分机制，并给出未选原因、确定性回退和退出条件。不要因为项目名称里有“智能”就默认选择 Agent。
```

预期内部路由仅供学习对照：机制选择。

## Prompt B：形成生产级方案和合同

```text
请基于选定机制形成最小完整系统设计，覆盖输入、状态、数据来源、规则或模型、工具调用、人工复核、输出、监控、失败、重试、取消、降级、恢复、成本和责任。逐项定义接口字段、版本、鉴权、区域、幂等、超时、错误和兼容方式；把功能目标与性能、安全、可用性、审计和人工接管底线分开。所有特权动作和权威状态变化必须留在受信任软件边界。
```

预期内部路由仅供学习对照：生产级系统设计＋方案设计＋合同设计＋NFR 基线。

## Prompt C：定义并验证最窄纵向切片

```text
请按当前授权设计一个从脱敏报修输入到“有引用的建议和本地工单草稿”的端到端纵向切片。P0 提示必须走确定性路径；信息不足要停止并提出最少问题；重复只提示候选；没有 Sandbox 草稿权限时不能假装写入成功。请列出最小改动、验证点、失败注入、恢复和回滚方式，并说明当前环境实际能证明到哪一步。只维护本阶段固定候选产物，不推进阶段。
```

## 人工检查

- 是否选择了混合机制，而不是把全部工作交给模型。
- 是否把 P0、权限、幂等和读回放在受信任边界。
- 是否包含正常、拒绝、超时、冲突和恢复路径。
- 是否清楚区分“方案”“切片已运行证据”和“生产就绪”。
