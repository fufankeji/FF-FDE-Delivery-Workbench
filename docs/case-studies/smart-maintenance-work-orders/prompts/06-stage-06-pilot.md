# 阶段 6 提示词：企业集成、可靠性改造与受控试点

## 前置条件

- 阶段 5 已由 FDE 人工决定进入阶段 6。
- 先定义 Pilot 边界和运行手册；完成仿真运行后再导入 `materials/06-pilot/01-pilot-boundary-and-observations.md` 的观察结果部分。

## Prompt A：生产就绪预审和试点边界

```text
请针对阶段 5 的精确候选版本做一次进入 Pilot 前的就绪审查，并定义一个有界试点：门店、用户、时间、数据、身份、允许读取、允许写入、人工确认、禁止动作、监控、停止、回滚和责任人。不要把 Eval 通过推导成生产就绪。任何没有明确授权的写入、通知、派单、费用承诺和跨区域访问保持禁止。
```

预期内部路由仅供学习对照：生产就绪审查＋试点范围与授权。

## Prompt B：形成别人能执行的 Pilot 手册

```text
请把试点接入、启动、日常检查、人工复核、工具超时、重复草稿、来源冲突、P0、权限拒绝、停止和回滚写成另一名运维人员也能执行的步骤。每一步说明前置条件、操作、应观察的结果、失败处理和谁负责；回滚必须可演练，不能只写“必要时回滚”。当前未取得 Sandbox 草稿权限时，只能运行本地草稿路径。
```

预期内部路由仅供学习对照：企业接入、可靠性与恢复；如客户有变更流程，再使用变更控制和部署手册能力。

## Prompt C：导入观察后复盘 Pilot

```text
我现在提供 Pilot 的仿真观察记录。请把客户提供的汇总数字、实际工具证据和未验证主张分开，核对试点范围、P0、人工修改、重复候选、采用、Sandbox 权限和未授权动作。对每个问题记录严重度、状态、责任人、恢复或修复证据，并判断证据支持扩大、修订、收窄还是停止。不要把客户汇总表当成不存在的工具审计，也不要自动进入生产阶段。
```

## 人工检查

- 是否明确 3 店、10 个工作日和只允许草稿的边界。
- 是否将本地草稿与 Sandbox 读回草稿分开统计。
- 是否记录采用问题、人工容量和错误重复候选，而不只看准确率。
- 是否存在可执行停止与恢复路径。
