# 系统、访问与责任清单

## 系统清单

| 系统 | 用途 | 当前事实 | Owner 候选 | 当前访问 |
|---|---|---|---|---|
| WorkOrder Pro 7 | 工单创建、派单、状态和关闭 | SaaS；支持查询和草稿 API，正式派单 API 需单独权限 | 设备运维经理林哲 | 只读测试账号已批准；写入未批准 |

| 企业消息平台 | 门店报修入口之一 | 真实群消息含员工姓名和可能的顾客信息 | 数字化运营部 | 当前没有 API 或数据使用批准 |

## 工单 API 仿真合同

- `GET /tickets/{id}`：读取单张脱敏工单。
- `GET /assets/{assetId}`：读取设备状态、门店、品牌和保修候选信息。
- `GET /vendors?region=&category=`：读取候选维修商，不表示合同当前有效。
- `POST /ticket-drafts`：仅创建草稿，不派单、不通知维修商、不锁定价格。
- `POST /tickets/{id}/dispatch`：真实派单；当前 Pilot 明确未授权。
- 请求必须绑定当前操作人、区域和项目；跨区域查询默认拒绝。

## 已知失败与限制

- WorkOrder Pro 的 API 文档比 Sandbox 实际版本新一个小版本。
- AssetBook 中 4.6% 的在用设备没有唯一有效标签。
- ContractHub 的合同元数据不包含全部费用审批规则，PDF 正文仍是权威来源。
- 供应商当天是否值班来自人工表格，不在 API 中。
- 系统之间没有统一事件 ID，消息、设备和工单只能通过门店、时间、设备候选和症状组合匹配。
