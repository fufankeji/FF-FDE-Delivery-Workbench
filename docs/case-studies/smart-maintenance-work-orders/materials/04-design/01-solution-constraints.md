# 方案与纵向切片约束

## 已确认的设计输入候选

- 首期只处理华东一区 12 家门店的四类设备。
- 输入由人工上传，不直接接企业消息平台。
- 输出是建议和工单草稿，不执行正式派单。
- P0、安全风险、费用超限、设备身份不明、合同状态不明必须进入人工路径。
- 每项建议需要显示原始来源、规则或合同依据以及未验证项。

## 可比较机制

1. 只优化人工表单和流程，不使用模型。
2. 规则引擎完成紧急等级与权限硬门，人工搜索设备和合同。
3. 规则＋检索＋单次模型调用：规则负责硬门，检索设备/合同，模型负责抽取和解释候选。
4. 有界 Agent：可按状态选择读取工具、请求补充信息并创建工单草稿，但不能派单。
5. 多 Agent：分别负责设备、合同、故障和调度，再由协调器汇总。

候选机制不等于推荐结论。必须以价值、数据、权限、可靠性、延迟、成本、可维护性和可验证性比较。

## 可比较的语义基础

执行机制与语义基础必须分开判断：

1. 普通数据／接口 Schema：直接用稳定字段、规则和查询完成当前链路。
2. 正式本体／知识图谱：统一跨来源身份、关系、来源、有效时间和冲突，再通过受控查询提供上下文。

不能因为已经安装 Semantica、数据来源多或案例名称包含“智能”就选择知识图谱。只有普通 Schema 无法可靠回答跨来源实体统一、多跳关系、时间有效性、来源冲突或多个任务共享稳定语义等能力问题时，才进入正式本体路线。

如果进入本体路线，第四阶段只使用代表材料构建最小图谱并回答必答问题，不处理全部 80 家门店数据，不把节点数量、构建成功或 Explorer 可打开当作验证通过。

## 纵向切片边界

输入一条脱敏报修文本和可选设备号后，切片应：

1. 保留原文与 SourceId；
2. 抽取门店、设备候选、症状和影响；
3. 检查重复事件候选；
4. 先执行确定性的 P0 与权限硬门；
5. 查询设备、合同和维修商候选；
6. 生成故障域、优先级和维修商建议及引用；
7. 信息不足时提出不超过三个关键问题；
8. 由人确认后，只在已批准环境创建工单草稿；
9. 从 WorkOrder Pro 读回草稿编号后才显示成功。

本次 Sandbox 草稿权限仍在申请中，因此可运行切片的动作终点是“本地草稿＋明确未执行外部写入”。图谱上下文必须保留 SourceId、有效时间、置信度和权限边界，不能把整张图谱无差别注入 Agent。

## 接口与 NFR 候选

- P0 安全提示应在输入进入系统后 5 秒内显示，且不依赖外部模型成功。
- P1/P2 建议在 30 秒内返回；外部依赖失败时提供明确降级和人工路径。
- 同一门店、同一设备候选、相似症状在两小时内必须提示重复，但不得自动合并。
- 所有外部读取和草稿写入必须绑定项目、用户、区域和操作 ID。
- 同一操作 ID 的草稿创建应幂等；超时重试不得创建多个草稿。
- 任何 P0、费用超限、合同不明或跨区域请求不能进入自动提交路径。
- 纵向切片必须可在没有付费模型的确定性夹具上演示合同与失败行为。
