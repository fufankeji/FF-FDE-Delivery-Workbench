# 阶段 4 操作者验收基准

本文件用于人工核对结果，不能上传给 Agent，不能作为本体或图谱输入，也不能替代真实运行证据。

## 路线判断

本案例具有跨来源身份统一、复杂关系、时间有效性、来源冲突、多跳查询和受控 Agent 上下文需求，因此“正式本体／知识图谱”应成为有证据的候选语义基础。执行机制仍应采用混合路线：确定性 P0／权限硬门＋受控数据查询＋必要的抽取或解释能力＋人工确认，而不是让本体或 Agent 承担全部工作。

如果实际运行因材料未绑定、Provider 不可用或能力问题不能执行而证据不足，正确结论是 `insufficient_evidence` 或 `validation_failed`，不能为了匹配本基准写成 `validated`。

## 最小语义覆盖

名称可以不同，但当前 Schema 至少需要表达以下语义：

- 实体：门店、设备、报修记录、现实故障候选、告警、工单、维修商、合同、政策／规则、证据来源。
- 关系：报修发生于门店、报修涉及设备候选、报修可能属于同一故障、故障关联告警／工单、设备或类别受合同覆盖、维修商受合同约束、事实来自来源、规则约束动作。
- 限定：来源、有效时间、置信度、候选／确认状态、区域和权限范围。
- 约束：未知身份不能变成确定关系；过期合同不能作为有效覆盖；重复只能提示候选；禁止动作不能被图谱关系绕过。

## 必答问题的核对要点

| 能力问题 | 应出现的事实和边界 |
|---|---|
| CQ-01 | `R-1002` 与 `R-1003` 是同门店、相近时间和相似影响的重复候选；保留两条来源，不自动合并。 |
| CQ-02 | 关联 `NJ-003`、`CHAT-20260821-1807`、`CHAT-20260821-1811`、`WO-88419`、`WO-88422`；StoreNet 告警仍为未验证，设备身份存在候选而非创建时确定值。 |
| CQ-03 | 网络路线可找到 `V-NET-02`／`CTR-NET-2026-02` 的当时覆盖，但只能形成候选；杭州 `CTR-HVAC-2023-09` 元数据 active、签署期限已过，必须标冲突并转人工。 |
| CQ-04 | 合同有效期、设备身份或来源规则改变后，引用旧版本的验证、上下文和切片证据进入待重评。 |
| CQ-05 | P0 先返回固定人工应急提示；正式派单、通知、费用承诺和跨区域读取保持禁止。 |
| CQ-06 | Agent 只得到当前报修所需子图、规则、来源、时间、置信度与未知项；不得看到全部图谱或 `final_*` 标签。 |

## 证据门

只有以下证据来自同一项目、当前版本且都可打开时，本体机制结论才可候选为 `validated`：

1. 材料绑定与输入版本记录；
2. 经人工审阅后发布的当前 Ontology Schema；
3. 项目隔离的图谱构建运行及真实节点／关系摘要；
4. 独立结构校验结果；
5. 六个能力问题的真实查询输入、结果和证据；
6. 受控 Agent 上下文查询结果；
7. 从报修输入到本地草稿的真实纵向切片运行；
8. 外部写入明确记录为未执行；
9. FDE 决定仍单独等待人工提交。

文件存在、构建命令退出 0、Explorer 可打开或节点数量非零均不能单独通过此门。
