# 智修协同：连锁门店设备故障智能分诊案例

## 案例目的

本案例用于从“新建项目”开始，完整走通 `FF - FDE 交付工作台` 的八阶段流程，并观察两个外部 FDE Skill 来源怎样在真实任务中组合：

- `davidahmann/fde-guide` 负责业务方法、Artifact、证据要求和决策门；
- `rpraharaj/forward-deployed-engineer` 负责现场调查、代码与数据、验证、发布、运营和交接动作；
- `FF - FDE 交付工作台` 负责八阶段编排、固定产物、项目隔离和 FDE 人工决定。

案例中的企业、人员、系统、合同、工单、指标和事件全部为仿真数据，不对应真实企业或个人，不包含凭据，也不需要调用付费服务。

## 案例主题

一家拥有 80 家门店的连锁企业，通过群消息、电话和旧工单系统上报冰柜、收银机、空调、网络等设备故障。总部设备运维组需要人工补资料、判断紧急程度、查保修和合同、选择维修商、取得审批、派单并跟踪 SLA，存在漏单、重复工单、错误分级和超时。

客户最初提出“用 AI Agent 自动读取报修消息并自动安排维修商”。随着现场证据逐步释放，项目会发现自动派单受到设备身份、合同覆盖、费用审批、区域权限、数据质量和人工接管要求约束。案例目标不是预设一定要做 Agent，而是通过八阶段判断最小可行机制和安全动作边界。

## 使用规则

1. 先阅读 [`CASE-MANIFEST.md`](CASE-MANIFEST.md)，只释放当前步骤允许的素材；不要在项目开始时一次上传全部未来证据。
2. 在工作台中创建一个新的独立项目目录，不把案例输出写回本案例素材目录。
3. 通过项目资料入口导入当前阶段素材，保留工作台生成的 SourceId 和识别状态。
4. 复制 `prompts/` 中当前步骤的“可复制提示词”。提示词只使用业务语言，不主动告诉 Agent 应该选哪个 Skill。
5. 每次执行后立即更新 [`records/execution-ledger.md`](records/execution-ledger.md)：记录材料、原提示词、实际加载 Skill、工具、产物、证据、阻塞和人工决定。
6. Agent 生成文件、给出建议或测试通过，都不能自动推进阶段。只有 FDE 在工作台人工评审后才能 Go、Revise、Narrow 或 Stop。
7. 预期 Skill 只用于学习对照，不是通过条件。若实际路由不同，先记录原因，不为了匹配答案强行调用 Skill。
8. 不预先创建工作台应生成的 `fde-deliverables/` 或 `.fde/` 文件；它们必须来自后续真实运行。

## 完成标准

案例只有在以下条件全部成立时才算完整：

- 新建项目和八阶段都有独立运行记录；
- 每个阶段记录了实际输入、提示词、Skill、工具、Artifact、证据状态和人工决定；
- 至少一次重大说法冲突被保留并由 FDE 明确处置；
- 至少一次外部动作因权限或证据不足被拒绝或降级；
- Eval 使用固定候选版本和代表性、异常、拒绝、恢复案例；
- Pilot 有明确范围、授权、监控、停止和回滚条件；
- 生产、采用、验收与责任交接分别留证；
- 持续改进由生产证据触发，并明确客户特有内容与可复用能力的边界；
- 任何未真实执行的动作都没有被写成成功。
