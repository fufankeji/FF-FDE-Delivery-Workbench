# FF - FDE 交付工作台 V2 产品需求文档

> 以项目为最小交付单元，以八阶段组织 FDE 真实工作，以六项生产责任约束生产就绪，并通过透明的 Agent 执行、持久化 Artifact、证据状态和 FDE 人工决定，把模糊客户问题推进为可运行、可治理、可交接和可持续改进的企业成果。

## 2. 背景、问题与目标

- 当前问题：V1 已具备项目、会话、资料、代码、终端、运行、评估和交付能力，但产品仍以技术模块和固定文件为中心；用户需要理解阶段、会话、目录、Skill、工具与产物之间的关系，难以低门槛地知道系统现在做什么、自己下一步做什么。
- 为什么现在解决：技术基座已经能够支撑真实项目执行，V2 的首要工作是把能力组织为可理解、可追踪、可干预的 FDE 工作流程，而不是继续堆叠孤立入口。
- 产品目标：让 FDE 只需理解项目目标、当前工作、证据和待决定事项，即可通过自然语言和推荐行动驱动 Agent、Skills 与平台工具完成真实企业交付。
- 非目标：不把工作台做成通用聊天机器人、纯代码 IDE、固定文件检查器、客户管理系统或自动替人作出业务决定的无人系统。

## 3. 目标用户与场景

| 用户/角色 | 使用场景 | 当前困难 | 期望结果 | 明确不服务 |
|---|---|---|---|---|
| FDE | 从进入客户现场到生产交接持续推进一个项目 | 不知道当前最应完成什么；资料、工程动作和阶段证据分散 | 每次进入项目都看到当前目标、推荐行动、执行过程、产物、缺口和人工决定 | 不替 FDE 判断业务价值、客户确认和风险接受 |
| 项目协作人员 | 在授权范围补充资料、查看产物并参与评审 | 无法区分候选结论、真实证据和已确认决定 | 能在项目事实中查看来源、状态、责任和下一步 | 不提供未经授权的跨项目数据或生产操作 |

V2 不按学员端和导师端拆分。课程学员获得的是可以继续用于真实企业交付的完整 FDE 工作台。

用户可从独立的“业务挖掘实验室”练习模拟企业访谈。该入口不要求创建项目，不改变真实交付的用户角色、项目身份或八阶段路径。

## 4. 产品目标与成功信号

| ID | 成功信号 | 目标值/判断方式 | 反指标 |
|---|---|---|---|
| GOAL-001 | 用户理解当前工作 | 进入项目后无需查阅技术说明即可说出当前阶段目标、正在执行的任务和下一项人工动作 | 只能看到空白聊天框、技术日志或不明进度 |
| GOAL-002 | Agent 工作透明 | 每次执行均可查看所用上下文、计划、动作、观察、结果和终态 | 只显示思考中，或结果突然出现而无法追溯 |
| GOAL-003 | 阶段结果可继承 | 每项重要工作形成持久化 Artifact 和证据，后续任务可以直接使用 | 结论只存在于一次会话回答中 |
| GOAL-004 | 决策责任真实 | 所有阶段推进、风险接受和生产责任均由有权的人明确记录 | 文件存在、Agent 自评或构建成功自动推进项目 |
| GOAL-005 | 生产闭环完整 | 六项生产责任可回指范围、版本、证据、责任人和批准 | 摄取文档或页面可访问被显示为生产就绪 |

| J-005 | P1 | 生产与持续改进 | 受控运行证据、采用结果、事故或业务反馈 | 形成改进假设，重新测试、审查、批准并受控发布 | 生产证据成为下一轮可验证改进和复用资产 | 缺少授权或验证时停留在候选状态 |
| J-006 | P0 | 业务挖掘实验室 | 用户主动选择一个模拟企业案例 | 阅读委托、访谈岗位、索取原件、交叉核实、计算、完成调查并生成报告 | 完整训练轮次与可导出的诊断报告；返回后原项目不变 | 失败保留访谈和已获资料，可重试；重新开始仅归档本案例轮次 |

## 6. 产品范围

### In-Scope

- 项目级目录、会话、资料、状态、Artifact、证据和决定隔离。
- 八阶段默认路径、非线性返回、重评和四类 FDE 决定。
- 当前阶段透明工作台：目标、输入、推荐工作、实时过程、产物、缺口和人工决定。
- 最小上下文、可控工具、Skill 自动路由、闭环执行和会话审计。
- Artifact-first、证据／可信度标签、后续任务复用前序产物。
- 六项生产责任及其范围、版本、证据、责任人和批准状态。
- V1 项目、会话、文件和状态保护；V2 仅在明确生命周期身份下启用。
- 第五阶段保留“运行 PoC 与 Eval”名称，以项目开发为核心：在 DSH 中依据已确认方案开发，工作台展示受测版本、运行情况、指标与测试证据；形成可运行版本后进行测试和阶段验收。
- 独立业务挖掘实验室：保留已交付五案例、办公室、多岗位访谈、资料授权、调查提示和进度、计算、报告导出、版本升级及历史轮次；不替换项目工作台。

### Out-of-Scope

- 不在首个 V2 切片中自动迁移 V1 六阶段项目。
- 不要求用户学习或手动选择全部 Skill 名称。
- 不把 43 个外部 Skills 全量加载到每次会话；只按项目、阶段和任务加载必要能力。
- 不建设客户管理、销售管理、资产市场或复杂组织权限后台。
- 不使用静态演示数据、文件数量或 Agent 总结伪造真实进度。
- 不由 Agent 代替客户签字、治理批准、生产授权、风险接受或责任移交。
- 实验室本轮不新增账号、班级或多人独立训练，不自动创建项目、回流报告、推进阶段或把模拟调查解释为真实企业验收。

| REQ-032 | P0 | 训练不改变项目交付 | 进入、退出、重开、升级或完成训练 | 训练轮次和项目状态分别维护，访谈上下文只含该角色授权材料 | 原项目、阶段、资料和会话保持原状 | 同服务每案例共享当前轮次；不混入项目会话、不自动推进阶段、不发放教师资料 |

## 8. 业务规则与状态

### 已确认的局域网访问变更（2026-10-23）

## 10. 验收标准

### AC-001 · 项目隔离

- 来源：REQ-001, NFR-001
- Given 已打开一个已登记的 FDE 项目
- When 用户查看目录、会话、状态、上下文、产物和证据
- Then 只能看到当前项目事实，其他本机工作区不会被扫描或混入

### AC-002 · 双工作面一致

- 来源：REQ-002
- Given 同一项目同时拥有交付工作台和项目管理入口
- When 项目事实发生变化并刷新两个工作面
- Then 两处显示相同阶段、缺口和决定，不各自维护进度

### AC-003 · 八阶段与人工决定

- 来源：REQ-003, REQ-004, NFR-002
- Given 项目采用 V2 生命周期
- When FDE 提交 Go、Revise、Narrow 或 Stop
- Then 系统保存决定人、理由、时间、证据快照和影响范围并更新责任状态

### AC-004 · 非线性返回与恢复

- 来源：REQ-003, NFR-003
- Given 后续证据要求返回较早阶段
- When FDE 选择合法返回目标并填写原因
- Then 项目保留全部历史并标记受影响结论需要重评

### AC-005 · 禁止自动推进

- 来源：REQ-004, REQ-005
- Given 文件、任务或工程验证已经完成
- When 尚无 FDE 阶段决定
- Then 项目保持当前阶段并显示等待人工评审

### AC-006 · 事实与证据分离

- 来源：REQ-006, REQ-007, NFR-002, NFR-011
- Given 项目同时存在输入、候选产物、验证和人工决定
- When 用户查看阶段事实
- Then 每类事实独立显示并可回指来源、版本和责任

### AC-007 · V1 兼容和中文文档

- 来源：REQ-009, NFR-005, NFR-006
- Given 一个未明确迁移的 V1 项目
- When V2 功能在同一工作台上线
- Then 原项目仍按 V1 状态可用，V2 文档只维护中文事实源

### AC-008 · 真实失败状态

- 来源：REQ-010, NFR-004
- Given 项目事实缺失或读取失败
- When 用户打开相关工作面
- Then 页面显示具体未知、缺失或错误以及恢复入口，不显示空白、零值或演示数据

### AC-009 · 智能执行闭环

- 来源：REQ-011, NFR-007
- Given FDE 已限定当前项目和执行范围
- When 提交自然语言请求
- Then 可以追踪意图、上下文、选用能力、动作、持久化结果和上下文解释

### AC-010 · 最小能力边界

- 来源：REQ-012, NFR-007
- Given 用户限定模型、工具或数据范围
- When Agent 尝试读取或调用范围外能力

### AC-011 · 工具控制与审计

- 来源：REQ-013, NFR-008

- Given 用户显式启用指定局域网地址的访问。
- When 本机或局域网浏览器访问工作台、项目资料与操作接口。
- Then 经过浏览器授权的请求才可访问，未授权和不可信来源被拒绝；不支持所有网卡免登录，不扩大项目权限。本机默认启动路径保持可用。

2026-10-23：用户同意以指定局域网 IP＋浏览器授权替代原全网卡免登录方式；F027 实施该变更，不授权公网部署、计费调用或新增用户体系。

### AC-033 · 项目终端职责分离

- 来源：REQ-036, NFR-001。
- Given FDE 正在当前项目工作区查看 Agent 启动的项目。
- When 查看运行输出、打开手动终端或执行停止操作。
- Then 运行输出来自该项目实际运行会话且不能输入；手动终端处于当前项目目录但不接管 Agent 终端；停止仍定位原运行会话，输出缺失明确提示而不伪造恢复。手动操作不会自动变成 Agent 的执行记录或新的运行确认。

2026-10-23：用户确认采用同一工作区内的“运行输出”和“手动终端”双入口，本轮不实现人工接管 Agent 终端。
