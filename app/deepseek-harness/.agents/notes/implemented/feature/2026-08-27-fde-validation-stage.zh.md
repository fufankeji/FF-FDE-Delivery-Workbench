# Agent Note：FDE 验证评估与进入部署试运行

状态：已实现

[English](2026-08-27-fde-validation-stage.md) | 中文

## 问题

项目开发已经能够产出代码和研发收口文档，但工作台缺少一份项目级合同，用来判断某个明确的候选版本是否可以进入部署试运行。既有评估页能够运行可重复的 Agent Trial，却没有表达候选版本、环境、项目适用输入、验收阈值、证据和未解决问题。若仅凭文件存在或 Agent 自述完成验收，也会把应由 FDE 作出的交付决策交给自动化。

## 决策

Host 有界读取 schema v2 的 `.fde/evaluations/validation.json`，记录候选版本、环境、可选数据集或用例、项目专属指标、阈值、结果、证据路径和问题。每个指标都必须引用此前阶段的真实项目文档，并给出需求、验收或决策编号；来源和结果证据都必须解析为当前项目内真实存在的文件。PASS 和 WARN 使用一条非空的项目相对路径 `result.evidence` 文字；存在多份文件时，由一份主要证据文档建立索引，WARN 的接受理由使用 `result.waiverReason`。登记数据集是可选能力，可追溯指标与证据才是必需的业务合同。缺失、无效、未执行、失败、没有接受理由的警告，以及未关闭的高等级问题都会作为明确阻塞项显示。

Host 在有界顶层事实通过后，逐项隔离解析指标。若某个指标的结果字段格式错误，候选版本、环境、数据集、问题、其他有效指标和独立索引的阶段产物仍会显示，便于诊断；但整份合同保持无效，不生成方案摘要，不能确认方案，也不能打开阶段门。保留部分可见信息不代表接受部分结果。

验证评估阶段按需加载 `fde-validation` Skill，并明确区分两种模式。准备方案时只维护合同与 `validation-plan.md`，未真实执行的结果保持 `NOT_RUN`。只有 FDE 确认当前方案定义摘要后才能开始执行；摘要覆盖候选、环境、数据、指标定义和来源文件内容，不包含执行结果、证据及问题状态。Host 将确认原子写入 `.fde/evaluations/validation-plan-approval.json`，Agent 不能创建或修改它。执行后才维护 `validation-report.md` 与 `validation-baseline.md`。Skill 不得编造数据、阈值、结果、证据或客户确认。候选版本、环境、输入、来源文件或其内容、方法或阈值变化时，旧确认自动失效，受影响结果必须重置为 `NOT_RUN`；正常写回执行结果不会使确认失效。

评估页明确展示“生成评估方案 → 确认评估方案 → 开始验证”。页面总览直接根据当前快照计算必需指标完成度、执行状态、证据与产物覆盖、阻塞、类别覆盖和五步推进；结果与类别筛选只改变页面展示，不会修改验证合同。页面同时显示每项指标的来源编号，既有 Trial 运行器保留为更准确的“运行固定用例”，只是可选验证方法。项目进度页展示同一份来源、确认状态、证据和三份固定文档。只有当前方案已确认、必需结果和证据完整、警告具有接受理由、高等级问题已关闭、三份文档齐备时，Host 才启用最终的 FDE 两步确认；最终动作按 revision 只执行一次 `validation → pilot`。Agent 和 Skill 既不能确认方案，也不能推进阶段。

项目进度页还提供一条仅供 FDE 使用的明确路径，用于接受一条仍为 open 的问题。页面要求填写理由，并明确说明该操作不会把失败、未执行或缺少证据的指标改成通过。同源 Host 接口会在持有合同文件锁时重新核对页面所示方案摘要，并确认目标问题仍为 open；随后保留原问题和处理建议，原子写入 `status=waived`、`waiverReason` 与 `waivedAt`。刷新后的快照只移除这一条问题对应的阻塞，所有指标结果和其他阻塞保持不变。长哈希、路径、问题说明与接受理由都会在项目进度卡片内断行，不再扩大页面最小宽度。

## 影响

每个项目可以按照真实交付定义证据，不必套用通用基准，同时来源编号会让指标为何存在保持可见。简单项目不必单独建立数据集；数据或 AI 项目则可登记带版本和哈希的输入。没有固定用例不会阻止使用其他验证方法。人工接受会形成可审计记录，而不是静默覆盖为 PASS，也不能隐藏仍然存在的技术证据缺口。第一版不会自动执行所有指标、建立独立数据集服务，也不会根据 Trial 报告推断验收结论；已有报告只能在真实存在后被引用为证据。
