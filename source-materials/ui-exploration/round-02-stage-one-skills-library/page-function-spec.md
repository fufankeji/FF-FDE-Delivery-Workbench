# 第一阶段技能中心与文件阅读页：设计方案

## 已确认边界

产品形态继承本轮 [`product-shape-spec.md`](product-shape-spec.md)，状态 `CONFIRMED`。首层按阶段展示独立 Skill 卡片，只有点击查看之后才展示单个 Skill 的文件树和 Markdown 正文。用户已确认本方案并授权视觉候选；不包含前端开发或 GitHub 发布。

## 1. 首批资产清单

建议把运行时已有的七个第一阶段 Skill 作为首批资产，不重新发明另一套方法。卡片中文名沿用当前目录；技术 ID 放详情辅助信息中。

| 卡片名称 | Skill ID | 职责与内容重点 | 使用条件 |
| --- | --- | --- | --- |
| 判断问题是否值得继续投入 | `qualify-ai-workflow` | 主方法：还原业务、追踪额外劳动及原因、核对指标、比较传统改进与 AI 增量，更新客户现状记录、待确认事项、业务流程说明 | 开展第一阶段业务诊断 |
| 项目启动与方向确认 | `fde-orient` | 明确原始诉求、支持者、时限、已知约束和调查顺序，向主方法提供定向信息 | 新项目或任务性质改变 |
| 访谈业务人员，还原真实做法 | `knowledge-interview` | 按证据缺口准备少量问题，整理正常与异常案例，区分观察、记忆、假设和未知 | 资料无法回答关键问题 |
| 找到负责人和决策人 | `ownership-map` | 区分业务责任人、维护者、访谈对象和审批人，保留责任证据 | 责任或决策权不清楚 |
| 盘点现有系统与资料 | `repo-recon` | 仅调查会影响当前问题判断的系统入口、数据与风险，不提前设计或修改系统 | 问题确实涉及现有系统或代码 |
| 整理给负责人看的决策简报 | `stakeholder-brief` | 把建议、支撑事实、风险与未知、待决定事项写成简短材料 | 已有足够证据请求明确决定 |
| 核对冲突并调整项目范围 | `reframe-ai-engagement` | 保留原约定与冲突证据，提出边界调整、回退及待批准事项 | 重大事实改变范围、成功标准或停止条件 |

前一项承担业务诊断主线，其他项按实际任务协同；列表顺序不表示必须串行运行七个 Skill。本页不修改项目中既有的“必做工作／按需处理”规则。配套方法向主方法贡献证据，不各自创造互相冲突的主报告。

## 2. 技能中心：选择一个合适的方法

### 页面职责

让用户理解每个 Skill 能帮自己完成什么，决定查看或下载；不需要选中客户项目，不显示客户材料。

### 直接可见

- 原平台侧栏与技能中心入口保持；标题为“技能中心”。
- 按八阶段组织分类，第一阶段“发现高价值问题”默认可用；第二至八阶段仅显示名称和“待接入”，不出现虚构资产或下载按钮。
- 当前阶段说明：“从客户现场和真实证据出发，判断什么问题值得继续投入。”
- 第一阶段七张卡片：名称、一至两行用途、适用条件、`查看`、`下载`。
- 仅按实际已发布资产统计数量；不使用下载量、评分或虚构推荐热度。

### 稳定可达

- 可按中文名称、Skill ID 和用途搜索当前已接入的资产；没有结果时可清除搜索。
- 点击查看进入独立详情页，保留所选阶段、搜索条件及列表位置，返回时恢复。
- 卡片的下载动作取得该 Skill 的完整包，与详情页下载的是同一资产版本。

第一版不设一键下载八阶段、批量安装、运行 Skill 或创建项目动作。阶段合集下载暂不纳入本轮，避免把“先接第一阶段”扩成额外打包产品。

## 3. Skill 详情：读懂一个完整的资产包

### 页面职责

在同一平台页面内打开独立的阅读视图，不使用狭窄小弹窗。目录树只属于当前 Skill，不把技能中心所有资产塞进一棵树。

### 直接可见

- 返回技能列表的入口，以及“技能中心 / 第一阶段 / 当前 Skill”的上下文。
- Skill 中文名、简短用途、版本和 `下载 Skill`。
- 当前包的文件目录树与选中文件的阅读区；按照已确认交互，文件树位于详情阅读区左侧，正文位于右侧。
- 当前文件名与包内相对路径。进入详情默认选中 `SKILL.md` 并渲染正文。

### 阅读与目录交互

- 点目录只展开或折叠；点文件才切换正文，选中项保持明显标记。
- Markdown 支持标题、段落、列表、表格、引用、链接、代码块和包内图片；长文阅读优先，不做编辑、保存或终端功能。
- 点击包内相对 Markdown 链接时，在当前 Skill 内定位对应文件。外部链接明确标为外部来源，不伪装成包内文件。
- 若包内确有 JSON、YAML 或脚本，以只读代码显示；不执行脚本，不将它们硬转成 Markdown。
- 当前文件可以单独下载；主按钮始终是下载整个 Skill 包，避免“下载”含义随选中文件悄悄改变。
- 版本、固定来源、适用环境和许可说明在详情中稳定可达，但不压过正文。

### 关键状态

| 状态或动作 | 页面反馈 |
| --- | --- |
| 首次打开 Skill | 读取该版本文件清单并打开 `SKILL.md` |
| 点击另一个文件 | 加载并显示该文件，文件名与选中态同步 |
| 文件读取失败 | 显示失败文件和重试操作，不把上一文件正文冒充新内容 |
| 包内相对链接没有目标 | 明确提示未包含该文件，不伪造空白文档 |
| 下载失败 | 保持当前阅读位置，提示失败并允许重试 |
| 返回列表 | 恢复原阶段、搜索条件及列表位置 |

## 4. 文件与下载：先保证是真资产

### 当前事实

- 现有七个 Skill 的 Markdown 正文主要在 `packages/fde/stage/src/index.ts` 中注册，不是七个已经准备好的独立文件夹。
- 现有核心方法的参考资料包含 Markdown 与 JSON 等类型，当前主要以固定版本外链呈现。引用链接存在不代表文件已经纳入可下载包。
- 项目工作方法弹窗已经使用 `MarkdownText` 渲染正文，后续实现可以复用其已有能力；本轮未实现文件目录、下载或渲染扩展。

### 推荐的首版包

- `SKILL.md`：稳定名称、描述及实际适配正文，保留方法边界，不冒充上游原文。
- `README.md`：用途、输入、输出、配套方法和工作台依赖说明。
- 来源与许可材料：按实际来源整理后随包提供，不能仅凭仓库名称猜许可条件。
- `references/`、`templates/` 等仅在确实纳入对应文件时显示；没有文件时不创建空目录或虚假树节点。
- 外链资料仍可在详情中打开原来源，不因为出现在页面中就声称已包含在下载包。

页面读取与下载必须来自同一份固定版本的包内容。后续实现应复用当前方法定义或建立受控导出，不能维护一份展示正文和另一份下载正文。是否把运行时正文迁移为文件源，需要在实现计划里明确，当前不先行改变 Agent 调用。

### 适用范围假设

首版按“工作台配套版”设计，保留 `.fde` 状态路径与方法协同约束。它可以被阅读与下载，但尚未验证其他 Agent 环境的直接执行兼容性。若用户要求通用独立版，应单独确认需要适配的运行环境，不在本轮同时维护两种正文。

## 5. 保留、增加、替换与不做

- 保留：总览、项目中心、实验室、平台导航、设置、品牌、原项目阶段方法和工作流。
- 增加：第一阶段资产卡片、只读文件详情、单个 Skill 包与当前文件下载。
- 替换：技能中心“待接入”占位内容；正式实现时，同步总览中受同一能力状态约束的技能中心提示，仅表达第一阶段已接入。
- 不移除：任何项目内方法入口，不把阅读和下载改成自动运行。
- 不做：其他阶段资产、编辑器、安装执行、交易评分、客户项目材料导出、通用 Agent 兼容承诺。
