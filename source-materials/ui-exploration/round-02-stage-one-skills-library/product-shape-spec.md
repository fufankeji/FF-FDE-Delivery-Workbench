## 用户、任务与形态

- 目标用户：想了解、阅读和取得 FDE 交付方法的从业者。
- 使用场景：不必先打开一个客户项目，从平台技能中心找到当前阶段适合使用的 Skill。
- 核心任务：选对方法，阅读完整内容，取得与所读版本一致的资产包。
- 一句话形态：按 FDE 阶段组织的技能资产库，以卡片选择 Skill，以单个 Skill 的文件阅读页理解其内容，并支持下载。
- 主旅程：平台技能中心 → 第一阶段 Skill 卡片 → 查看选定 Skill → 浏览包内文件并阅读 Markdown → 下载 Skill 或返回列表。
- 主要交互模型：先选资产，再读文件；阶段是分类，Skill 是资产，文件属于某个 Skill 的固定版本。

## 信息层级

1. 一级：当前阶段、Skill 名称与用途、查看与下载。
2. 二级：适用条件、包内文件、当前文件正文、依赖说明。
3. 三级：稳定 Skill ID、版本、来源和许可说明。

用户三秒内应能知道“这里是第一阶段的技能资产，点查看可读内容，点下载可取得文件”。不把全部技能的目录树当成技能中心主页。

## 首轮取景

- 主取景：第一阶段的可浏览技能列表，展示多个实际 Skill 及查看、下载动作。
- 关联取景：用户打开一个 Skill，默认阅读 `SKILL.md`，包内文件和当前正文存在清楚对应关系。
- 原因：先证明“挑选资产”和“阅读文件”两层关系成立；无需虚构执行过程或 Agent 运行状态。

## 范围与非目标

- 只设计第一阶段资产；第二至八阶段不整理正文、不生成资产、不开放下载。
- 保留项目内已有工作方法入口、阶段状态和 Agent 调用行为。浏览或下载不等于调用、安装或阶段完成。
- 不建设在线编辑器、终端、插件安装市场、客户产物库、交易、评分、收藏、账号或团队系统。
- 第一阶段新资产能力是用户本轮提出的范围增量；本轮只保存设计草案，不修改原 PRD 或把新增范围当成已经实现。
- 具体七项资产展示、下载包构成与详情交互见 `page-function-spec.md`；用户随后已确认该方案并授权先出视觉。
