# 语义能力问题工作坊纪要

## 参与角色

- 设备运维负责人：确认业务问题与人工接管要求。
- 门店主数据负责人：确认门店和设备身份边界。
- 采购合同管理员：确认合同覆盖的时间与来源规则。
- FDE：记录能力问题，不预先决定必须建设知识图谱。

## 必答能力问题

### CQ-01：重复事件

给定两条相近时间的报修，系统能否说明它们是否可能属于同一次现实故障，并展示门店、设备候选、症状、时间和既有工单证据？系统只能形成重复候选，不得自动合并或删除。

### CQ-02：跨系统事件链

给定一个报修编号，系统能否追踪相关消息、门店、设备候选、网络告警、工单和人工决定，并区分已确认关系、推断关系和未知关系？

### CQ-03：维修商与合同有效性

给定事件发生时间、门店、区域和设备类别，系统能否找出当时可能适用的维修商与合同，同时识别合同正文、元数据和值班表之间的冲突？候选不得表达为已批准派单。

### CQ-04：来源变化影响

如果设备身份、合同有效期或政策版本改变，系统能否指出哪些候选建议、关系和上下文结果需要重新评估，而不是静默保留旧结论？

### CQ-05：安全与权限

给定 P0、合同不明、费用超限或跨区域请求，系统能否返回固定人工升级路径和禁止动作，并证明图谱查询没有扩大阶段 3 已确认的权限？

### CQ-06：Agent 最小上下文

Agent 为一条报修生成分诊建议时，系统能否只返回必要实体、关系、规则、来源、有效时间、置信度和未知项，而不是注入全部图谱或历史最终答案？

## 业务词汇提示，不是预制 Ontology

工作坊中出现了门店、设备、报修、现实故障、告警、工单、维修商、合同、政策、审批和证据来源等业务概念。它们只是候选词汇；最终类、属性、关系方向、Domain／Range、基数和约束必须由当前材料与能力问题共同决定，并经 FDE 人工审阅。

## 验证边界

- 使用南京新街口收银中断和杭州空调合同冲突作为代表链路。
- `final_domain`、`final_priority` 和历史人工结果不得进入候选生成上下文。
- 能力问题必须在当前项目图谱上执行真实查询；类名匹配、节点数量或总体质量分数只能作为诊断。
- 当前不允许正式派单、供应商通知、费用承诺或生产状态修改。
