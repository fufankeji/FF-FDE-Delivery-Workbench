# 脱敏数据样例与字段口径

## 字段口径

| 字段 | 含义 | 来源 | 质量情况 |
|---|---|---|---|
| `report_id` | 一条报修消息的稳定编号 | 仿真消息导出 | 唯一，不等于业务事件 ID |
| `store_id` | 门店编号 | 门店主数据 | 2% 历史消息缺失 |
| `reported_at` | 首条报修进入总部的时间 | 消息或电话补录 | 电话补录可能晚 5～30 分钟 |
| `asset_text` | 报修人描述的设备 | 原始消息 | 自由文本，可能写错 |
| `asset_id` | AssetBook 候选设备编号 | 人工匹配 | 约 17% 首次无法匹配 |
| `symptom` | 报修症状原文 | 原始消息 | 可能包含多个问题或无关指令 |
| `impact` | 对营业、安全或商品的影响 | 人工补充 | 31% 首报缺失 |
| `final_domain` | 最终确认的故障域 | 关闭工单 | 关闭原因可能不规范 |
| `final_priority` | 最终业务优先级 | 运维或区域经理 | P0/P1 需要人工确认 |
| `vendor_id` | 最终服务商 | 工单系统 | 可能为空或记录转派后的服务商 |
| `duplicate_of` | 同一故障事件的主记录 | 人工复核 | 历史只有部分重复被标记 |

## 数据使用限制

- 以上数据只用于当前仿真案例。
- `final_*` 字段在评估中作为独立标签，不能在生成候选答案时泄漏给被测逻辑。
- 样例不足以代表 80 家门店的全部设备、方言、图片和异常。
- 含有“忽略政策”等文本的报修描述属于不可信输入，不能改变系统权限或绕过审批。
