# 本地维修系统架构

本轮采用 Node.js 内置 HTTP 与文件API，浏览器原生 ES Module、CSS 和 SVG。无需依赖安装或构建，适合本轮前端与链路快速验证；未来技术优化不属于本轮。

`backend/server.mjs` 同源提供 API 与 `frontend/`，默认监听 127.0.0.1:4177。`backend/catalog.mjs` 只读加载已有资料与图谱，`backend/workflow.mjs` 执行业务规则和局部关系检索。运行数据以原子文件替换写入 `.runtime/maintenance/state.json`。

不重新构建本体，不复制原始资料，不访问工作台内部 API。现有 Semantica 快照是唯一图谱输入，记录原件内容哈希；历史最终类别、优先级、维修商结果和关闭原因不进入分析。规则模式对自由文本识别的能力有限，遇到未知返回补充问题。

静态资源保持同源；原始资料只通过文件清单匹配的只读接口获取。限定本地开发用途，不实现账户系统和生产高并发。

## 当前已实现链路

浏览器报修页 → 本地 HTTP API → 资料白名单读取与规则判断 → 按门店/设备查询图谱两跳关系 → 候选建议 → 人工确认 → 本地草稿原子保存与独立读回。

- `GET /api/overview`：报修、分析记录、草稿、资料与图谱统计。
- `POST /api/reports`：保存用户输入，拒绝未登记门店或跨区域输入。
- `POST /api/analyze`：执行本地规则和图谱查询，保存真实分析记录。
- `GET /api/graph`：读取图谱；`node` 参数用于查询指定实体的两跳关系。
- `GET /api/source?id=…`：通过已加载资料清单预览原件。
- `POST /api/drafts`：要求人工确认、操作人、分析版本和幂等操作标识。
- `GET /api/drafts/:id`：独立读回已经保存的草稿。
- `GET /api/health`：核对本项目服务；不表示业务验收通过。

页面使用浅色 Apple 风格：系统字体、低饱和分区、轻量半透明导航、右侧详情、即时按压反馈和可访问的键盘焦点。不引入动画框架、构建链或网络字体。

本应用不改写 FDE 阶段状态。2026-09-07 按用户接入第五阶段数据的请求，已依据本文和实际源码，通过工作台现有架构领域接口发布 `.fde/architecture.json` R1 候选架构；未代替用户确认架构。现有 4177 服务已登记预览入口，第五阶段技术结果与人工验收分开保存。
