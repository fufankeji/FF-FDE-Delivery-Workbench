# FF - 门店维修工作台

基于当前 `fde-agent` 阶段资料和 Semantica 图谱的本地业务系统，用于后续开发验证。当前先实现规则和图谱驱动的报修处理流程，未接入大模型或企业系统。

## 启动

需要 Node.js 22 或更新版本，无需安装依赖。在本目录执行：

```sh
node backend/server.mjs
```

打开 http://127.0.0.1:4177 。修改端口可使用 `REPAIR_PORT=4178 node backend/server.mjs`。停止使用终端 Ctrl+C。

启动前可用 `curl -fsS http://127.0.0.1:4177/api/health` 检查已有服务；成功且名称为“FF - 门店维修工作台”时直接使用，不要启动第二份。

## 快速体验

1. 默认选择南京报修 `R-1002`，查看即时应急提示，点击“分析这条报修”。
2. 查看故障域候选、补充问题、相似报修与维修商候选；切换“关联与证据”并点击实体查看来源。
3. 点击“核对并存草稿”，填写操作人并确认本地边界；保存后会从服务端读回。
4. 刷新后从“本地草稿”再次打开，或导出 JSON。
5. 用“新建报修”输入自己的测试内容。原样本不会被改写。

前端采用浅色 Apple 风格、系统字体、轻量半透明导航和右侧详情面板；概览突出待处理事项，队列展示设备类型，详情区分原文、候选、证据与人工操作。支持窄屏、键盘及减少动态效果设置。详细场景见 [测试说明](docs/TESTING.md)。

## 测试

```sh
node --test backend/tests/*.test.mjs
```

## 目录

- `frontend/`：维修工作台、关系图、资料查看和本地草稿。
- `backend/`：业务 API、来源加载、图谱检索、规则和测试。
- `docs/`：本业务系统规格、运行说明和交接清单。
- `.runtime/maintenance/`：新增报修、处理运行和草稿的持久化记录，不纳入 Git；其中人工输入不能仅凭原始资料重建，请勿随意删除。
- `fde-resources/`、`fde-deliverables/`、`.fde/`：原有资料与阶段记录，程序只读。

数据来自脱敏仿真案例；运行结果用于当前案例验证，不代表真实客户授权或生产效果。原始答案字段不进入候选生成逻辑。知识图谱使用已有快照，不宣称重新调用 Semantica 完成构建。
