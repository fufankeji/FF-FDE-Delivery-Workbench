# 第五阶段验证计划

日期：2026-09-07。受测版本：`local-repair-v0.2-ui`。状态：本地开发验证，非客户最终验收。

## 范围与依据

本轮按用户要求，接入已实现的维修业务系统，以 `docs/PRD.md`、`docs/TESTING.md` 和实际源码为验收依据。使用 12 条脱敏案例、35 份既有原始资料及现有 Semantica 56 实体 / 56 关系快照，不重新构建本体。

目标链路：报修 → 规则分析与图谱检索 → 核对来源 → 人工确认 → 本地草稿持久化及读回。此处是本地技术和页面验证，不代表阶段二的业务收益目标、任意自由文本准确率、生产集成或客户验收已通过。

## 本轮必测指标

1. **样本与历史答案隔离**（`input-integrity`）：原始样本仅使用输入字段；改变 final_* 不改变分析，R-1002 保留双故障候选与未知时间。

2. **安全提示与未知边界**（`safety-boundaries`）：P0 人工优先，缺失优先级保持待定，报修原文不能提升权限；拒绝跨区域与无效时间。

3. **重复候选与时间窗口**（`duplicate-window`）：仅在已知时间相差不超过两小时时标记时间核实；候选不合并原记录。

4. **真实图谱与来源追踪**（`graph-evidence`）：查询返回原图真实节点、边和 SourceId，维修商匹配真实门店与类别；不凭空补关系。

5. **人工确认与幂等草稿**（`human-idempotency`）：未确认或证据版本过期不得保存；同一操作不重复创建，冲突拒绝，externalWrite=false。

6. **HTTP 闭环与重启读回**（`http-persistence`）：独立临时运行区完成新增、分析、并发幂等保存、读回与服务重启读回；拒绝跨站请求和越界资料路径，原件字节不变。

7. **当前前端模块检查**（`frontend-syntax`）：当前 frontend/app.js 通过 Node 语法检查；该检查不代表浏览器布局或交互验收。

8. **页面完整流程人工验收**（`manual-acceptance`）：依据 docs/TESTING.md，在实际浏览器完成分析、实体与来源查看、人工确认、草稿保存及刷新读回；确认桌面与窄屏可滚动、操作无遮挡。

## 执行与证据

- 前六项：`node --test backend/tests/*.test.mjs`，每个指标对应同顺序的一项真实测试；阈值为该项通过。
- 第七项：`node --check frontend/app.js`，阈值为退出 0。
- 第八项：用户按 `docs/TESTING.md` 完成真实浏览器操作并明确反馈。自动测试、DOM 模板检查或外观认可不能代替完整流程验收。
- 运行前由工作台现有 `loadEvaluationWorkbench` 计算候选文件、环境和指标依据的指纹，运行后比较同一指纹；结果只绑定本轮受测版本。
- 测试在独立临时目录执行并自行清理，不注入正常运行区的分析或草稿。证据登记不改写前四阶段结论、来源原件和知识图谱。
