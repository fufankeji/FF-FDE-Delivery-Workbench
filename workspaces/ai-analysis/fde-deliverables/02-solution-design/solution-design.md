## 1. 目标流程与产品形态

### 1.1 产品形态【✅已确认】
本地优先、**单机运行**的分析工作台（3 名分析师，各自独立使用）。以浏览器为前端，后端本地服务承载能力；数据主要来自本机文件（CSV/Excel/SQLite）与 IT 提供的只读副本/脱敏文件。**不做 20 人局域网并发**作为一期目标。

### 1.2 目标流程（闭环）

```
业务问题(自然语言/手动查询)
  → ①说明将使用哪些数据与计划
  → ②执行只读查询（仅 SELECT），结果保存为项目数据片段
  → ③质量画像 → 清洗/特征工程（生成新产物，不覆盖原始数据）
  → ④图表（引用已保存数据片段，记录维度/指标）
  → ⑤模型实验（登记数据/特征/参数/指标/逐行预测）
  → ⑥报告（引用已保存产物，Markdown 底稿，版本化）
  → 任意环节可回溯，关键结论可溯源到 数据/SQL/图表/模型/报告
```

核心特性【✅已确认 / 推断】：
- **项目化空间**：每个经营问题一个项目，数据与产物隔离。
- **只读边界**：查询默认只读，禁止 DDL/DML/多语句与生产库写回。
- **可追溯**：结论必须能回到来源数据、SQL、图表或模型产物；历史结论不因数据源变化被悄悄改写，而应提示重新运行。
- **离线可用**：无在线模型/凭证时，确定性能力（数据/查询/建模/报告）仍可用。
- **模型输出**：复购预测只生成**人工复核名单**，不自动触达。

## 3. 系统边界

### 3.1 边界内
- **数据接入**：本机文件导入（CSV/Excel/SQLite）+ MySQL 只读副本（若提供）。数据来源登记为“资产”，只有明确绑定后才进入项目。
- **数据层**：数据源画像、来源指纹、字段版本；查询结果落为项目数据片段。
- **分析层**：只读查询、探索、清洗、特征工程、图表。
- **建模层**：异步训练、模型登记（数据/特征/种子/参数/指标/逐行预测）、横向比较。
- **报告层**：Markdown 底稿 + 引用产物的版本化报告与导出。
- **安全层**：敏感字段脱敏/排除、凭证不入源码/导出包、脚本无网络沙箱、只读约束。

### 3.2 边界外（明确不接）【✅已确认】
- 不直连生产库做写操作；不接入手机号/地址/身份证原值。
- 不使用外部在线模型处理敏感明细。
- 不构建登录/权限审批流/移动端/跨部门协作。

### 3.3 信任边界
- 单机本地运行：用户即本机的使用者（3 名分析师各自的本地实例或共享本机项目目录，需 IT 决定是“每人一份”还是“共享一台机器的多个项目”，本方案按**每分析师独立工作区**设计，见开发计划）。
