# 完整数据分析报告

先读取当前项目的数据源基线、查询、数据片段、图表、模型、预测和已有报告版本，再决定还缺哪些分析。
报告不是聊天摘要，也不是用几段通用描述包装几张图；它应让业务读者理解问题、证据、结论、行动和
限制，并让技术读者能够回溯每个承重数字。

## 写作主线

1. 用报告标题和一句核心问题锁定单一业务主题，首屏直接给结论、关键指标与优先动作；
2. 说明数据源、关系、质量问题、处理方式和变化基线；
3. 从总体、趋势、结构、分布和分群展开描述性分析；
4. 对每条关键发现区分事实、解释假设、业务影响和反例；
5. 若有模型，报告目标、特征、切分、算法、融合关系、指标、解释和漂移风险；
6. 给出有优先级的行动建议、观察指标和验证办法；
7. 收束于限制、风险、后续分析与完整可复现附录；内部 ID、哈希、路径不得抢占正文阅读路径。

## 证据纪律

- 只写当前项目产物能支持的数字和结论；正文用人类可读的产物名，artifact ID 与哈希集中到末尾技术附录；
- 缺证据时先调用分析工具，不凭语言模型补造；
- 相关性不写成因果性，模型重要性不写成干预效果；
- 图表与表格必须来自同一登记数据产物；
- 源变化、样本偏差、缺失、泄漏、时间外泛化和阈值取舍必须如实说明。

## 版本纪律

Markdown 是内容真相源。修改生成不可变新版本；恢复旧版本同样产生新版本，不覆盖历史。HTML 只能由
当前版本 Markdown 与固定模板生成，并记录模板版本。
