# SQL 业务分析

先写清“一个结果行代表什么”，再写 SQL。查询的目标是回答业务问题，不是展示语法复杂度。

## 查询设计

1. 把问题拆成对象、指标、时间、分群、过滤条件与比较基线；
2. 从数据源基线确认真实表名、字段、主外键和时间字段；
3. 在每张明细表内部先聚合到目标粒度，再连接，避免一对多重复计算；
4. 对收入、用户数、订单数、比率等指标明确去重键、分母和空值口径；
5. 只生成单条只读查询，并设置合理的时间范围、排序和展示上限；
6. 保存结果为数据片段，记录 SQL、源版本、行列数和业务问题。

## 结果验证

- 用总量与分组和对账；抽查边界日期、空值和重复键；
- 比率同时返回分子、分母，均值说明是否加权；
- 多表连接前后对比行数与唯一键数量；
- 结果为零或异常大时先诊断口径，不用语言模型猜原因。

## 输出合同

回复先给可读结论，再给关键表格与口径说明。SQL 与技术路径进入可展开细节；承重数字必须能追溯到登记的数据片段。
