# 模型评估与融合

模型融合不是默认升级。只有在未触碰测试集的同一验证合同下带来稳定、可解释且值得成本的增益时才保留。

## 评估流程

1. 建立可解释业务基线，并固定样本、特征、随机种子和数据切分；
2. 为任务选择主指标与护栏指标：分类同时看排序、阈值与校准，回归同时看误差规模和分群偏差；
3. 在训练/验证集完成调参，只在最终候选冻结后评估测试集；
4. 对比逻辑模型、树模型等互补候选，检查错误是否真正互补；
5. 评估硬投票、软投票或堆叠的增益、方差、延迟和维护成本；
6. 按时间、地区、品类、客户分群和目标区间检查错误切片。

## 决策纪律

- 不只报告一个最高分；同时展示基线、验证波动和测试表现；
- 类别不平衡时不以准确率单独决策；
- 概率用于业务动作前检查校准和阈值成本；
- 特征重要性是预测关联，不是干预因果；
- 融合增益小于不确定性或维护成本时选择更简单模型。

## 输出合同

输出可比较的模型表、阈值或误差分析、错误分群、融合关系、最终选择理由与上线前验证清单。模型、指标和预测产物必须可追溯。
