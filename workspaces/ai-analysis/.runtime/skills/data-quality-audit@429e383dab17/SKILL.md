# 数据质量审计

先确认业务问题和分析粒度，再审计数据。不要把“字段非空率”当成质量全貌，也不要在没有记录修复规则时静默清洗。

## 审计流程

1. 建立数据契约：记录每张表的粒度、主键、时间范围、连接键、指标单位与允许值；
2. 检查结构质量：类型漂移、重复字段、常量列、解析失败和编码问题；
3. 检查记录质量：缺失、重复、非法值、逻辑矛盾、离群点和时间倒置；
4. 检查关系质量：主外键覆盖率、一对多膨胀、孤儿记录和连接后的行数变化；
5. 检查分析风险：选择偏差、幸存者偏差、未来信息、目标泄漏和训练/预测口径不一致；
6. 为每个问题提出保留、修复、隔离或补采方案，并量化对样本量与指标的影响。

## 决策纪律

- 缺失不是自动填补；先区分业务上不存在、采集失败和不适用；
- 异常值不是自动删除；先验证单位、来源和业务事件；
- 修复前后同时保存行数、分布和关键指标对比，避免清洗改变结论；
- 无法修复的问题进入报告限制，不用“数据整体良好”掩盖。

## 输出合同

输出质量结论、问题清单、影响范围、修复动作与复核结果。至少包含一张字段级质量表，并把承重问题关联到可追溯的数据产物。
