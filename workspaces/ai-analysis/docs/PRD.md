# DS4-AI 数据分析系统 PRD

> 文档性质：根据当前源码、测试、已有需求产物和运行说明逆向形成的 as-built PRD  
> 状态：研发基线候选  
> 更新日期：2026-08-27  
> 排期：待确认

## 1. 产品定义

DS4-AI 数据分析系统是一套本地优先、单用户使用的数据分析工作台。它把项目管理、数据接入、只读查询、数据探索、清洗与特征工程、机器学习、Agent 对话、Skills、产物血缘和版本化报告组织在一个连续工作流中，使分析结果能够回到数据、查询、参数、模型和报告版本，而不是只停留在一次对话结论中。

首要用户是需要独立完成经营分析、数据探索、建模和报告交付的分析人员。运营、供应链、增长和管理人员主要消费由分析人员审阅后的结果；当前实现不是多人协作、审批或生产写回平台。

## 2. 用户问题

传统分析工作分散在 Excel、SQL、Notebook、图片和文档中，常见问题包括：

- 数据源、字段口径和数据版本难以确认；来源变化后旧结果仍被继续使用。
- 临时 SQL、清洗步骤、模型参数和图表散落，结果难复现、难交接。
- 自然语言分析容易只给结论，缺少真实执行步骤和可复核产物。
- 报告通过复制粘贴生成，修改会覆盖旧结论，图表与原始数据失去联系。
- 模型凭据、数据库连接和客户数据存在泄漏或误写风险。

## 3. 产品目标

| ID | 目标 | 可观察结果 |
|---|---|---|
| G-001 | 建立项目化分析空间 | 项目可创建、重命名、归档、导出；项目数据、消息、运行和产物隔离 |
| G-002 | 让数据接入可识别、可复用 | CSV、Excel、SQLite、MySQL 可登记、画像、预览并明确绑定到项目 |
| G-003 | 让分析执行安全且可追溯 | 只读 SQL、清洗、特征、图表、模型和预测均形成项目产物与血缘 |
| G-004 | 让 Agent 对话落到真实工作 | 数据类意图产生可见运行步骤、工具调用和产物；普通对话不误触发数据工具 |
| G-005 | 让报告可持续修改和复核 | 报告按版本保存、恢复生成新版本、引用明确产物，并可生成 HTML |
| G-006 | 保持本地优先和凭据边界 | 没有在线模型仍可使用确定性能力；凭据不进入源码、状态响应或导出包 |

## 4. 非目标

- 不向 OMS、WMS、CRM、MySQL 生产库写回数据。
- 不自动执行营销触达、短信、优惠券或其他业务动作。
- 不替代企业正式财务结算、指标审批或数据治理平台。
- 不提供多人实时协作、复杂权限审批、移动端或云端 SaaS 管理面。
- 不承诺完整 Notebook/IDE，也不把 Agent 生成内容自动视为已验证结论。
- 当前 Windows 路径以 WSL2 为建议方案，不把 PowerShell 原生运行列为已验证能力。

## 5. 核心用户旅程

### J-001 建立分析项目

1. 用户创建独立分析项目并进入项目对话。
2. 用户可重命名、归档、恢复或导出项目。
3. 删除项目时，系统删除数据库记录并把工作目录移动到本地回收位置，避免跨项目残留被继续引用。

### J-002 接入并理解数据

1. 用户在全局数据资产中上传 CSV、Excel、SQLite，或登记 MySQL 表。
2. 系统生成来源指纹、字段画像、行列规模和字段字典。
3. 用户把明确资产绑定到项目，项目获得隔离的 Source 身份。
4. 来源变化时显示 `changed`，重新画像后才更新可用基线。

### J-003 查询、探索与形成数据产物

1. 用户选择项目来源并提交只读 SQL。
2. 系统拒绝写语句、多语句和越权文件/表访问，限制结果行数与执行时间。
3. 查询结果保存为项目 Artifact，可分页、排序、字面筛选并生成图表。
4. 用户可以对明确产物执行画像、清洗和特征工程；每一步生成新产物，不覆盖上游。

### J-004 建模与预测

1. 用户选择数据产物、任务类型、目标、特征、算法和随机种子。
2. 系统异步训练分类、回归或聚类模型，并允许读取状态或取消。
3. 模型、指标、配置、复现代码和预测结果形成可追溯产物。
4. 预测结果只供分析与人工判断，不自动触发业务动作。

### J-005 Agent 与 Skills 协作

1. 用户在项目对话中明确选择来源和 Skills 后提问。
2. 普通对话不注册数据工具；分析意图建立持久 Run 和可见步骤。
3. Agent 通过受控工具创建查询、图表、模型或报告，并把 ArtifactId 关联到消息和 Run。
4. 失败步骤可基于原 Run 重试；用户可取消运行。

### J-006 形成版本化报告

1. 用户选择经过复核的产物创建 Markdown 报告版本。
2. 报告执行证据审计，只引用当前项目真实产物。
3. 修改或恢复历史版本都会创建新版本，不覆盖旧文件。
4. 用户可生成并下载 HTML，图表数据以内联安全结构嵌入。

## 7. 非功能需求

| ID | 要求 |
|---|---|
| NFR-001 | 本地优先：除用户明确配置的模型/MySQL 外，确定性主路径不依赖云服务。 |
| NFR-002 | 项目隔离：项目、来源、运行、产物、报告和工作目录以 ProjectId 关联，禁止跨项目引用。 |
| NFR-003 | 数据安全：查询只读；路径限定在受控工作区；压缩包、Skill 和下载路径防止穿越。 |
| NFR-004 | 凭据安全：API Key/MySQL 凭据不进入仓库、普通响应、日志摘要、模型上下文或导出包。 |
| NFR-005 | 可恢复：来源失败、运行失败、取消、报告渲染失败和服务重启均保留可诊断状态。 |
| NFR-006 | 可追溯：关键结果关联来源、参数、哈希、lineage、Run/Step 和报告版本。 |
| NFR-007 | 有界执行：上传大小、预览行数、查询行数、查询/训练时间和脚本沙箱均有明确限制。 |
| NFR-008 | 可验证：后端 ruff/mypy/pytest 与前端 Vitest/build/e2e 命令可独立执行。 |

## 8. 产品级验收

### AC-001 项目隔离

Given 两个独立项目，When 用户在其中一个项目创建来源、查询、模型或报告，Then 另一个项目不能通过 ID、路径或 API 读取这些对象。

### AC-002 数据接入与变化恢复

Given 一个 CSV、Excel、SQLite 或 MySQL 数据源，When 用户完成登记与项目绑定，Then 系统展示真实画像；When 来源内容变化，Then 系统标记变化并要求重新画像后再使用新基线。

### AC-003 只读分析

Given 已绑定项目来源，When 用户提交写语句、多语句、主机文件函数或未登记表查询，Then 系统拒绝且不产生成功 Artifact；合法只读查询生成带 lineage 的结果。

### AC-004 处理与建模可复现

Given 一个项目数据产物，When 用户完成清洗、特征、训练或预测，Then 原产物不被覆盖，新产物保存父级、参数、指标、随机种子和必要复现信息。

### AC-005 Agent 运行真实可见

Given 用户发起普通对话或分析任务，When 系统处理消息，Then 普通对话不创建数据运行；分析任务保存 Run/Step、状态、工具和产物，失败可重试、运行可取消。

### AC-006 报告版本不可变

Given 已有报告版本，When 用户修订或恢复，Then 系统创建更高版本且旧版本内容保持不变；HTML 只嵌入已登记证据和安全序列化图表数据。

### AC-007 凭据与本地运行边界

Given 用户配置模型或 MySQL，When 系统保存、测试、展示状态或导出项目，Then 真实凭据不被回显或打包；无模型凭据时本地确定性能力仍可使用。

## 9. 已知边界与待确认事项

- 多人局域网访问虽允许私有网段前端 Origin，但当前产品语义仍是单用户工作台；多人并发、鉴权和审计不在已验证范围。
- PDF/Word 报告不是当前固定导出；已有实现为 Markdown 版本与 HTML。
- MySQL 只读依赖外部账号权限，系统还会在 SQL 层限制为已导入表，但不能替代数据库端最小权限。
- Olist 原始数据和在线模型凭据不随源码包提供。
- 计划开始、结束日期和正式交付里程碑没有源码事实，均保留“待确认”。
