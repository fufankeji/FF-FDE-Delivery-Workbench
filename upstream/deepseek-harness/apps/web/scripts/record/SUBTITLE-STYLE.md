## 0.5 · 写字幕前必做：提炼项目差异化（4 个维度）

> 先填这张表，再动笔写字幕。不填就写 = 必然写出"描述画面能做什么"的通用字幕。

### 维度 1 · 独家性——这个项目有没有"全网唯一"的点？

如果有，**必须写进字幕**，用"独家"或"全网独家"开头：

| 情形 | 字幕写法 |
|---|---|
| 自研了某个模块/接口 | 独家自研 X 接口 |
| 复现了某个热门项目 | 独家复现 & 二开热门 ClawdBot |
| 组合了两个从未组合过的技术 | 全网独家：二次开发 GraphRAG 支持多模态文档 |

**判断标准**：在同类教程/产品里搜不到这个功能组合 → 就是"独家"。不要滥用，滥用则失效。

---

### 维度 2 · 技术组合——"用什么做"比"做了什么"更有说服力

技术栈本身就是卖点。不要只写功能结果，要把关键技术名词写进字幕：

| ❌ 只写功能 | ✅ 写技术 + 功能 |
|---|---|
| 前后端分离架构 | React + LangGraph 前后端分离架构 |
| 多模态解析服务统一集成 | MinerU、PaddleOCR-VL、DeepSeek-OCR vLLM 服务统一集成 |
| 两个项目集成 | GraphRAG 与 MinerU 项目集成 |
| 深度代理系统 | 一键启动 DeepSeek-v3.2 深度代理系统 |

**规则**：凡是用了有辨识度的技术名（模型名、框架名、工具名），必须写进字幕，不能省略成通用词。

---

### 维度 3 · 难度规模——让小白感受到"这个东西很厉害"

在处理对象前加规模/难度限定词，建立"这不是简单任务"的感知：

| 限定词 | 适用场景 | 示例 |
|---|---|---|
| **超复杂** | 结构复杂的输入文档 | 超复杂年报 PDF 多模态数据 |
| **超大** | 页数/体量极大的文件 | 超大复杂论文 PDF 在线索引构建 |
| **海量** | 批量处理场景 | 海量数据一键批量导入 |
| **复杂** | 有一定难度的对象 | 复杂 CAD、架构图和工程图精准识别 |

**禁止滥用**：同一个视频里"超复杂"最多出现 1 次，否则失去震撼感。

---

### 维度 4 · 部署与适用场景——"给谁用"决定了是否值得购买

部署模式和目标用户是差异化核心，直接写进字幕：

| 场景 | 字幕写法 |
|---|---|
| 完全本地化，不依赖云端 | 完全本地私有化部署，企业直接上手应用 |
| 已达到生产可用标准 | 真正适配企业级应用 |
| 垂直行业场景 | 医疗垂直领域论文解析测试 |
| 多行业通用 | 适用医疗、销售、金融等垂直领域场景 |

## 1 · 五条禁令（强制 ban · 出现一条就重写）

| 类别 | 禁词举例 | 为什么禁 |
|---|---|---|
| ❌ **比喻 / 隐喻** | "松开方向盘"、"行车记录仪"、"自驾代理"、"夜班"、"接管" | 品牌话术 ≠ 功能描述。观众要听"它能干啥"不是"它像什么" |
| ❌ **第二人称** | "你的目标"、"你只管审批"、"你睡觉的时候"、"你审批" | 功能字幕是中立播报，不对观众喊话 |
| ❌ **诗意修饰** | "一夜不停地运转"、"永不停摆"、"灵魂之作"、"让 X 飞起来" | 文学化表达稀释信息密度 |
| ❌ **过渡 / 引导词** | "→ 现在进入..."、"接下来看..."、"演示完整链路"、"让我们..." | 字幕不需要串场，跳剪自然衔接 |
| ❌ **教学注释 / 元说明** | "这是教学演示"、"30 天压缩成 1 分钟演完"、"为方便讲解..." | 介绍产品不是介绍课件 |

> **测试题**：把字幕打印贴在产品官网首屏 banner 下面 —— 一秒就让人觉得是文案的，PASS。
> 一秒就让人觉得是 PPT 备注 / 课件标题 / 朋友圈句子 / 营销 slogan 的 —— FAIL。

## 7 · 字幕必须有视觉锚点 · 不能漂浮

字幕**永远绑定一个 viewport 中可见的元素**。否则字幕承诺的功能会跟错画面 → 观众怀疑产品是 PPT。

### 强制规则

- ❌ **禁用**：`scrollBy → subtitle` 三步式 · 字幕落点不可控
- ✅ **必用**：`scene` 复合 action · 字幕和锚点元素绑死

```jsonc
// ❌ 错的写法 · 字幕飘在画面间
{ "action": "scrollBy", "y": 700, "duration": 1500 },
{ "action": "subtitle", "text": "六大功能模块覆盖运营全链路", "hold": 6000 }

// ✅ 对的写法 · 字幕锚定到 #features section
{
  "action": "scene",
  "anchor": "#features",          // CSS selector OR { y: 0 } OR { scrollBy: 700 }
  "framing": "center",            // 'center' (默认) | 'top'
  "settleMs": 400,                // 滚完到出字幕之间的缓冲
  "subtitle": "六大功能模块覆盖运营全链路",
  "hold": 6000
}
```

### scene action 内部时序保证

```
scrollIntoView(anchor, framing)   ← 平滑滚动 1.2s
wait settleMs                     ← 等动画 / 图片稳
showSubtitle                      ← 出字幕
wait hold                         ← 字幕停留
返回，下一步                       ← 干净衔接
```

字幕**永远在元素稳定显示之后**才出现 · 永远不会半空中飘。

### 例外白名单（不需要 scene）

| 场景 | 原因 |
|---|---|
| navigate 后第一句字幕 | 整页就是锚点本身 · 用 `subtitle` 直出即可 · 但需 `settleMs >= 1500` 等 hydration |
| 操作反馈字幕（点击后描述发生了什么） | 字幕绑定到 click 后的状态变更 · 可独立 `subtitle` |
| 收尾字幕 | 不需要锚点 |

## 9 · 运营反馈引发的硬性规则升级 · 2026-04-28

> 第一版剧本被运营反馈"丢脸"。这一节把 5 类问题落成可执行规则,违反任一条 = 重做。

### 9.1 节奏分级 · 重点慢、过场快、绝不平铺

**症状**:整体速度慢 / 重要的地方和简单的地方时间一样。

**强制规则** · 每个 scene 按内容重要度分 4 级:

| 级别 | 定义 | hold 时间 | settleMs | 全局 speedup |
|---|---|---|---|---|
| 🔥 灵魂时刻 | 产品价值压缩点 · 1 个视频 ≤ 3 处 | 4500-5500 ms | 600 | — |
| ⭐ 核心功能 | 功能展示 + 操作触发 | 3200-4000 ms | 400 | — |
| 🌊 过场/导览 | 切场景 / scroll | 2000-2500 ms | 300 | — |
| 💨 切换瞬间 | navigate 落地 · 通常无字幕 | 1500-1800 ms | — | — |
| **整体加速** | speedup 顶层字段 | — | — | **1.8 ~ 2.0**(原 1.6 太慢) |

**测试题**:把同一支视频的 hold 时间画成柱状图 · 必须有明显的高低起伏 · 不能是平的一字线。

### 9.2 字幕场景化 · 痛点先于功能

**症状**:文字过专业,缺场景钩子。

**强制规则** · 主字幕 = **「痛点 / 场景钩子」**,副字幕(若有)= 功能描述。

| ❌ 旧 · 纯功能描述 | ✅ 新 · 场景化 |
|---|---|
| 实时呈现 trace 解析结果 | agent 卡死时 · 30 秒定位失败步骤 |
| 自动归类 5 维评分体系 | 用 PageSpeed 风看 agent 哪里不行 |
| 一键启动真 LLM 流式调用 | gemini-2.5-flash 真跑 7 秒出报告 |
| 实现修复方案一键复制 | fix prompt 直接粘到 system prompt |

**句式扩展**(在原 8 句式基础上加场景钩子):
- "X 时:[原句]"(场景触发型)
- "用 X 的方式 V N"(隐喻替代为具体技法)
- "[受众] 第一次能 V N"(决策者钩子)

### 9.3 字幕画面节奏匹配 · 字幕承诺必须有画面证据

**症状**:演示文字出现了 · 但画面没有明显调整。

**强制规则**:**每条字幕之前必须有"可见的画面变化"** · 至少满足下面之一:
- (a) `navigate` 跳到目标页(整页换)
- (b) `click` 触发功能(状态变化)
- (c) `scene anchor` 滚到具体元素 · 元素必须在 viewport 中 ≥ 50% 可见
- (d) `type` 输入触发联动

**禁用模式**:连续两条 `subtitle` 之间没有任何画面变化。这种情况要么:
- 删掉一条
- 或者改成 `scene` 强制锚点 + 滚动证明字幕承诺的内容

### 9.4 局部放大与重点突出(B 阶段路线图 · 当前替代方案)

**症状**:网页文字较多 · 信息没有重点。

**当前替代方案**:
- `scene anchor` 必须用**最小可凸显单元**(具体 testid · 不要用整页 / section 块)
- 框定到屏幕中心(`framing: "center"`)而不是 top
- 配合 click 触发该元素的 hover/active 态

**B 阶段路线图**(待升级 inject):
- 加 `zoom` 字段:`{ "zoom": 1.5, "anchor": "[data-testid='hqs-gauge']" }`
- runner 用 `page.evaluate` 注入 transform: scale + transform-origin

### 9.5 字幕样式 v5 · **已落地** · 透明底大字 4 角轮换

**症状**:字幕一直黑色底框 + bottom-center · 又丑又挡。

**v5 落地规则**(inject/cursor-overlay.css 已实现):

| 项 | 规格 |
|---|---|
| **背景** | 完全透明 · **不要黑色块**(挡画面) |
| **字体** | `"旁门正道标题体"` · 降级 `"PingFang SC", "Microsoft YaHei", sans-serif` |
| **字重** | normal（字体本身已是标题体） |
| **字号** | 角落 56px · mc 开场 64px（`bc` 已废弃）|
| **颜色** | `#ffffff` 白字 + 黄色软发光 + 黑色投影 |
| **可读性技法** | `text-shadow: 0 0 28px rgba(255,214,10,0.50), 0 6px 20px rgba(0,0,0,0.85)` |
| **行为** | nowrap · 不能换行(单行字幕硬上限 22 字符) |
| **主题** | 默认 `orange-sticker`（旁门正道标题体 · 红色描边 + 黄色发光）· runner 自动补，剧本可省略 `theme` 字段 |
| **位置** | 日常以 `bl / tr` 为主轮换 · `mc` 仅用于**开场第一条**（写项目名字）· `bc` 已废弃 |

**JSON 写法**(双格式 · runner 都接):
```jsonc
// 开场第一条 · mc 上下左右真居中 · 写项目名字
{
  "action": "navigate",
```
