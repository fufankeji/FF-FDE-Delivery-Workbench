# 门店项目全流程录制计划

用户已确认已有对话与示例产物的方案。本轮看过素版后要求缩短首页等无效停顿，并直接增加逐步操作字幕。按这一明确修改要求，直接交付紧凑的字幕确认版，不再额外交付另一份无字幕素版；未授权放大，因此本轮不加入 zoom，也不标记为已验收成片。

## 本轮修改验收

- 首页开场只停约 2 秒后点击入口；总览与项目中心各约 3 秒，不重复空等。
- 关键提问、回答和文档保留约 4–5 秒；滚动后的纯等待由 4 秒缩至 0.6 秒，不使用全片倍速。
- 字幕指出当前阶段、入口或按钮、操作目的及可见结果；保留历史对话、脱敏案例、联调示例和无外部派单的披露。
- 复用已验证的入口与状态变化断言；仅在录制脚本中调整时长和字幕，不改变业务源码、阶段文件或原运行数据。
- 三段重录后拼接，去掉第三段重复进入首页的导航；字幕烧入 MP4，并保留单独 SRT。

## 叙事与顺序

1. 从产品首页进入总览与项目中心，打开门店项目的历史会话。
2. 前四阶段依次展示：阶段目标、代表性用户提问、Agent 已有回答、已保存产物。
3. 使用真实业务应用完成 R-1002 分析、来源核对、人工确认及新草稿读回。
4. 后四阶段展示版本与测试证据、限定 Pilot、验收与责任移交、运行反馈与改进。
5. 以系统架构和当前项目工作台结束，突出资料、对话、产物及人工决定的连续关系。

## 数据与副作用

主会话 31 轮，阶段 1/2/3/4 分别选第 1/14/21/24 轮回看；不新增模型调用。第五至八阶段包含已披露的联调记录与过期证据，按实际画面说明，不宣称生产上线或客户签收。业务操作用已有脱敏数据，执行真实本地规则与图谱查询；createApp 使用独立 mkdtemp 状态目录，退出清理，不碰原运行数据。

## 字幕

每章标识阶段与目的；操作前说明怎么做，操作后说明结果和限制。字幕正文在各 JSON 的 scene 中，角落轮换、单条不超过 22 字符。用户明确要求说明和引导，因此内容优先解释操作，不使用夸大宣传句式。

## 验证与清理

专用浏览器使用全新临时 profile，授权令牌只在后台请求、不进入脚本或画面。预演已通过报修分析与草稿保存；录制过程要求 captureState → 提交 → waitForStateChange。保持唯一源码，不创建仓库副本或 worktree。成片与 QA 位于被 Git 忽略的 artifacts/recordings。
