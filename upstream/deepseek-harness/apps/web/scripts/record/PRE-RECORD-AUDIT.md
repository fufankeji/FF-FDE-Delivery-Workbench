# 录制前功能审计 · 强制清单

> **录制 ≠ 表演 · 镜头里看见的每个动作必须真有功能。**
> 写完剧本、跑录制之前，每条 step 必须过这份审计 —— 防止"嘴炮但不实"穿帮。

---

## 0 · 为什么要这一关

字幕承诺过、画面演了、按钮点了 —— 但功能根本没实现 / 按钮没 onClick / 拖拽没 handler，
**用户/客户/老板看完会立刻识破"这是 PPT 不是产品"**。

历史踩坑：
- 字幕说"拖动进度条" → scrubber 实际只能点击圆点，没有 drag handler
- 字幕说"一键通过审批" → 按钮没绑 onClick，点了画面零变化
- 字幕说"AI 自动调浏览器" → 实际是 mock-script 预录事件，非真调

---

## 1 · 四轴对账（每条 step 必查）

写完剧本，对每个 **会出现在画面里的动作** 走以下四轴：

### 轴 A · 选择器存在性
- [ ] `click` / `type` / `moveTo` / `waitFor` 中的 `selector` 在源码里能 grep 到吗？
- [ ] 是用 `data-testid` 而不是文案匹配？（防止文案改了 selector 失效）

### 轴 B · 行为可达性
对每个 `click` 动作 ——
- [ ] 这个 element 真有 `onClick` / `href` 吗？grep 源文件确认
- [ ] 点了之后**画面会有可观察的变化**吗？（DOM 变化 / 路由跳转 / 状态切换 / 数据更新）
- [ ] 如果是 form 元素，submit 后有真实响应（API 调用 / state 变更）吗？

### 轴 C · 字幕真实性
对每条 `subtitle` 文本 ——
- [ ] 字幕承诺的功能（如"拖动 / 实时 / 自动 / 真调"），源码里**真的实现**了吗？
- [ ] 如果是 mock，字幕用词是否避免了"真"的暗示？
  - ❌ "AI 真实调用浏览器抓取竞品" (mock 时承诺过头)
  - ✅ "Agent 自动调浏览器抓取竞品数据"（功能描述，不暗示实时真调）
- [ ] **观众看到画面 + 字幕的同时**，能不能验证字幕说的事真发生了？
  - 字幕说"7 节点 Plan Tree" → 画面真有 7 个节点
  - 字幕说"已发布到小红书" → 画面真有"已发布 ✓"成功状态
  - 字幕说"实时事件流" → 画面真有滚动的事件 row

### 轴 D · 运行结果证据

对每条 `journey` / `operation`：

- [ ] 剧本是否在触发前用 `captureState` 捕获结果基线？
- [ ] 基线和断言之间是否真的执行了 `click` / `type` / `drag`？
- [ ] 是否用同一 `evidenceKey` 的 `waitForStateChange` 等到本轮新结果？
- [ ] `operationEvidence.preflight` 是否来自真实试跑，而不是读源码后推断？
- [ ] 涉及凭证、计费或外部写入时，是否已有明确授权；否则是否使用已确认并披露的 fixture？

只切页、切 Tab、展开设置或输入但不提交，统一归类为 `feature-overview`。

## 2 · 三类常见穿帮 · 修法对照

### 类型 1 · 死按钮（点了无反应）
| 症状 | 修法 |
|---|---|
| Server Component 的 `<button>` 没 onClick | 整页加 `"use client"` + useState + onClick handler |
| 点击后只调 API 但 UI 不反馈 | onClick 后立即 setState 显示乐观更新 + 成功状态 |
| 按钮组没有"已处理"反馈 | 用 disabled / 状态徽章 / 卡片淡出 等可视化 |

### 类型 2 · 字幕过度承诺
| 字幕过头 | 中性化重写 |
|---|---|
| "AI 真实调用 Claude 4.7" | "Claude 4.7 拆解目标 · 自动生成 Plan Tree" |
| "拖动进度条精准定位" | "点击事件节点跳转任意时刻" |
| "实时调浏览器抓取" | "自动调用浏览器工具抓取数据" |

### 类型 3 · 演示链路断裂
| 症状 | 修法 |
|---|---|
| navigate 到一个静态展示页（没真功能） | 改 navigate 到真功能页 / 砍掉这段 |
| click 跨多个页面但 state 不连贯 | 在每个页面单独完成一个完整动作 + 反馈 |
| waitFor 的 selector 永远不出现 | 改用 mock-script 已知会触发的 selector |

## 3 · 录制前 6 步检查清单

```
[ ] 1. 跑 lint：pnpm record:lint scripts/record/scripts/<your>.json
       字幕风格 0 违规 → 通过

[ ] 2. 走 grep：剧本里每个 selector / data-testid 在源码里能 grep 到
       grep -rn "btn-approve\|审核并发布" src/

[ ] 3. 单步过：把每个 click step 的目标元素，到源文件确认有 onClick
       grep -n "onClick" src/app/<page>.tsx

[ ] 4. 字幕真实性：每条 subtitle 念给同事听 —— 他能不能在画面里指出哪个像素证明了？

[ ] 5. 跑合同门禁：pnpm record:validate
       journey/operation 必须包含基线、触发动作与状态变化断言

[ ] 6. 跑预演：先用 RECORD_SLOWMO=300 慢速跑一次，肉眼盯每个动作
       是否真的有可观察的画面变化
```

**6 项全过 → 才能正式录制 + 转码。**

## 4 · 本项目功能现状清单 · 录制前必填

> 这是当前项目的 ground truth · 每个新剧本写之前把要演的功能登记到对应一栏。
> **不在 ✅ 的功能 → 不许演，不许字幕承诺。**

### ✅ 已实现 · 可放心演

| 功能 | 入口（路由 / selector） | 验证方式 |
|---|---|---|
| 平台入口、项目中心、阶段回看 | 3080；项目中心、侧栏阶段按钮 | 真实界面点击，阶段选择只改变阅读位置 |
| 历史对话轮次与产物预览 | 对话 Tab、轮次导航、预览按钮 | 已定位 1/14/21/24 轮；Markdown 预览实际读到项目文件 |
| 报修分析、证据、确认与草稿 | 4177；data-action select/analyze/confirm | 独立临时状态下真实提交并读回草稿，未执行外部写入 |

### ❌ 未实现 / 半成品 · 演了会穿帮

| 功能 | 当前状态 | 处理建议 |
|---|---|---|
| 录制时实时模型生成、正式派单、真实生产验收 | 未授权计费及生产动作；不属于本次已有结果回看 | 不操作、不宣称完成 |

### ⚠️ 是 mock 但视觉真 · 字幕需中性

| 功能 | mock 来源 | 字幕原则 |
|---|---|---|
| 阶段 5–8 联调输入 | 项目 docs/verification/2026-09-07-delivery-flow-fixture.md | 明示示例和过期证据；不是生产批准或客户签收 |

> 项目早期可以先把所有功能丢进"⚠️ mock 但视觉真"那栏。
> 等真接口上了一项，就把它升级到 ✅，写字幕时才能用"真实 / 实时"等强承诺词。
