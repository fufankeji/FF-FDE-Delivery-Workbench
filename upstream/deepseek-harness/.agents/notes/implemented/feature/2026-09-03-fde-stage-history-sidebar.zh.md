# Agent Note：项目阶段历史页与侧栏使用一套真实数据驱动结构

状态：已实现

[English](2026-09-03-fde-stage-history-sidebar.md) | 中文

## 问题

已完成阶段的历史回看页此前只有基础文字卡片，无法清楚表达输入、阶段记录、人工决定和封存关系。项目侧栏同时需要经过“阶段项 → 本阶段工作方法 → 方法列表”两次展开，额外层级占用高度，也让用户误以为“本阶段工作方法”是独立业务对象。

## 决策

已完成的第一阶段使用通用历史回看结构：Hero 展示阶段身份、真实材料与记录数量和人工阶段门，证据链继续从当前 Workspace 的 Source、Artifact、流程、阻塞和阶段状态投影内容。页面不包含具体项目名称或固定业务数据；缺失事实保持未登记。专用 SVG 只承担装饰，不承载文字、数据或交互。

项目工作台以 354px 打开左侧栏，使九项方法可以保持单行并让八阶段时间线继续可达。当前或正在查看的阶段项本身成为默认收起的目录开关；点击阶段项直接读取并展示后端注册的“必做工作 / 按需处理”，再次点击收起。选择其他阶段时，同一次操作切换只读阶段并展开其方法。方法详情、固定来源和运行时 Skill 路由保持不变。

## 考虑过的替代方案

**保留“本阶段工作方法”二级入口。** 否决，因为它没有独立状态或业务含义，只重复阶段项已有的展开能力并消耗纵向空间。

**把参考项目的名称、文件和数量写入页面。** 否决，因为历史页必须适用于所有 FDE 项目，并且只能显示当前 Workspace 的真实记录。

## 影响

任何完成第一阶段并进入后续阶段的项目都可以复用相同历史结构，同时显示各自的真实数据。侧栏展开操作减少一级，方法目录仍然按需读取、可重试并打开只读定义。其他阶段的历史页没有在本次决定中获得相同视觉实现。
