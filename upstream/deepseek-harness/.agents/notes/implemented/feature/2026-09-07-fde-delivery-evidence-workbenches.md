# Agent Note: 第六至八阶段的版本化交付证据工作台

Status: implemented

## Problem

第五阶段已有可运行项目，后续阶段仍使用统一四步和文件数量，无法区分本地成果、试点运行、生产签收与持续改进，也无法证明一个旧结果是否仍对应当前版本。

## Decision

用户明确否定另加演示模式。移除 deliveryDemo、演示入口、独立进度与对应状态，保留正常阶段工作台和单一项目生命周期。显式浏览只改变位置；实际进度由原 complete 接口写入，八阶段显示已完成轮数与最近评审。用户授权的当前验证项目联调数据保留来源说明和替换前记录，不改变全局门槛或生产系统。

后三阶段复用 Workspace 快照，在固定阶段文件的 delivery 字段登记版本、环境、稳定类别、来源、责任与下一动作。Host 检查项目内文件摘要并保留原始声明，缺少或失效的证据不能满足阶段门。三个专用页签视图共享证据详情，不共享业务完成状态；未来和历史只读预览不执行操作。

## Alternatives considered

继续复用四步和文件数会隐藏真实责任差异；直接将本地服务状态映射为 Pilot 或生产会产生错误结论；本轮引入自动部署或另一套数据库超过已授权的前端和资料接入范围。选择文件投影以复用已有 Agent 工作方式。

## Consequences

旧 V2 阶段文件仍能查看产物，但缺少 delivery 时需补证才能评审；旧六阶段路径不变。文件一致性不证明报告真实性或批准人身份，仍由有权 FDE 核对。Semantica 快照可作为依赖，第四阶段上下文构建仍不能充当生产查询执行器。真实部署、遥测采集和发布执行不由本次视图提供。

## Testing

侧栏及工作台三个组件测试文件共 46 项通过，包含无独立演示入口、实际改进轮数、未来只读与历史回看。3080 在线产物不含演示文案或 deliveryDemo；当前验证项目按原接口依次推进至 improvement、revision=9、improvementCycles=1。数据来源是用户授权联调输入，不能解释为实际生产交付。

读取器测试覆盖摘要、范围、缺失与既有阶段门；组件测试覆盖三种页签、右侧详情、未来只读、人工确认及返回。主端口在线快照提供真实项目读回证据，未执行浏览器自动回放或视觉验收。
