# Agent Note: 第一阶段可以从问题描述或项目资料开始

Status: implemented

[English](2026-08-31-fde-stage-one-guided-intake.md) | 中文

## Problem

此前 FDE 第一阶段看起来只是一个预填了技术提示词的通用 Agent 输入框，没有解释操作人员应该描述尚不明确的客户问题、上传客户资料，还是同时使用两者。界面还容易让人误以为必须先上传持久化项目资料，才能启动 Agent，但真实项目完全可能从一段不完整的口头需求开始。用户也无法看出内置的需求发现能力会怎样把任一种输入逐步整理成清晰事实和阶段产物。

## Decision

Harness 原生输入框是所有 FDE 阶段统一的 Agent 入口。第一阶段在这个执行器周围提供业务工作台，不再创建第二个文本框或发送动作。左侧项目导航负责生命周期定位，因此主页面不重复阶段编号、项目名称或完整八阶段路径。主页面用真实业务语言说明目标：“先弄清客户现在怎么做、哪里出了问题，再决定先解决什么。”页面用一条连续进度轨道展示“听客户怎么说、还原实际流程、确认是否值得做、决定下一步”四项业务动作；只给当前动作和紧邻的下一项动作显示状态，不再给所有后续步骤重复展示技术性的前置条件。

左侧当前阶段下提供默认收起的“本阶段工作方法”目录，帮助操作人员了解平台在这一阶段采用哪些方法，而不把技术名称混入主任务。目录只投影产品实际注册的七项第一阶段方法，并使用“项目启动与方向确认”“访谈业务人员，还原真实做法”“找到负责人和决策人”“盘点现有系统与资料”“判断问题是否值得继续投入”“核对冲突并调整项目范围”“整理给负责人看的决策简报”等业务名称。点击方法后，右侧只读抽屉用 Markdown 展示完整定义、适用场景与原始来源；技术标识默认收起。该目录不扫描用户电脑、全局 Skill 或其他项目，也不提供运行、安装、启用或编辑动作，因此它是可解释的方法目录，不是第二个 Agent 入口。真实交付环境的前三个页签固定为“项目工作台、Agent对话、运行轨迹”，其中“项目工作台”始终排在第一项；阶段新增页面只能排在其后。

Host 仍把既有固定需求文件投影为稳定 Artifact，但界面不直接暴露内部文档名，而是分别呈现为“客户现状记录、待确认事项、业务流程说明”，以及条件性的“项目调整记录”。同时读取项目内 `.fde/discovery/workflows.json`，让已经识别的真实业务流程成为可见的“待确认业务流程”，而不是继续埋在对话里或暴露为系统内部工作流。没有识别结果时，该区域只保留一条紧凑引导；有结果时以单列紧凑列表展示。该投影据此计算当前工作、候选产物就绪状态和真实缺口。文件存在只代表有候选载体，不代表其中事实已经确认，更不代表阶段完成。操作人员可以预览已有候选产物；Go、Revise、Narrow、Stop 始终是 FDE 人工决定。

候选材料齐备后，“提交 FDE 评审”在当前项目内打开第一阶段评审模式，不再跳转到多项目中心。评审模式把当前候选业务流程、客户原始资料、证据状态、阶段记录和仍待核对的事实放在一起，但进入评审本身不修改阶段。只有 FDE 选择“进入下一阶段”并完成第二次明确确认后，界面才携带当前修订号调用持久化阶段服务；成功后直接呈现第二阶段。继续补充调查、缩小问题范围和暂停问题都留在第一阶段，并把相应的可编辑任务交给原生 Agent 对话。

操作人员直接在原生输入框沟通。业务动作会切换到 Agent 对话、收起左侧项目阶段导航、展开右侧当前项目文件树，并预填一段可编辑的业务问题，必须等待操作人员补充或确认后手动发送；输入框已有内容时保留原草稿，不自动覆盖或发送。用户发送后，当前阶段的后台提示才加载内置阶段 Skill；Skill 名称、逐条证据格式、上下文限制和阶段控制规则不进入用户消息。只有操作人员明确选择“根据客户资料开始梳理”时，预填内容才会列出当前项目已归档资料路径；普通对话不会静默加入这些资料。进入项目工作台本身仍保持技术工作区收起；预览文件或发起其他适用技术操作时，也可在当前项目范围内展开文件树、代码、Diff、终端或浏览器。

项目资料是原生输入框内的可选辅助能力，不是第二条工作流。紧凑的“有客户资料？上传”动作复用项目级上传控件，并从当前 Session 解析出精确 Workspace。资料仍归档到可见的 `fde-resources/` 目录；它不会创建消息、触发 Agent，也不会宣称文件已经对模型可见。因此左侧项目导航不再重复提供 Agent 动作和上传动作。

桌面端把阶段目标、当前工作和候选工作流统一放在左侧执行列，阶段目标不再横跨产物区域。阶段产物默认收起为贯穿工作区高度的窄侧轨，轨内只显示产物图标和必需产物完成数；鼠标悬浮或键盘聚焦时，再用不换行浮层展示“阶段产物”和当前数量。展开后才显示独立复核栏。工作台保持在当前可用视口内，左侧业务内容与展开后的产物栏分别在自身区域滚动，原生输入框继续停靠在底部。该折叠状态只影响当前界面布局，不改变 Artifact、证据或阶段状态。

“现在先做”卡片用“从一个最近发生的案例开始”解释唯一主任务，并只保留“开始梳理真实流程”这个主动作。有项目资料时才显示“根据客户资料开始梳理”；只有平台已经形成项目调整记录时，才显示“继续核对说法不一致”。这些是当前事实缺口对应的业务入口，不代表第一阶段只会运行两个 Skill。阶段记录计数明确标注三项必备记录，条件性记录不再造成完成分母歧义。桌面端左侧执行列直接使用 ConversationRoot 发布的输入框实时高度计算自身可用高度，不再只在滚动内容末尾追加空白，也不再以固定像素估算；输入框与左侧执行列对齐，并在产物栏收起后随执行列扩展。

## Alternatives considered

**继续让没有任何解释的通用输入框承担整个阶段页面。** 未采用，因为一个完全空白的输入框会隐藏当前业务任务、澄清过程和预计产物。

**在原生输入框上方增加阶段专用文本框和开始按钮。** 未采用，因为两个 Agent 输入会争夺注意力，让操作人员无法判断到底哪个入口负责运行 Skill 和工具。

**自动把所有已上传项目文件加入 Agent 上下文。** 未采用，因为项目持久存储和模型可见上下文是两种不同的用户意图。自动加入会造成上下文污染和授权边界不清。

## Consequences

操作人员围绕执行器能够看到准确的阶段目的、四步引导、逐步出现的候选工作流、带事实缺口的候选产物和下一项人工决定。左侧导航负责生命周期位置，阶段工作台负责解释阶段，对话负责真实执行，技术工作区只在需要时承载文件和代码。客户资料仍可跨 Session 持久复用，但上传是可选操作，也不代表模型已经获得访问权。由 Workspace 解析的上传动作和后端业务投影形成了小而明确的合同，并由 Host 与组件测试覆盖。
