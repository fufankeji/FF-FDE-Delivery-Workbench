# Agent Note: 第四阶段 Semantica Provider 与项目知识图谱渲染

Status: implemented

[English](2026-09-04-fde-stage-four-project-knowledge-graph-renderer.md) | 中文

## 问题

第四阶段必须同时判断项目如何实现最小纵向切片，以及是否需要正式本体。原来的通用阶段面板既无法表达不含图谱的简单路线，也没有一条从项目材料到 Schema、经审核知识、验证、Agent 上下文和真实切片的可信链路。展示 Semantica 示例，或把构建命令成功当作项目已经验证，都会把演示数据和过程状态变成虚假业务证据。

这项集成还跨越进程边界。Semantica 是一套独立安装的 Python 运行时，分别提供解析、本体、图谱、来源、时间、验证和查询模块，并不是一个可把任意文档可靠变成生产图谱的一键端点。每条图谱事实都必须隔离在一个已注册 Workspace 内，并保留来源版本、权限范围、置信度、时间、Schema 版本和图谱修订。

## 决策

- 第四阶段使用专属工作台。实现机制和语义基础作为两项独立选择保存；普通 Schema 是完整的一等路线，不创建本体或图谱占位。
- `@deepseek-ai/dsh-fde-semantica` 是可选本地 Semantica `0.6.7` 运行时的可信 Host 边界。配置提供 Python 命令和可选源码目录；产品代码不编译本机路径、全局图谱或演示记录。
- 本体路线被明确拆为项目材料绑定、候选抽取、Schema 建议与编辑、候选审核、Schema 发布、图谱构建、独立验证、有边界 Agent 上下文查询、真实纵向切片报告和 FDE 决定。构建、验证、切片、机制结论和 FDE 决定始终是不同事实。
- 定义包含能力问题、类、别名、身份键、带类型属性、字段映射、关系与基数、抽取 Pattern、来源、时间、置信度和 SHACL 严重级别。定义或来源变化后，依赖证据会进入待重评。
- Host 在 `.fde/design/semantica/` 下写入有版本的项目状态；渲染器只在完成有界结构校验后读取 `.fde/design/knowledge-graph.json`。三维场景使用 React Three Fiber、Three.js 和 d3-force-3d；社区布局、渐进显现、镜头聚焦和 Bloom 处理适配自第三方声明固定的 GraphRAG Workbench 修订。
- Agent 只能使用 `semantic_context_query` 和 `semantic_slice_report`。前者返回带治理元数据的当前项目有界子图；后者记录已真实运行任务的证据。两个工具都不能选择路线、发布 Schema、批准候选、提交 FDE 决定或推进阶段。
- `Go`、`Revise`、`Narrow` 和 `Stop` 与精确证据摘要及理由一起保存。只有当前有效的 `Go` 可以调用既有阶段门；此后任何受治理证据变化都会使决定失效。

## 考虑过的替代方案

**第四阶段始终要求本体。** 否决，因为许多项目只需要开发 Spec 和普通数据／接口 Schema。业务复杂本身不能证明图谱有价值。

**把 Semantica Explorer 或单个 build 端点作为产品边界。** 否决，因为这会让工作台耦合全局运行状态，并把模块存在误当成可审计项目流程。

**让抽取结果直接写入正式图谱。** 否决，因为由模型或 Pattern 得到的实体和关系只是候选，必须经过明确审核才能成为受治理的项目知识。

**把完整图谱注入每次 Agent 请求。** 否决，因为这会扩大权限和 Token、降低任务相关性，也会掩盖结果究竟基于哪个 Schema 与图谱修订。

**当前项目为空时展示静态示例。** 否决，因为在该工作流里，精美占位与项目证据难以区分。产品应显示真实的空状态或阻塞状态。

## 结果

- 简单项目和本体项目共用一套阶段语言，但不会被迫采用相同实现机制或视觉界面。
- 项目文件而非 React 状态或外部全局图谱是持久真源；刷新页面和查看阶段历史都能复现当前证据状态。
- 本体与图谱操作拥有更多显式步骤，但每一步都能独立重试，过期或失败步骤不能伪装成完成。
- 图谱 Explorer 只在当前项目存在非空快照时出现。视觉质量与语义有效性彼此分离，节点详情会保留来源、时间和置信度证据。
- Semantica 仍是由操作方管理的可选运行时。其虚拟环境和生成的 Store 不会随 DeepSeek Harness 版本化或分发。
- 已记录的 `Stop` 会保留在第四阶段，因为项目目前没有独立的生命周期归档转换。

## 测试

Host 与集成测试通过真实本地 Semantica `0.6.7` Bridge 覆盖材料绑定、抽取、Schema 发布、经审核图谱构建、验证、有边界上下文和切片报告。测试还覆盖简单路线、项目隔离、无效与过期证据、来源版本失效、相互独立的构建与验证状态、全部四类 FDE 结果，以及过期人工决定拒绝。客户端测试覆盖两条路线、结构化 Ontology 编辑、决定行为、无演示节点和确定性三维布局。
