# Agent Note: 项目中心记录目标与交付周期来源

Status: implemented

[English](2026-09-08-project-center-navigation-metadata.md) | 中文

## Problem

项目中心的近期更新曾混用项目更新时间与最新会话标题，点击也无法定位这条记录本身。交付周期保存在浏览器中，预览项目行没有入口，完整时间线的项目计数与实际有日期的项目不一致。

## Decision

页面控制器提供明确的产品首页返回方法，项目中心概览与时间轴的顶部导航均可调用。时间轴另有返回完整项目中心概览的入口，不要求用户从卡片/列表控件猜测返回方式。两条路径均保留项目数据与原有会话入口。

最近动态分别投影当前可见普通会话、阶段记录和项目登记记录的最新更新，每条记录绑定自身标题、时间与目标。会话入口重新核对所属项目、存在性及非归档普通会话状态，打开精确会话的 Agent 对话；阶段和项目记录打开对应管理页。目标不可用时显示错误，不新建会话或回退到另一条会话。

企业与计划周期保存在已登记项目的 `.fde/project-metadata.json`，由 `fde-project` 的可信 Host 路由处理。`ui-workspace` 提供共享客户端服务，创建表单、侧栏与项目中心使用同一数据源。旧浏览器数据仅在项目记录缺失时导入；文件锁内保留已存在的记录，不删除旧浏览器副本。创建后的元数据保存失败只重试数据，不重复创建项目。

周期预览显示有日期的未完成项目，按结束日期排序，每行进入对应项目；完整时间线仍包含已完成项目的登记周期。标题、计数与空态均基于有日期的集合。此决定补足存储和导航，不改变待处理原因的业务判定，也不修改交付阶段。

## Alternatives considered

**继续从浏览器各自读取周期。** 无法让其他浏览器加载同一项目周期，也会让侧栏与项目中心使用不一致的数据来源。

**点击动态统一进入项目最新会话。** 会把用户看到的历史会话记录打开为另一条会话，不能验证记录与操作目标的对应关系。

**用旧浏览器副本覆盖项目记录。** 旧客户端可能持有过期周期，因此导入仅初始化缺失记录。

## Consequences

最新记录摘要不是完整事件审计日志；不存在会话内容变更的完整历史回放。周期是登记计划，不证明合同承诺或阶段通过。旧数据迁移依赖持有它们的原浏览器至少加载一次新页面；在此之前，其他浏览器仍显示未登记。该接口不编辑已有周期。

## Testing

定向测试覆盖真实 HTTP 路由、项目隔离、日期与文件校验、并发初始化、旧副本导入、保存失败恢复、精确会话导航、动态列表展开及周期计数和全部入口。受影响包类型检查和前后端构建通过；3080 运行的两个 Client Bundle 与本地构建一致。浏览器视觉验收未在本轮执行。
