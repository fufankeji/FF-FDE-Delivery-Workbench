# 入口与技术栈核对

先识别实际文件和部署形态，再选线索。示例是搜索方向，不是跨项目固定执行脚本；所有运行、安装、连接数据库和访问外部系统仍需本轮授权。

## 先排除三种错误前提

1. 源文件可能是生成结果：查生成声明、接口规范和手写部分，不统计生成代码作为业务实现。
2. 入口可能在配置：XML、YAML、消息订阅、作业定义、复制簿或数据库任务均可能承担入口。
3. 框架可能被封装：从实际注册点、配置绑定和调用方继续追踪，不能仅搜索官方注解。

## 按实际技术选择线索

| 技术或形态 | 常见入口线索 | 同时检查 |
|---|---|---|
| Java/JVM | 启动类、路由注解、Servlet、XML Bean、作业配置 | 消息监听、批处理与组织封装 |
| .NET | Program、控制器、路由映射、宿主服务 | 定时任务、队列消费者和配置绑定 |
| JavaScript/TypeScript | package scripts、服务创建、路由注册、函数导出 | Worker、事件订阅、CLI bin 与框架自动路由 |
| Python | 模块启动、ASGI/WSGI、路由装饰器、命令入口 | Celery/队列任务、调度和项目声明 |
| Go | main、HTTP Handler、路由器注册 | goroutine 消费循环与命令框架 |
| Ruby/PHP | 路由文件、控制器、框架入口 | 后台队列、命令和计划任务 |
| Elixir/Erlang | application、supervisor、路由和消息处理 | alias/use、OTP 进程与配置，不套 import 行首正则 |
| Rust/C/C++ | 主函数、导出接口、回调注册 | 事件循环、FFI、构建和运行配置 |
| COBOL/主机/行业系统 | 作业、事务定义、程序名、复制簿、控制文件 | JCL、CICS、BMS、IMS 或实际厂商词汇 |
| 数据库与数据作业 | 存储过程、触发器、调度器、管道定义 | 调用方、运行身份、时间窗与重跑语义 |
| 无服务器/托管任务 | 部署声明、handler、事件源 | 云配置、重试、权限与队列触发 |
| 命令行/库 | bin、命令注册、公开导出 | 调用者、输入格式、环境变量键名 |

## 无论技术都要查的入口

HTTP 请求、事件消息、文件落地、定时触发、人工批处理、管理命令、插件注册、数据库触发器、外部回调和恢复任务。只保留与当前业务问题相关的路径，不做无关全量目录。

每条入口至少记录“触发来源、处理位置、输入/输出、下一跳、证据与未知”。反射、动态派发和字符串配置可能绕过静态检索，搜索没命中只能说明本次搜索未找到，不能直接宣布未使用。

## 测试与数据线索

先通过 test/spec 目录与该语言文件命名约定找到测试，再看断言语法。将 fixture、快照和输入样本与测试代码分开；验证日志、配置和实际执行记录彼此不能代替。

数据定义除 SQL 迁移外，还可能存在 DDL、复制簿、序列化格式、配置模式和文件布局。记录谁读、谁写、时间语义与相关下游，而不是只列数据库品牌。

## 验证限制的写法

说明查了哪些真实路径、版本与配置，哪些环境没有权限，哪些行为尚未运行，以及何种最小观察能改变结论。不要在勘察报告中存储凭据值、生产数据样本或与当前任务无关的内部地址清单。
