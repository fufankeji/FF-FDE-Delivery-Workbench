# 有界系统与代码库勘察

建立足以回答当前问题的系统地图，不把“列出了目录和技术栈”当成理解系统。第一阶段只验证业务发现所需的事实，完整环境调查与设计留给后续阶段。

## 1. 锁定系统、范围和问题

确认用户授权的仓库或子目录、当前分支或版本、业务问题与只读边界。先读已有阶段材料和该项目的 AGENTS.md、README 等说明；记录勘察范围和暂时无法访问的区域。大仓库按相关服务或业务路径收敛，不宣称已经映射整个组织。

## 2. 先看体量和实际技术环境

用 `rg --files` 了解真实文件类型和目录，检查实际存在的构建清单、运行配置、部署文件和测试配置。先识别语言与框架，再选择对应检索方法，不能因为熟悉某技术就只搜索它的语法。

区分手写代码、生成代码、第三方依赖和构建输出。接口生成产物不等于真正的业务实现；如果大量文件声明“生成，请勿编辑”，应寻找生成输入、规范和手写部分。不要为了查看版本而安装依赖、启动服务或执行仓库脚本，除非本轮已经授权。

## 3. 找到真实入口

先确认部署形态：Web 服务、命令行、库、批处理、事件消费者、定时任务或无服务器函数；一个系统可以兼有多种形态。按 [入口与技术栈核对](references/entry-points.md) 选择搜索线索。

入口可能声明在 XML、YAML、数据库配置、作业定义、消息订阅或行业运行时文件中，不一定在源码函数里。成熟系统可能包装框架，要沿实际调用或配置查找，不能因为官方框架注解搜不到就断言不存在。

对当前业务路径至少找到触发、入口处理和下一跳证据。一个大系统只找到两个 HTTP 路由时，先反思搜索范围与部署形态，不把检索遗漏当成系统简单。

## 4. 看模块边界与依赖方向

按实际目录、模块声明和导入方式理解主要职责与依赖，区分计划架构与真实调用。不要用只匹配行首 import 的跨语言正则计算模块数；有的语言使用 alias/use，有的依赖由配置注入。

只追踪会改变当前问题判断的边界。发现深入追踪才可解释的行为时记录待核对点，不自动扩展成重构。

## 5. 盘点相关数据和外部集成

核对与候选工作流相关的持久化对象、读写位置、接口、事件、文件交换与下游消费者。Schema、SQL、迁移文件只是线索，还可能有复制簿、作业定义、遗留数据文件和数据库过程。

记录系统联系的方向、业务用途、配置位置和责任人线索，不记录真实凭据或敏感数据值。区分“配置了地址”“源码存在调用”和“观察到运行”三种证据；不擅自发出网络请求验证外部系统。

## 6. 判断变化集中在哪里

只有判断风险确需历史时，查看相关路径近期变更。排除锁文件、生成代码、格式化和批量重命名噪声，不将提交次数直接解释为复杂度或业务价值。浅克隆或缺历史时明确限制，不能编造活跃度结论。

高频变化可能代表业务演进；长期未改也可能是稳定核心或无人敢动的遗留部分，不能只凭时间下结论。

## 7. 确认测试与配置的真实位置

先按文件名和目录约定找到测试，再检查该技术栈的测试语法。区分测试逻辑、fixture、快照与输入样本，不把数百个数据文件当成数百个测试。

说明测试种类、相关路径覆盖情况和 CI 是否实际要求它；没运行就写未运行，不把存在配置等同于通过。查看配置来源、环境差异和注入方式，仅记录键名或位置，不读取或回显秘密值。

## 8. 找出会改变判断的危险点

查阅相关路径的历史说明、警告、弃用、临时绕过、异常重试和隐藏入口。一个难看的分支可能是过往事故留下的约束，不能直接建议删除。生成代码密度高时回到生成源，而不是统计 TODO 来评价系统。

对每项风险写出证据、影响、尚未验证的部分和最小核对动作；不把不能访问的系统部分默默省略。

## 9. 回答五个问题后停止

1. 当前业务从哪里进入系统？
2. 相关数据在哪里，由谁读写？
3. 它和哪些外部系统交互？
4. 若以后实现候选改进，最可能涉及哪条路径或边界？
5. 哪一处最需要先核实，错误判断会影响什么？

能以当前范围内的证据回答时停止；仍有问题无法回答，就记录缺口和解决条件，不无限深挖。

## 输出与平台协作

使用 [系统事实记录](assets/system-map.md) 整理必要证据，结论回到既有主报告和确认清单。需要独立附录时放在当前项目授权目录并从主报告引用，不新增阶段完成分母，也不自动创建或改写用户 AGENTS.md/CLAUDE.md。

每项结论用 project-file 或 system 类型 evidenceRef，ref 精确到相对路径、版本、命令结果或系统读回；推断和未知分别标注，规则见 [阶段记录规则](../qualify-ai-workflow/references/stage-records.md)。本 Skill 不修改客户代码、执行部署、替代 FDE 确认或推进阶段。
