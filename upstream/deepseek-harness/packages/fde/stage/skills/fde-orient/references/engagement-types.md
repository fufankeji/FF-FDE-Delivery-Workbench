# 任务类型与下一步选择

在定向时确认约束，不把本表当成必须逐项执行的任务清单。优先读取平台当前可用能力，未注册能力只能写成后续需求或人工动作，不声称已调用。

| 类型 | 先核对 | 第一阶段的合适下一步 | 后续再处理 |
|---|---|---|---|
| 现有系统增强 | 当前路径、原行为、业务缺口 | 系统事实勘察和流程诊断 | 范围规格、影响分析、变更验证 |
| 组织内新建系统 | 现有平台、真实使用者、结果责任 | 项目定向、流程访谈、机会判断 | 需求、非功能与方案 |
| 系统集成 | 两侧责任人、真实交换对象、业务失败点 | 有界盘点、责任映射 | 接口合同与集成设计 |
| 迁移或重建 | 迁移动因、现有数据与不可中断业务 | 核对边界、系统事实与知情者 | 迁移路径、切换与回退 |
| 救火或稳定性 | 是否仍在事故、安全处置责任 | 事故后补事实、定向与责任 | 事故处置由授权流程负责 |
| 纯评估 | 谁用评估结果作什么决定 | 有界勘察、证据核实与简报 | 不自动开发 |
| 版本升级 | 失效时间、支持约束、当前版本 | 核对时限与影响对象 | 依赖升级与部署验证 |
| 数据分析 | 数据口径、样本、使用权与结果验证 | 数据准备度与机会判断 | 数据管道和评估方案 |
| 商用软件配置 | 可配置能力、供应商约束与升级路径 | 核对是否真需要新建能力 | 不默认另写一套系统 |
| 系统退役 | 谁仍在使用、依赖、保留与恢复要求 | 系统盘点与责任确认 | 授权后的退役计划 |
| 监管整改 | 真实义务、固定日期与决定权 | 先核对必须满足的边界 | 范围或资源无法兼容时及时上报 |
| 探索验证 | 哪个未知值得有限投入 | 明确问题、最小验证、停止条件 | 不把探索直接升级为正式项目 |

组合任务要说明依据，不强套单一类别。只列当前最有信息价值且已经授权的下一步；访问、外部沟通与生产操作的授权分别确认。
