# 发现、边界与准备度检查

在候选工作流已有事实轮廓、需要判断缺什么证据或是否值得继续时读取。按当前问题选用，不要求每个项目填写全部清单，也不把检查完成当成项目获批。

## 业务边界

逐项确认对象、用户、触发、输入、判断、允许动作、结果、验证人和回退。把正常、异常、人工补救与跨团队等待区分开；同一个案例不自动代表整个业务总体。

售前说法、人员陈述、现场观察、系统行为和政策授权分别记录。权威不是固定排序：正式政策可能没有覆盖当前环境，系统行为可能违反政策，近期访谈也可能只是记忆。保留来源片段、时间、适用范围和冲突，重要变化转入重新界定。

## 价值判断的十二项观察角度

| 角度 | 当前应查明什么 | 不应推导什么 |
|---|---|---|
| 结果 | 业务真正希望改变的结果和可接受状态 | “用了 AI”不等于结果 |
| 责任 | 谁拥有结果，谁独立验证，谁能作出决定 | 支持者不自动拥有全部权限 |
| 基线 | 当前测量、总体、样本和观察窗口 | 未测量不写零或平均行业数 |
| 增量 | 相比不做、流程调整和普通软件的额外价值 | 人工步骤不等于 AI 机会 |
| 工作边界 | 哪类对象、环境、用户与异常在范围内 | 一个成功案例不等于全量可用 |
| 数据上下文 | 输入是否可获得、可解释、允许使用 | 文件存在不等于具备使用权 |
| 行动边界 | 允许读什么、建议什么、写什么，何时审批 | 技术可调用不等于业务授权 |
| 采用 | 操作者是否接受、需要怎样改变现有工作 | 演示好用不等于实际采用 |
| 评估 | 用什么案例和标准证明结果，谁验收 | 技术准确率不等于业务结果 |
| 经济性 | 投入、运行成本、维护和风险代价 | 局部省时不直接等于利润 |
| 服务责任 | 失败谁接手、怎样回退、谁长期维护 | 开发完成不等于交接完成 |
| 持续反馈 | 什么变化会让当前结论失效，怎样发现 | 一次验证不等于永久可靠 |

第一阶段重点建立前六项事实与硬性阻塞，其他项只记录当前可知的约束和后续验证人。不在此阶段完成价值建模、生产评估或架构设计。

## 数据准备度

分别核对运营输入、知识上下文、评估训练材料和遥测反馈：

- 业务所有者、实际保存位置、访问审批、使用目的与保留要求。
- 字段口径、时间含义、更新频率、有效范围、异常值、缺失和版本差异。
- 数据是否能代表目标总体，是否存在选择偏差；样本能否合法脱敏用于验证。
- 哪些输入需要清洗、关联或人工解释，谁对准备结果负责。
- 允许的输出、留存、审阅、回写与删除方式；是否含个人信息、商业敏感内容或凭据。

只盘点当前业务判断所需内容，不主动复制数据、扩大访问、申请外部服务或扫描其他资料库。

## 候选比较与停止条件

对每个候选写明传统改进对照、AI 的额外作用、最大可改善范围、关键未知、最小验证及验证人。收益为推断时说明公式、假设和可能重复计算的部分，不输出没有依据的评分排行榜。

结果、责任人、可访问上下文、授权、采用路径或风险上限存在实质缺口时，建议继续补证或暂缓；无法产生有价值且可接受的增量时，可以明确建议不建设。各类结论仍是候选，不改变平台项目状态。

## 业务模式只是假设

可用近期案例判断是否类似分类分流、资料核对、异常处理、决策辅助、知识问答或受控回写。模式只能帮助提出问题，不能代入标准答案、虚构企业角色或把通用性能指标当成现场基线；不匹配就写“暂无匹配模式”。
